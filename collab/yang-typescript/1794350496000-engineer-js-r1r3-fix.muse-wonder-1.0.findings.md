## Mechanism chosen, and why a minted cell cannot replicate it

Companion provenance cell + runtime seal + wrapper-identity back-reference,
all allocated by the runtime at protocol-reception time; no registry.

- `js/raise-protocol` (`prelude.cljc:1695`) still builds the local TypeError
  wrapper `e` via `js/make-error`. It no longer writes the condition into the
  wrapper's own contents. It allocates a fresh companion cell holding
  `{:yang.call/wrapper e, :yang.call/seal js.rt/retained-seal,
  :yang.call/condition condition}` and writes only the companion reference
  into the wrapper under `:yang.call/retained-provenance` (:1707-1713),
  then throws `e`.
- `js.rt/retained-seal` (:4133, init-form; registered in `runtime-keys`
  :4293) is a cell `js/init!` allocates once per task. No `js/` definition
  returns it or its contents; JS source has no name for it and the Clojure
  donor/probe sources run under their own prelude namespace. Admitted
  source therefore cannot obtain the seal reference to stamp into a forged
  companion.
- `js/retained-condition` (:1675-1694) now authenticates, in order: the
  candidate is a cell and `cell/authentic?`; its contents are
  `:js/class :error`; `:yang.call/retained-provenance` is a cell and
  `cell/authentic?`; the companion's `:yang.call/wrapper` is identical
  (`=`, cell-reference identity) to the candidate; its `:yang.call/seal`
  is identical to `js.rt/retained-seal`. Only then does it answer the
  companion's `:yang.call/condition`. Every other shape answers nil, and
  the entry bridge (:1617) delivers a fresh `:yang.call/thrown` carrying
  the thrown value itself.

Why each attack fails: (1) a minted cell from scratch (the architect's
`cell/new` snippet, or a mimic that builds its own companion layout) has
no companion the runtime sealed — an attacker-chosen seal cell is not
identical to `js.rt/retained-seal`, and the old
`:yang.call/retained-condition` contents key is no longer read at all.
(2) A copied-metadata wrapper carries the genuine companion reference,
but the companion's back-reference names the genuine wrapper cell, not
the copy, so the identity check refuses. Lifetime: the companion is
reachable only through the wrapper, so the association lives exactly as
long as the wrapper (survives `retain`/`later` across activations, as the
unchanged 30/30 provenance gate confirms) and needs no ambient/global
table; per-task state is limited to the one seal cell from `js/init!`.

P2: the bridge comment (:1584-1592) now claims only that
restore-before-transfer establishes delivery ORDERING (the callee bridge
is absent while the caller's exit runs), and names the no-reuse-after-
completion lifetime claim an explicit open obligation pending the
suspension probe. Standing rulings respected: no nil-raise-exit guest
fallback added; no common-constructor claim for `js/construct-with-nt`;
the `exception_contract.clj:55` donor tweak untouched.

`exception_contract.clj`) composed by the kit on all three VMs
(semantic/stack/register), assertions guest-side in the probe program.

   :yang.call/not-callable, :yang.call/data {:forged true}}`, and (b) a
   mimic wrapper armed with an attacker-built companion (own seal cell,

## Weakening / deferral I could not avoid

- Residual surface, stated plainly: an attacker who already holds a
  genuine wrapper and deliberately reads its companion with raw
  `cell/get` can extract the seal reference and the condition, and a
  deliberate in-place `cell/set!` of a genuine companion is not detected.
  The two architect-required probes (mint-from-scratch, copy-to-new-cell)
  both refuse, and no wrapper-riding scheme can do better while admitted
  source holds raw `cell/get`/`cell/set!` over a wrapper it legitimately
  possesses; the only stronger shape is a runtime registry keyed by
  wrapper identity, which the architect explicitly ruled out. I did not
  add an extraction-from-genuine-companion probe, since it would encode
  this known residual as a failing expectation rather than a contract
  the fix claims.
- The suspension/raise-exit lifetime probe remains a named open

  generator/async lowering still refuses, so it is not closable in this
