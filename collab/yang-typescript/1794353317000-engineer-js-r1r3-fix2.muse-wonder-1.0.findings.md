## Mechanism (the architect's accepted direction, implemented to the letter)

The sealed companion cell of fix round 1 is gone entirely — contents,
back-reference, seal, the `js.rt/retained-seal` runtime key, and every
wrapper-carried provenance slot. In its place, a prelude-private,
task-owned identity association:

- `retained-store-install` (a new private form in
  `src/cljc/yang/typescript/antlr/prelude.cljc`, beside `init-form`) is
  one guest `let` that `js/init!` runs once per task, inside the uninit
  guard. It allocates the store cell `(cell/new [])`, binds it only as
  the lexical `retained-store`, builds a self-passing `retained-lookup`
  over `[wrapper condition]` pairs, and installs the real
  `js/retained-condition` / `js/raise-protocol` as closures capturing
  that cell via `yin/def`. The two top-level definitions of the same
  names are now pre-init stubs (no store exists yet); init replaces
  both before any guest code runs.
- Key = the genuine wrapper reference. Cell identity verified against
  the cell implementation: `cell/new` answers a sealed
  `{:type :cell-ref :id :cell-N :seal s}` whose content lives in the
  task heap (`yin.vm.module` / engine `check-ref!`), the guest `=` is
  host `=` on those refs, and the prelude's own encoding note states
  "the guest reference is the cell ref, identity is `=` on refs". A
  copied or newly minted cell has a different heap id and therefore
  never matches a stored key.
- Payload = the original complete condition, stored in the private
  store ONLY, at the moment `js/raise-protocol` creates the wrapper.
  That is the sole membership-establishing operation. The installed
  `js/retained-condition` authenticates by private membership alone:
  heap-authentic candidate, then a linear identity lookup; it never
  reads the candidate's contents, so no wrapper-supplied or
  wrapper-reachable metadata can establish, replace, or augment a
  membership. The retained `:yang.call/retained-provenance` field no
  longer exists anywhere.
- Lifetime (explicit policy, stated in the retention comment):
  associations are preserved across completed calls and catches for
  the life of the task — the `saved-protocol-*` fixtures (retain →
  return → `later` rethrow from a new activation) prove the
  cross-activation case — and are reclaimed only at task teardown,
  when the task heap (store cell included) dies. No process-global or
  cross-task registry; the only per-task state is the one closure.

## Reachability evidence (obligation 2, and the corrected :1660 claim)

The round-1 comment's false claim is replaced with a precise statement
of what is and is not reachable. Admitted Clojure donor source (raw
`cell/new`/`cell/set!`/`cell/get`, module namespace) cannot obtain the
store root:

- Not via the wrapper cell: the wrapper carries no
  `:yang.call/retained-provenance`, `:yang.call/retained-condition`, or
  `:yang.call/seal` slot (guest-probed on a genuine wrapper, all three
  VMs). There is no companion to follow anymore.
- Not via `:props`: JS-visible properties live in the wrapper's `:props`
  ordered map; the association was never written there or anywhere in
  the wrapper's contents.
- Not via runtime keys: `js-prelude/runtime-keys` contains no
  `retained` key at all (host-asserted in the new test; the seal key
  was removed, and no store key was added).
- Not via any exported name: `js-prelude/module-exports` contains no
  store/seal/provenance registration name (host-asserted), and no
  global name holds the store or a seal (guest-probed via
  `js/global-typeof` for `retained-store`/`retained-seal`/
  `retained-provenance`, all `"undefined"`).
- No exported registration/replacement operation exists: the store cell
  is reachable only as a lexical capture inside the two installed
  closures, which neither return it nor accept associations from
  callers. What a wrapper holder CAN reach is the wrapper cell itself
  and its JS-visible contents; that grants retaining and rethrowing
  that wrapper, never altering what it forwards.

Because the root is a closure capture allocated in `js/init!` (the
per-task allocation point), no process-global table was needed or
improvised.

## Weakening / deferral

- None against the architect's bounds. The companion model is fully
  removed, not layered over: there is no wrapper-reachable authority
  left to mutate, extract, or stamp.

  preserve-across-calls policy with reclamation at task teardown; a
  task that raises unboundedly many protocol wrappers grows the pair
