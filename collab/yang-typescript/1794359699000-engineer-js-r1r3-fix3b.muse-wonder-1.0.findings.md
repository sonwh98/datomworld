## 1. The actual resolution rule (file:line)

Variable lookup is exact-symbol, in this order, with no namespace normalisation anywhere:

- `yin.vm.engine/resolve-var` (`src/cljc/yin/vm/engine.cljc:116-142`): env → active store →
  primitives → module registry. The registry leg fires only when the name has a namespace
  (`:134`), and builds the dotted symbol `(symbol (str (namespace name) "." (name name)))`.
- The active store is the module store while a module closure runs, else the task store
  (`engine.cljc:206-215` `active-store`, `:217-225` `put-active` — every `yin/def` writes
  through it). AST-walker call sites: `src/cljc/yin/vm/ast_walker.cljc:481-484`, `:758-765`.
- Registry descent is `yin.vm.module/walk-path` (`src/cljc/yin/vm/module.cljc:40-56`): once the
  path reaches a module entry it reads that entry's `:bindings` (linked) or `:slice` (host).
  So `js/retained-condition` from outside resolves to `[:bindings 'retained-condition]` — the
  frozen slice value — while `js.rt/retained-condition` builds `js.rt.retained-condition`,
  descends `[:modules 'js]` into the entry, and then reads `[:bindings 'rt 'retained-condition]`,
  which is nil; `resolve-var` then fails loudly ("Unable to resolve symbol"). `js.rt/*` names
  are therefore unreachable from outside the module, by construction.
- Export set: `yang.core.prelude/exports` (`src/cljc/yang/core/prelude.cljc:71-76`) takes only
  keys whose namespace is exactly `"js"`. `js.rt/*` keys are never exports.
- Linked emitter: `core/strip` (`core/prelude.cljc:20-26`) strips only namespace `"js"`;
  `strip-form` (`:29-34`) rewrites references, definition keys and quoted keys alike.
  `js/*` → bare everywhere (definition key, reader, quoted `yin/def` install key all become
  the same bare symbol in the module store); `js.rt/*` stays qualified everywhere. All three
  sites coincide under either spelling — which is exactly what the orchestrator's attempt
  broke (next section).

**Correction to the brief's premise:** at `31287b17` the callers did *not* read `js.rt/*`.
They read `js/retained-condition` (entry bridge, `prelude.cljc:1617` pre-edit) and
`js/raise-protocol` (`js/call`, `:1709` pre-edit), and the install keys were the same `js/*`
spellings (`:4123`, `:4131` pre-edit). The orchestrator's rename changed only the install
keys to `js.rt/*` and deleted the stubs, leaving the readers at `js/*` — a guaranteed
exact-symbol mismatch in both paths (bundled: store holds `js.rt/…`, read asks `js/…` →
registry fallback finds no such export → operational "Unable to resolve symbol",
`engine.cljc:53` is `fail`; linked: install stays qualified `js.rt/…`, read strips to bare).
That, not a strip subtlety, is what produced the 45 errors. The brief's conclusion that
"`js.rt/*` reads resolve to what the `js/*`-installed bare keys define" does not hold under
`resolve-var`: no such aliasing exists.

## 2. Why literal shape (A) fails, and what was landed instead

Shape (A) (delete both stub definitions, keep the install key) was implemented first and run
against the arbiter. Result: `yang.typescript.antlr.linked-prelude-test` 15 failures / 9 errors
(pre-edit: 10 tests / 62 assertions, 0 failures). The decisive error, repeated across formats:

```
Module link refused: undeclared-free
{:name raise-protocol, :status :refused, :reason :undeclared-free, :link-module js}
```

Root cause: the host-side spec discharges the two reads because
`yang.core.prelude/defined-keys` (`core/prelude.cljc:99-108`) counts the nested `yin/def`
keys in `retained-store-install` — confirmed by probe (§3). But the linker's own step-5a join
does not: `yin.vm.linker/undischarged` (`src/cljc/yin/vm/linker.cljc:1086-1139`) discharges a
lambda-body occurrence only against an **unconditional definition whose position precedes
every application site** (`:1094-1099`). The install `yin/def`s sit inside `js/init!`'s lambda
under the uninit `if` — conditional and in-body — so they discharge nothing for the
semantic/debruijn formats. Only the top-level stub definitions discharged the entry-bridge
and `js/call` body reads. Deleting the stubs is therefore not a rename-detail; it removes the
only discharge the linker accepts. (The AST-walker format was already `:refused
:undeclared-free` pre-fix, pinned at `linked_prelude_test.cljc:145-151`; it is unaffected.)

Landed instead — architect correction (i) from the verdict §2, applied consistently:

- Definition keys: `[js.rt/retained-condition (fn [e] nil)]`,
  `[js.rt/raise-protocol (fn [condition] …)]` (stubs retained verbatim, re-keyed).
- Readers: entry bridge `(js.rt/retained-condition e)`, `js/call`
  `(js.rt/raise-protocol condition)`.
- Install: `(yin/def (quote js.rt/retained-condition) …)`,
  `(yin/def (quote js.rt/raise-protocol) …)`.
- Not added to `runtime-keys` (the definition list already discharges the reads; the
  architect marked the placeholder optional). `js.rt/state` (`prelude.cljc` definitions,
  `:js/uninit` slot) is the in-file precedent for a `js.rt/*` definition key resolving in
  both stores.

Why this satisfies the goal: the names are not exports (`core/exports` takes namespace
`"js"` only), so `lift-slice` (`engine.cljc:1055-1070`) never snapshots them and
`receive-module` (`engine.cljc:1091-1125`) never freezes them into `:bindings`; an external
`js/retained-condition` or `js.rt/retained-condition` read fails loudly as unresolvable
(§1), never as silent nil. Intra-module readers get the stub pre-init (no guest code runs
pre-init) and the installed closure post-init, in both the bundled store (exact symbol) and
the linked module store (`strip` leaves `js.rt/*` qualified at all three sites). The stubs'
pre-init failure shapes are unchanged from `31287b17`; they are simply no longer observable
outside the module.
