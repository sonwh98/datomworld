### P2

**P2-1. The profile checker is not total: a with-meta frame whose metadata map itself carries metadata crashes with AssertionError, and the corpus pins no class for that shape.**
- File: `test/resources/dao/jing/cbor-v1.generate.py:226` (`assert m["t"] == "map" and "meta" not in m`) with `_frame`/WITH_META at lines 501–511.
- Wire bytes `27(["clojure/with-meta", [27(["clojure/with-meta", [m', metamap]]), value]])` pass `to_node` (a with-meta over a plain map is structurally valid — the inner frame returns `{"t":"map", ..., "meta": m'}`), then hit the assert during `jing_decode`'s re-encode — an uncaught `AssertionError`, not a `Refusal`. The README refusal table ("metadata that is not a map, metadata on a non-collection non-symbol or on a value already carrying metadata") does not cover this shape either: the meta map is the frame's *first* element, not the "value".
- Plan sentence: "Reject malformed CBOR, unknown tags or named wrappers outside this profile… Validate tag/name/payload shapes before any lossy host conversion" (Encoding contract). A J1 implementer mirroring the corpus taxonomy has no ruling to mirror.
- Smallest fix: rule the metadata map must be bare — in `_frame`'s WITH_META branch, after `m = to_node(p.value[0])`, raise `Refusal("malformed-frame", "metadata map itself carries metadata")` when `"meta" in m`; add one decode-refusal fixture (e.g. `meta/decode-meta-with-own-meta`); record the ruling under A3/A10. This keeps "one value has one metadata map" consistent with `meta/decode-nested-with-meta`.

### P3

**P3-1. Self-tests require only 14 of the 16 refusal classes.** `required-refusals` in `test/dao/jing/cbor_fixtures_test.cljc` omits `malformed-number` and `unsupported-value`. Both occur in the corpus today, but a future edit could delete every case of either class without a self-test failing. Fix: add both to the set.

**P3-2. No encode-refusal for an integer-width duplicate introduced by normalization.** Plan: "Reject duplicate canonical keys or elements introduced by normalization instead of losing entries"; the declared normalizations include integer width. The DSL already supports it (`{"t":"int","v":"1","host":"big"}` beside `{"t":"int","v":"1"}`), and it is constructible on Node (a JS Map holds `1` and `1n` separately). NaN-normalization duplicates are covered (`coll/set-nan-payload-duplicate`, `coll/map-nan-payload-duplicate`); integer-width is not. Fix: one `duplicate-key` encode-refusal case.

**P3-3. No fixture for a sorted collection carrying metadata.** Plan: "Normalize sorted collections to ordinary maps and sets" + "Preserve collection and symbol metadata…". A `sorted-map` with `{:doc "d"}` would pin that the two normalizations compose (with-meta over the plain-map encoding). Fix: one canonical case.

**P3-4. Several equality-collapse encode refusals are not constructible on ANY host, and the notes imply otherwise.** `coll/set-signed-zero-collapse`, `coll/set-int-ratio-collapse`, `coll/set-decimal-scale-collapse`, `coll/set-vector-list-collapse`: JVM Clojure `=` merges all pairs; Node SameValueZero merges all; Dart raw doubles merge (`0.0 == -0.0`, `1 == 1/1`-equivalent); correct portable carriers merge by contract ("equal numeric values compare zero and hash equally, independent of kind, decimal scale, and zero sign"). `coll/map-int-float-key-collapse` is live on JVM only; `coll/set-nan-payload-duplicate` on Dart raw doubles only. The decode-side twins all exist (`mal/collapse-*`), so enforcement is intact — but the README Obligations bullet should say these may be N/A on **all** hosts, so a J1 report of "N/A everywhere" is not read as a skipped test.

**P3-5. Symbol-metadata wrap order freezes a byte but is not listed under AMBIGUITIES.** `meta/symbol-x-doc` pins with-meta *outside* the `dao.jing/symbol` frame; A4 records the wrap-order question for lists only. The choice is right (same reasoning as A4; matches Boring's writer wrapping whatever it emits for the value), but the README claims to list "every place the plan does not fix a byte". Fix: extend A4's text to symbols.

**P3-6. Symbol side of the slash-cross identifiers is thinner than the keyword side.** Keywords pin `ns "a/b"/name "c"` vs `ns "a"/name "b/c"` (`id/keyword-ns-a-slash-b-name-c`, `id/keyword-ns-a-name-b-slash-c`); symbols pin only `(symbol nil "a/b")` vs `(symbol "a" "b")` (`frame/symbol-a-b`). The plan's literal requirement ("the corresponding symbol pair") is met and PATH-group injectivity covers it; adding the two symbol crossings would be belt-and-braces.

**P3-7. `every-named-frame-has-accepted-and-malformed-cases` matches frame-name hex by unaligned substring** (`includes?` in the test file) — a name hex could theoretically match across byte boundaries. Cosmetic; no current false positive.

**P3-8. Immutability is currently only policy, not git-enforced: the corpus is untracked.** Also, the Dart lane's digest self-check runs through `dao.jing`'s hand-rolled Clojure SHA-256 (`src/cljc/dao/jing.cljc:300-303`), so on Dart the check is not fully independent — mitigated because JVM (MessageDigest), Node (goog.crypt) and the generator (hashlib) are three independent digest paths that agree. Fix: commit promptly after sign-off; optionally wire `python3 …generate.py --check` (which never writes) into CI so drift fails loudly.
