## Verdicts on challenged decisions

**A — Sound; keep it. It resolves an existing host split rather than creating one.** `dao.data.btree` orders datoms with Clojure `compare` (`btree.cljc:1689`), and on the JVM `compare` is *already* cross-kind numeric (`(compare 1 1.0)` → 0) while `=` is category-strict (`(= 1 1.0)` → false) — compare and `=` are inconsistent on the JVM today. The portable contract makes `=`, `compare`, and `hash` mutually consistent (equal ↔ compare-zero ↔ same hash), which is precisely the invariant sorted structures and hashed lookup require. The consumer-visible divergence from JVM host `=` is unavoidable for cross-host parity: JavaScript cannot distinguish `1` from `1.0` at all, so any kind-sensitive query equality would make Node and the JVM answer the same query differently. Content identity remains kind-strict (addresses differ), so the divergence is confined to matching semantics, where cross-host agreement is the non-negotiable. One cost note, not a design change: exact cross-kind comparison (decimal↔float↔ratio via exact rational arithmetic, "without rounding through double") is the heaviest obligation — same-kind fast paths in the comparator are advisable implementation guidance.

**B — Sound and forced by A; not too restrictive.** Under portable equality, `{1 :a, 1.0 :b}` cannot round-trip: the canonical bytes keep both entries (integer vs `dao.jing/float64` are distinct encodings), but the decoded map on any host applying portable `=` collapses them — `decode(encode(m)) ≠ m`, which the acceptance criteria forbid. The only alternatives are host-sensitive acceptance (JVM keeps both entries, Node collapses — exactly the divergence the revision refuses) or abandoning mathematical equality. The pre-decode rejection ("before decoded collection construction") is the load-bearing half: without it, the accepting host's map constructor would silently decide the boundary. The only values lost are ones that could never satisfy the round-trip acceptance — the same standing rule as "reject duplicates introduced by normalization."

**C — Acceptable; the trade is right.** Without a format header, an interrupted first write is genuinely indistinguishable from foreign content; auto-truncating it to empty would also auto-truncate any unrecognized nonempty file, which is destructive to data the store never owned. Refusing without mutation errs toward nondestruction, loses nothing acknowledged, and fails loudly. The new validate-complete-frames-before-truncation ordering is a strict improvement (a corrupt complete frame no longer has its tail silently trimmed first). The one gap is the missing operator remedy — the second finding above, one sentence, not a redesign.

**D — Consistent, and the only lossless classification.** JS `-0` carries observable sign information (`1/-0` = `-Infinity`); encoding it as integer `0` would be exactly the lossy fallback the profile forbids and would diverge from JVM/Dart `-0.0`. Positive zero stays an integer, symmetric with `1` vs `1.0` (JS callers express float kind through the carrier, which the doc already requires). One word-level nit: **float32 widening is a normalization** (JVM `Float 0.1` and its exact `Double` widening address identically, :221, :380-382) missing from the identity-after-normalizations parenthetical at :414-416 — add it so the injectivity clause's scope is complete.

## Final verdict

**Ready with corrections — and explicitly: the design is ready to implement.** The corrections are the two single-sentence documentation additions above (sequence ownership of the portable-numeric consumer boundary; the interrupted-first-write remedy) plus the one-word normalization-list addition in D. None changes the architecture, the byte contract, or any decision of record; none gates starting the implementation sequence — they can land with the step-5 documentation pass or before step 1, whichever the implementer prefers. The central invariant held throughout revision: CBOR bytes are the stored representation, backends remain opaque byte stores with their own durability, no database semantics leaked into storage, and the frozen-fixture strategy plus uniform identifier escaping removes the last host-sensitive parts of the encoding contract.
