## A. src/cljc/dao/stream/ws_project.cljc (Slice S1)

### A1. CHANGES REQUESTED — `step!` silently unbounded on an invalid budget

`ws_project.cljc:106-107`: `bounded?` is `(and (integer? budget) (pos? budget))`,
and a non-positive or fractional budget falls into the unbounded loop
(`remaining -1`). So `(step! p 0)`, `(step! p -1)` and `(step! p 1.5)` each
read to blocked.

The just-added §3.0 contract (`dao.stream.remote.md:399-402`) says "When
specified, at most `budget` events are read and processed". A specified
budget of 0 promises at most 0 events; the implementation reads unboundedly.
In a slice whose purpose is bounds, silently degrading to the unbounded mode
on exactly the misconfiguration the bound exists to catch is the wrong
failure mode — and inconsistent with the slice's own acceptor bounds, which
fail loudly as composition errors (`ws_project.cljc:196-199`,
`make-acceptor` throws on 0/-1/1.5 for both `:max-sessions` and
`:idle-timeout`). Requested: throw `ex-info` for a non-nil budget that is
not a positive integer (matching the `make-acceptor` idiom), or honor 0 as
read-nothing; add `{0, -1, 2.5}` rows beside the budget test. Small, but it
should land while the slice is open.

### A2. Architect decision required — `accept-step!` never uses the budget

`ws_project.cljc:358` calls `(step! (:project session))` — the 1-arity,
unbounded. The step budget exists as a primitive but no composition uses it.
The consensus D5 assigns S1 "admission/session/pending/idle bounds,
rejection policy, **fair scheduling** and session failure isolation", and
its required acceptance evidence includes "continuous producer cannot defeat
step budget". Today a concurrent producer appending to a session's traffic
medium (the host adapter's callback deposit path, `ws.cljc:147-158`, runs
off-driver) can keep the read-to-blocked loop (`ws_project.cljc:107-133`)
spinning inside one `accept-step!` tick, deferring every later session's
step in that tick — the exact defeat the budget prevents. Per-tick
per-session stepping still happens and no D2/D3 invariant is broken, so
this is a scope gap, not a correctness bug. The implementer's findings
disclose the deferral to S2 but not the D5-letter discrepancy. The architect
should either waive it explicitly (recording an S1-remainder for S2) or
require the small wiring now: an optional `:step-budget` in acceptor config
passed at `ws_project.cljc:358`, with a flood test.

### A3. Verified sound — rejection at cap is a live bound, not a shrinking one

`adopt!` (`ws_project.cljc:299-304`) reaps first, then closes the offered
handle with no ack and no `make-media` call when still at `:max-sessions`.
The cross-layer consequences check out:

- `WsHandle.close!` synchronously sets the handle-state `:phase :closed`
  (`ws.cljc:218-228`), and `accept-step!`'s second `endpoint-step` runs the
  pending-release doseq (`ws.cljc:609-612`) — so the handoff slot frees
  within the same tick. This matches `dao.stream.ws.md:307-316` ("the
  composition also holds the handle and closes it if acknowledgement cannot
  be deposited") and the endpoint's own comment that bounded admission is
  "a live bound rather than a monotonically shrinking one". The slot-release
  path itself is covered at the ws layer (`ws_test.cljc:218`,
  `pre-accept-peer-loss-releases-its-handoff-slot`).
- The newcomer's client-visible semantics are coherent: a pre-accept socket
  close resolves as `:ws/transport-error` on the client
  (`dao.stream.ws.md:302-305`), the same answer the transport gives when its
  own slot pool is full.
- Reap-then-reject ordering matches §3.0's "after reaping expired and closed
  sessions" (`dao.stream.remote.md:390-394`), and an idle session reaped at
  admission time has its ring closed, so a link waiting on it observes
  channel loss (2.4) rather than blocking — correct loss semantics.

### A4. Note — a flood of dropped traffic defers idle reaping forever

`active?` (`ws_project.cljc:364-365`) resets the idle clock on any reading-
or mirror-cursor advance. Continuous malformed frames (continuous `:ws/error`
deposits, dropped by `project!` at `ws_project.cljc:85`) or continuous
payloads keep a hostile session never-idle. Memory stays bounded by the
traffic medium's own admission declaration, but the session never expires.
The consensus evidence item "unrelated-traffic flood cannot defer expiry" is
written against liveness supervision (S3a), and in production each traffic
medium is per-attachment so truly foreign events should not occur; still,
the architect should state whether the idle reaper needs the same
flood-proof property (e.g. counting only mirror-visible work as activity)
or whether traffic-counts-as-activity is intended. Not blocking S1.

### A5. Note — adoption-path failures are not isolated

A throw from `make-media` or the ack `append!` (`ws_project.cljc:305-312`)
aborts the whole `accept-step!` tick. The brief's isolation checkpoint
covers one session's `step!`/`mirror-step` — delivered,
`ws_project.cljc:356-372` — and pending/retiring bounds plus admission
hardening are consensus S2 (D3: "Bound pending and retiring resources too").
Recorded as an S2 input: a hostile offer must not be able to crash the
acceptor tick through the adoption path either.

### A6. Note — `now` handling edge

A session admitted under `now = nil` gets `:last-activity-ms 0`
(`ws_project.cljc:326`), so the first real-`now` tick reaps it instantly
(`>=` at `ws_project.cljc:229`). Both callers always pass `now`
(`yin/repl/serve.cljc:696`, `yin/vm/linker/head/ws.cljc:286`), and
`session-idle?` never fires on nil-`now` ticks. Harmless; recorded for
completeness.

### A7. Verified sound — purity, concurrency, idempotency

- All side-effecting closes run outside `swap!`: `reaped` closes handles
  (`ws_project.cljc:254-264`) but is only called from `reap-sessions!`
  (`ws_project.cljc:271-275`), which computes kept sessions from a deref and
  then `swap! assoc`s; the catch's `close-session-resources!`
  (`ws_project.cljc:371`) also runs outside its `swap!`. The `swap!` fns
  themselves (`ws_project.cljc:366-368`, `:372`) are pure — no side effect
  repeats under swap retry. Single-driver ownership is documented
  (`ws_project.cljc:269-270`).
- The catch may close an already-closed ring; ringbuffer `close!` is
  explicitly idempotent (`ringbuffer.cljc:137-144`), so this is safe.
- The catch clause `#?(:clj Throwable :cljs :default :cljd Object)` follows
  the existing three-host idiom in this codebase (`ws.cljc:122`).
- `step!` with a budget preserves the reading cursor and continuation
  state: the cursor advances per ok/gap read (`ws_project.cljc:117`,
  `:129`), budget exhaustion returns between reads, blocked and end consume
  no budget, and gaps count against it — exactly D3's "Count malformed
  reads/gaps too".

### A8. Verified sound — closed-projection sessions are dropped, not leaked

`reaped` drops a `session-closed?` session without closing its handle
(`ws_project.cljc:257`). The ring was already closed by the projection
itself (terminal event or medium end close it in `step!`/`project!`), and
the handle is the transport's to have closed: only the host
close-completion callback deposits `:ws/closed` (`dao.stream.ws.md:160`),
and the failure resolutions imply teardown. This matches pre-S1 behaviour
exactly. The one edge — a host composition ending the traffic medium while
the socket stays open — leaves the handle to the medium's owner, a
pre-existing contract, unchanged by this diff.

## B. docs/design/dao.stream.remote.md (Slice S0)

### B1. CHANGES REQUESTED — `:idle-timeout` alias undocumented

§3.0's idle bullet (`dao.stream.remote.md:395-398`) documents only
`:idle-timeout`, but `make-acceptor` also accepts `:idle-timeout-ms`, with
`-ms` silently winning when both are given (`ws_project.cljc:183-190`), and
neither §3.0 nor the `make-acceptor` docstring states the precedence. Two
spellings for one bound with hidden precedence invites config drift. Either
name the alias and its precedence in §3.0 and the docstring, or drop the
alias. One paragraph.

### B2. ACCEPT — §3.0 placement and content

Inserted as `### 3.0` directly under `## 3. Channels` and before `### 3.1
WebSocket` (`dao.stream.remote.md:375-406`); compact (33 lines). It states
the D1/D2 boundary invariant verbatim in substance — dao.stream is the sole
boundary; transport swap preserves handle operations, outcome algebras,
opaque cursors, source gap/recovery and append semantics; a raw network
drop is never invented as a source-retention gap — and cadence stays
driver-owned (no ambient timers, daemon loops or background threads).
No new registry, no new core operation, no public closed? predicate — S0's
D5 constraints hold. The four bounds bullets match the implementation as
verified in A (with A1's edge and B1's naming gap the only divergences).
