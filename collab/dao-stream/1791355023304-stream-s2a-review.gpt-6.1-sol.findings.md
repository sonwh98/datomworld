## Blocking finding

### R1 — P1: dial mirror effects execute inside an atom retry function

**Location:** `src/cljc/dao/stream/ws_project.cljc:587-590`; effect paths `src/cljc/dao/stream/remote.cljc:235` and `:161-168`.

`dial-step!` calls `remote/mirror-step` inside the function supplied to `swap! mirror-cursor`. That function reads streams, invokes source operations (including append!), and writes answers. If the cursor atom changes before the compare-and-set commits, swap! executes those effects again. The cursor transaction cannot roll back an already accepted source append or answer write.

This fails the task's explicit checkpoint “Are all side-effects kept outside atom retry?” It also means the non-rewind branch for append! does not by itself prevent duplicate execution through the dial composition. A retry can exceed a tick's mirror budget.

**Provenance:** This effectful swap! already existed at HEAD. S2a changes its body to pass bounds but preserves the defect. This is an inherited defect in the specifically reviewed/touched path, not a claim that S2a introduced the retry hazard. The blocking verdict follows the requested purity checkpoint; the new remote loop itself otherwise passes the inspected requirements.

**Deterministic reproduction, executed without writing a test file:** construct the minimal dial state consumed by dial-step!, with one append! request and mirror-budget 1. Wrap the real mirror-step to replace the cursor atom's value after its first invocation with an equal cursor carrying different metadata. This changes object identity, forces the swap! CAS to fail, and leaves the logical cursor unchanged. The wrapper performs no source append itself.

Observed:
```clojure
{:source-values [:once :once], :answer-count 2, :mirror-invocations 2}
```

The following executable reproduction uses only the current implementations plus the stated CAS-conflict instrumentation:

```clojure
(require '[dao.stream :as s] '[dao.stream.ringbuffer :as rb] '[dao.stream.remote :as remote] '[dao.stream.ws-project :as p])
(defn ring [] (:dao.stream/handle (rb/create! {:dao.stream/type rb/transport-type rb/capacity-key 16})))
(defn values [h] (loop [c (:dao.stream/cursor (s/cursor h :dao.stream/oldest)) acc []] (let [r (s/next h c)] (if (= :dao.stream/ok (:dao.stream/outcome r)) (recur (:dao.stream/cursor r) (conj acc (:dao.stream/value r))) acc))))
(let [source (ring) requests (ring) answers (ring) c (:dao.stream/cursor (s/cursor requests :dao.stream/oldest)) cursor-atom (atom c) dial (atom {:ring requests :table {"w" {:handle source :surface #{:writer}}} :channel (atom {:handle answers}) :mirror-cursor cursor-atom :mirror-budget 1}) step remote/mirror-step calls (atom 0)]
(s/append! requests {:dao.stream/identity "w" :dao.stream.remote/op :dao.stream/append! :dao.stream.remote/args [:once] :dao.stream.remote/id 1})
(with-redefs [remote/mirror-step (fn [& args] (let [result (apply step args)] (when (= 1 (swap! calls inc)) (reset! cursor-atom (with-meta @cursor-atom {:force-cas-retry true}))) result))] (p/dial-step! dial))
(prn {:source-values (values source) :answer-count (count (values answers)) :mirror-invocations @calls}))
```

A separate two-driver overlap reproduction, synchronizing the first two mirror invocations after their effects and before cursor commits, also produced two source appends and two answer writes for the same request (three mirror invocations, the final retry reading blocked). This demonstrates the caller-overlap hazard in addition to the forced-retry mechanism.

**Requested correction:** compute mirror effects outside atom retry and commit only the resulting cursor through a state-only operation. Follow the explicit driver ownership model; if overlapping driver calls must be supported, serialize the complete tick before executing effects. Merely replacing swap! with reset! does not make concurrent ticks safe. Add a meaningful dial regression demonstrating that a cursor commit conflict cannot re-execute append! or multiply answer writes.
