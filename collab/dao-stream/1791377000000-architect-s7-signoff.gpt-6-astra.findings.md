## Architectural and implementation findings that pass inspection

- **Layering and invariants:** Only prelude.cljc and data.cljc change production behavior. Limits remain explicit immutable composition values; no hidden global state, mutable configuration, callback, new effect channel, AST schema, Jing encoding, heap/store protocol or UCF profile field is introduced. Python-specific refusal translation stays in the interpreted prelude; generic data registration remains language-independent.
- **Sequence bound:** The quotient comparison preserves the signed 64-bit Py_ssize_t interval before handling empty or negative repeats. Non-integers raise TypeError; out-of-range counts raise OverflowError. Empty sequences and negative in-range counts reduce to zero. Exact integer/mul computes the result size, integer/compare checks data/max-items, and py/int-result translates either a bit-limit breach or an item-limit breach to MemoryError with empty args before the repetition loop. py/imul computes the repeated value before cell/set!, preserving a list on refusal. Scope remains repetition, as ruled; incremental growth is not silently assigned this limit.
- **Data module:** The one-argument registrar retains its existing exports. The two-argument registrar validates a positive native integer through exact-integer?, exclusion of big carriers, and pos?, then adds an arity-checked, pure, zero-argument export. No default is smuggled into the registry. Tests cover absence, explicit registration, invalid input, arity and four-VM access.
- **Admission:** prelude/admit checks every declared host name using the registry's dotted resolution path, deterministically sorts all missing names, emits the specified qualified refusal data, and returns the original registry on success. This implements name admission, not full callable/profile attestation, consistent with the bounded interim design and later linker requirement discovery.
- **Profile portability:** PM1 names the three missing version-4 integer exports and missing data/max-items. PM2 lifts a version-1 2^100 result, resumes under the small registry, checks that limits are absent from the body, and ties the resumed value to the S0 small-profile outcomes. No execution-profile identity is added to content.
- **round and keywords:** The float branch checks ndigits type before the deliberately unsupported round(float, ndigits) result. Non-numeric x retains the missing-__round__ TypeError first. pow/round retain keyword acceptance per the governing measured ruling; adding :no-kw would be incorrect. int(x=...) remains the documented divergence.
- **Corpus design:** Ten named programs distinguish eight CPython measurements from two labelled profile hand pins. Source/docstring/parser-packet binding prevents independently drifting portable packets. Tests compare exact stdout and absence of an exception, with all four VM runners; JVM source tests also exercise no-op hooks. The generator now rejects blank output lines.
- **Goldens:** The five affected prelude/image addresses are updated and the hook-prelude address is unchanged. Recorded fast-lane verification supports the checks actually executed; skipped image/semantic bodies still require S7-1 closure.
- **Ledger:** The new overflow and round-order measurements, lint-scope docstring, deferred Unicode repr work, accepted shift allocation class and NaN-sign limitation are consistent with the supplied rulings.

No additional production-code correctness defect was established in this review. That observation does not substitute for the missing acceptance runs.
