## The fix — recovery trusts ONLY the shell's own records

Astra's F2: the DEFAULT `format-value` path realizes a returned lazy seq through `first`/traversal at ~:639, called from `finalize-eval`'s fallback at ~:1355 — outside all three r9/r10 wrap sites — so `(lazy-seq (throw (ex-info "late boom" forged)))` reached a recovery catch with its payload intact, and recovery merged the forged keys. r7-r10 patched throw sites one at a time (loader wrapper, link-raise, render hook) and each round found the next route. r11 takes astra's structural alternative: recovery obtains retention evidence EXCLUSIVELY from the data structures the shell itself maintains at its own operation boundaries — never from exception-carried keys. Any exception, from any host-code execution point in the round (renderer, formatter, or a seam not yet written), now carries zero retention evidence because recovery reads none.

Five changes, all in `src/cljc/yin/repl.cljc`:

1. `run-evaluator-stage` (repl.cljc:1536) takes the round's shell accumulator `latest` (the volatile `run-evaluation` owns). Its catch records what this stage's loaders completed — `@handles` merged into `:call-provenance-handles`, `@failures` appended to `:call-provenance-failures` and set as `:call-provenance-round-failures`, the empty record included — into `latest` via `vswap!`, then RETHROWS THE PROGRAM ERROR AS ITSELF. The former ex-info re-wrap (r3 F4 carriage, made unconditional in r9) is gone: nothing retention-shaped rides the exception.
2. `run-evaluation`'s catch (repl.cljc:2022) passes `latest` into the stage and reads retention evidence ONLY from `@latest` — handles merged, failures and round-failures assoc'd — never from `(ex-data error)`. `@latest` is always at least `expanded` (it starts there, and the evaluator stage records into it before rethrowing), and its failure vector extends `expanded`'s by construction (the stage appends), so the r8 diagnostic and its round Warning survive exactly once, duplicate-free. The `retention-recovery-failures`/`retention-recovery-round-failures` helpers (exception-preferring merge logic) are deleted — unused.
3. `recheck-pending*`'s catch (repl.cljc:2514) reads no payload at all: `st` — the shell's own session state, drained — already carries every handle and failure the parked run's loaders recorded before it parked (retention happens in the loader at load time; the resumed run adds none), so the `(::call-provenance-* d)` arms are simply gone and the `cond->` collapses to the plain rollback `assoc`.
4. `finalize-eval`'s r10 render wrap is REMOVED — a plain `(render value)` / `(format-value value …)`; a raise from either flows to the round recovery raw. The docstring now states the r11 contract.
5. `link-raise` no longer assocs the three retention keys. It still re-wraps for rollback identity — `::link-counter`, `::link-origins`, `::query-pair`, `::linker`, `::dht`, `::indexer` — which are not retention evidence and are attached only by this shell-owned site.
