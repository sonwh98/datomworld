## Implemented

`yang.correspondence-batch` is the resumable outcome record: `initialize!` refuses to reset an existing run; `record!` validates each outcome per status (a pass carries its admission origin and measured storage; a refusal names its stage), refuses unknown fixtures and malformed entries, and makes every recorded outcome final; writes go through a same-directory temporary file with fsync and an atomic move so a reader never sees a partial record. The corpus driver `d1-corpus-batch!` (oracle test namespace) runs the next N-or-fewer not-yet-recorded fixtures — each under a fresh recorded admission of the batch run, each through the full r7 per-fixture static gate — recording outcomes atomically; the deftest `test-d1-corpus-static-gates` drives it from a run-config file (scratch mode without one: 3 fixtures, resumability, finality, spot checks — the standing-battery form).

`d1-persist-and-check-fixture!` gained an optional live store handle (batch-scoped; one cross-process reopen per batch invocation), per-fixture measurements (store-growth delta, pre-stamp and stamped row-closure counts, site count, elapsed), and a mutated-input spot-check battery covering every distinct gate refusal class on real fetched fixture data. A per-batch heap sampler existed for ceiling aid only; no durable heap maximum was recorded (named in the declaration).

A defect clj-kondo caught before it could bite: `outcome-refusal` built its ex-data with a dangling `assoc` argument, so every refusal path threw the wrong exception — masked until now because the tests assert `thrown? Exception`. Fixed; refusal ex-data now carries rule, reason, fixture.
