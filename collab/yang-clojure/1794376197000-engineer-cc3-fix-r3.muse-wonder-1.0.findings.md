### F1 P1 — correspondence grammar data, gate-site! recognizer, duplicate site IDs — FIXED

- Scalar grammar data (`test/yang/latte_oracle_test.clj`, `cc3-correspond`
  ~:3507): the traversal's scalar branch (`:data/:sym/:syms/:bool/:kw/
  :key/:str/:int` grammar fields) now requires `(= pv sv)` at the
  translated position and refuses with `:rule :cc3-stamp-correspondence`
  (carrying `:field/:pre-value/:stamped-value`) on any difference; the
  leaf `:else` branch likewise compares non-node pairs instead of
  accepting them. Changing a callee variable name, a literal value, or
  lambda parameters — same shape, different grammar data — no longer
  preserves a false correspondence.
- Wrapper recognizer (`kernel-stamped-args?` ~:2030): now additionally
  verifies the wrapper's helper operand is the `:variable` named
  `gate-site!` (the helper at ~:2029's stamped shape), not any
  application in wrapper shape.
- Duplicate site IDs (`cc3-oracle-binding` ~:3656): stamped site
  entries are collected into a vector BEFORE any map is built; a
  duplicate site id refuses there with
  `:rule :cc3-duplicate-stamp-site` (naming the duplicated ids), and
  only then are `:binding` and `:stamped-paths` constructed from the
  checked entries. The old build-then-check overwrite loss is gone;
  the pre-existing distinct-values (ambiguous occurrence) check is
  unchanged.
- Tests: `test-cc3-correspondence-verifies-grammar-data` (new) pins
  same-shape mutation refusals (variable name, literal value, lambda
  params, renamed nested callee through a real stamped tree),
  recognizer refusal for a non-`gate-site!` helper, and duplicate-ID
  refusal on the real binding fixture.

### F2 P1 — per-JVM global counter → explicit admission/run scope — FIXED

- `kernel-admission-counter` (the global atom) is DELETED; there is no
  hidden global state left in the admission path
  (`datom.world.md:26` invariant restored for this harness).
- `kernel-compile` (~:2456) takes the admission coordinate
  explicitly on every call (no default arity): the admitting
  composition supplies `admission-scope` and the per-scope
  `admission-ordinal`, recorded as the batch token
  `[admission-scope admission-ordinal]` of
  `[:source :program [scope ordinal] 0]` — member index zero, since
  each admission is a separately admitted single-member batch, so
  projected keys (reconstructed from a single-member envelope, member
  index always zero) agree with the recorded origin for every
  ordinal, including nonzero ones. The coordinate is built and
  validated when admitting, before compilation, by
  `vm/source-origin` — the same origin-shape rules as every source
  origin — and retained with the compilation as plain data
  (`:admission-origin`, plus `:admission-scope`/`:admission-ordinal`).
  Every caller in the harness now supplies its coordinates
  explicitly. Replay (`cc3-oracle-binding` re-run on one retained
  compilation) reuses the recorded coordinate and answers the
  identical binding. (An initial r3 form — scope as token, ordinal as
  member index, with a default run scope — was refined to this token
  form during the round so that nonzero ordinals also bind
  end-to-end; the test below pins that.)
- Test: `test-cc3-distinct-admissions-distinct-origins` (rewritten)
  admits identical content (same canonical hash) under scopes
  `"run-a"` and `"run-b"`, BOTH with ordinal restarted at 0, plus
  `"run-a"` at ordinal 1, and pins distinct origins for each, every
  ordinal binding end-to-end under its own origin, and replay
  stability for scope `"run-a"` ordinal 0.
