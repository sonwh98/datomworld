## Launch, closure and expansion findings

The candidate direct composition is identifiable but not a launch configuration: `d1-assemble` builds the instrumented body and `yang/library-for` prefix, and `kernel-compile` calls `yang/compile-program` with `true` and the assembled options before `kernel-stamp-sites`. `d1-check-reconstruction!` compares assembly, compiled/stamped roots, source hash, site table, metadata, binding and correspondence in the already-loaded producer process. Its compiler and helpers come from the invoking checkout; it is not the requested isolated entrypoint. The current `correspondence-manifest` is explicitly a draft byte inventory. Its launch fields do not enforce environment clearing, locale, encoding, initialization or the actual process invocation, and no executable manifest using it was produced.

The ordered r19 classpath and the retained normalized JDK identify candidate inputs, but loading the oracle namespace itself performs classpath resource reads, including `yang/latte_oracle/manifest.edn`, and the source has dynamic `requiring-resolve`, evaluation and other reads. Some other paths read relative files and JVM properties. Consequently an empty or guessed environment map and working directory would not be a substantiated complete launch specification. A final plan must identify its exact entrypoint and initialization, package-relative working directory and resource mapping, ordered source/binary paths and resolution rules, retained runtime, supported host, JVM and property values, locale/encoding, explicit environment and allowed host facilities; the launcher must actually apply and check them. The environment must not silently inherit variables such as Java option injection or dependency-cache settings. Determine the reachable source/resource and native dependencies for that entrypoint, include all required bytes, and test with checkout and caches unavailable. Mere presence of the full observed snapshots does not resolve ambient file, native, or initialization dependencies.

The direct frontend documents that it lowers frontend forms and does not perform row-native macro lookup; the producer composition calls compile and stamping directly. That is useful static evidence for a bypass candidate, not the ruling's checked execution of a pinned composition. No expansion inapplicability declaration is issued. Historical expansion and admission evidence remain separate and cannot be invented from later matching outputs.

The r7 repository-relative, scratch-copy-before-open location is still a proposal. A real owner and discovery/availability commitment must be identified for the complete package before acceptance. The r19 JDK object, r20 jar bundle, and r21 directory bundle remain scratch.
