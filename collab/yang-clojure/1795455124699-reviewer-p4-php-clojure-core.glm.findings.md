## Findings

**MEDIUM | src/cljc/yang/php/antlr/lower.cljc:3382-3384,3413-3423** | Closure captures leak into functions *declared* inside a closure body. `persistent-lambda` (3448) passes `(assoc ctx :captures slots)` down; when a `functionDeclaration` occurs inside that lambda body, `lower-function`'s non-legacy branch forwards that ctx to `persistent-function`, whose `names` includes `(keys (:captures ctx))` and whose binding init wires them to `%capture-*` slots. So `$f = function() use ($x) { function inner() { return $x; } };` binds `inner`'s `$x` to the closure's *captured* value, where PHP reads `inner`'s own scope (implicit null + notice - a declared function is never a closure). Silent wrong value in the default profile; only nested declared functions inside captured closures are affected (nested lambdas replace `:captures` correctly; plain function-in-function is unaffected since no `:captures` is in scope). Untested: all suite programs declare functions at top level. Fix: strip the leak at the boundary - `lower-function`'s non-legacy branch should call `(persistent-function (dissoc ctx :captures) ...)` (a declared function is not a closure) - and/or add a fixture for a function declared inside a closure.

**MEDIUM | src/cljc/yang/php/antlr/lower.cljc:813-824** | Bare `isset($x)` under `clojure-core-v1` fails closed through a *native* hook with a misleading reason. `isset-var` was never given a persistent branch: inside a function it emits `:php/local-isset?` (823), at top level `scope-op "isset?"` maps to `:php/global-isset?` (824); both roles are native-only, so `hook-name`'s fallback refuses with `:capability :runtime/native :construct :php/global-isset?`. The surface is inconsistent: `isset($a['k'])` *works* (offset path lowers to a null-compare at 1090-1093), `empty($x)` works (1183-1187 lowers to `not(truthy(peek))`), and `lower-call-plain`'s non-legacy `case` special-cases `"isset"` (1979ff) as if supported. Nothing in `clojure-capabilities` names this refusal, and the capability-refusal fixture list has no isset entry, so the refusal is undeclared and untested. (Related known narrowing, acceptable per profile: the offset form's null-compare conflates a stored `null` value with an absent key - `isset($m[null])` on `[null => 'nil']` answers false.) Fix: either lower bare `isset` under the persistent profile to a presence check the profile can express (`(not (= <read> nil))`, consistent with `empty`'s treatment, or a `data/contains?`-backed helper over the state's `:vars`), or declare the refusal honestly (dedicated capability + fixture) instead of blaming `:runtime/native`.

**LOW | src/cljc/yang/php/antlr/lower.cljc:1987** | `lower-call-plain`'s non-legacy `"unset"` arm returns the result of `require-capability!` - nil - when the capability is *not* refused, silently lowering `unset(...)` to nothing. **NOTE | src/cljc/yang/php/antlr/contract.cljc:18-21** | `==` (`:op/eq`) and `===` (`:op/identical`) both map to `clj.php/eq` (`data/equiv`), and `!=`/`!==` both to `ne`: loose equality collapses onto kind-strict equality under the profile.
