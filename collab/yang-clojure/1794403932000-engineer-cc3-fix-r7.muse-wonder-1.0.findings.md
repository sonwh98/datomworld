## Item 1 — the 6 round-text failures: FIXED

**Mechanism (named).** cc3 r2 item 4 connected provenance retention to the production load path: `run-evaluator-stage` in `src/cljc/yin/repl.cljc` wraps every loader with `retaining-load`, which — before calling the real `load-program` — calls `retain-packet-call-provenance!`, which calls `jing/materialize!` twice on the session's `:index-store`. Ordinary Clojure rounds do create a claim (verified by probe: evaluating `(defn g …)` then `(g 10)` populates `repl/call-provenance-handles`), so on a store whose `put-bytes-fn` throws, `materialize!` threw *inside the loader*, before the program ever ran. `run-evaluator-stage` propagated it, `eval-program`'s catch routed it to `consume-failed-round`, and the round rendered `Error: store refused the write` with the value (`3`, `5`) lost and the query path's `(:yin.repl.query/index-unavailable)` refusal never produced. At master there is no retention on this path: the program evaluates, and the publication failure is reported by the indexer's own stage as the trailing `Warning: this round's code is not in the published code index (materialize failed: …)`. The regression window is r2's wrapper (retention connection), made unconditional-on-claim in the r4–r6 rounds; cc3's diff does not touch `index.cljc`/`query.cljc`, confirming the wrapper as the sole suspect.

**Fix.** Failure-isolate retention inside `retaining-load`: the claim lookup + `retain-packet-call-provenance!` now run in a `try` catching `#?(:cljd Object :clj Exception :cljs :default)`; on any throw, nothing is retained for that packet (absence, never invention — no handle is recorded) and `(load-program vm packet)` proceeds exactly as at master. Retention is a side artifact outside every manifest hash, so its failure must not change the round's value, Warning, or error text. No test was re-pinned; the provenance functionality (side artifacts, admission pairing, coverage refusals) is untouched, and `yang.clojure-callsite-test` (36/403, including the durable/survives-failure/survives-link-resume retention tests) stays green, proving retention still persists on the success path.

**Red-first evidence.** Before the fix, laptop at `0ec036d1`: `clojure -M:test -n yin.repl.index-test -n yin.repl.query-test` → 45 tests / 593 assertions / **6 failures** (`index_test.cljc:560`, `:563`; `query_test.cljc:390` ×4), with actual text `Error: store refused the write\nWarning: …` vs expected `3\nWarning: …` / `(:yin.repl.query/index-unavailable)`. After the fix: **0 failures**.
