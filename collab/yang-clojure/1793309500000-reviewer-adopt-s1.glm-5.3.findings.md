## Findings

**P1 | src/cljc/yang/clojure.cljc:1032-1055, 1146-1155 | User-shadowable names capture the new generated entry/bridge code.** The descriptor entry and caller bridge emit bare `get` (1032-1034, 1148, 1153), `=` (1048, 1147), `assoc` (1037, 1041, 1057), `empty?` (1045) as `:variable` nodes lexically inside whatever user binders enclose the fn site or call site. `check-binder!` (clojure.cljc:204-216) permits binding all four; `with-locals` (clojure.cljc:174-177) rejects only `conj`/`vec`; the keyword-call path guards local `get` (clojure.cljc:1205-1207), proving the hazard model is known. `conj` in `outcome-node` (1023) is covered by the existing guard; the four new names are not. Confirmed by probes: `(def f (let [get 5] (fn [x] x))) (f 1)` → host crash "Cannot apply non-function" (was `[:yin.k/ok 1]`); `(let [= not] …)`, `(let [empty? not] …)`, `(let [assoc not] …)` around an fn → "data primitive refused"/"Wrong number of args"; a `get`-shadowing param corrupts the raise path's condition→outcome conversion (`(fn [get] (g))` with `g` throwing → "Cannot apply non-function" instead of `[:yin.k/error {:yin.k/message "boom"}]`). The base emits none of these bare (verified by grep of `git show 64f2885a`). Fix: reject local bindings of `get`/`=`/`assoc`/`empty?` at fn/guest-call sites (keyword-call precedent), or emit them through dsg__-bound aliases established once beside the prepended `call/uast` (the data module exports no `get`/`assoc`, so `data/`-qualification is not available).

**P1 | src/cljc/yang/clojure.cljc:1057-1059 + src/cljc/yang/core/call.cljc:33-40 | Ordinary map writes forge callables; the data-map boundary fixture is missing.** Descriptors are plain immutable maps built by guest `assoc`, and `yang.call/eligible?` is purely structural (any map with non-nil `:yang.call/entry`). Probe: `(let [h (assoc {} :yang.call/entry (get f :yang.call/entry))] (h 21))` → `[:yin.k/ok 42]` — an ordinary `assoc` mints a working callable. The ruling's Additional obligations state "A source map containing `:yang.call/entry` remains data unless constructed by the pinned callable constructor/projection. Ordinary map writes must not overwrite or forge the runtime entry", and the 8.10.11 acceptance gate requires exercising "source data with an entry-spelled property remains data" (yang.antlr.md:4029-4031). No negative fixture exists; `test-common-call-hand-constructed-descriptor` (test/yang/clojure_test.clj:1183-1191) enshrines the opposite admission. Mitigating context: the orchestrator prompt (collab/1793338209376-…prompt.md item 5) explicitly directed the hand-constructed fixture "as the spec's own illustration shows". This needs architect arbitration: either seal/admit via a pinned constructor, or record the structural admission as this profile's defined projection (yang.antlr.md:3590-3592 gives cover) and add the boundary fixtures (non-callable entry → stays data; forged/assoc'd descriptor → refused).

**P2 | src/cljc/yang/clojure.cljc:1163-1169 | A2's "a missing entry means not callable" is not enforced for source applications.** The routing is `(if (yang.call/eligible? callee) common-call direct-call)` — a value-structural exemption ("anything without an entry applies directly"), not dsg__/private-scoped. `:yang.call/not-callable` is unreachable from compiled source calls; an entry-less foreign callable (e.g. a pre-migration py/js cell, which is a map) surfaces as a raw VM defect — probe: `(let [x 5] (x 1))` → host "Cannot apply non-function" — rather than the qualified condition. The reachable closure cases (adapters, macro lambdas, continuations) do work, and the orchestrator prompt item 2 sanctioned "plain non-descriptor closures (internal, private, pre-adopted program values) apply directly as today", which is broader than the architect's "internal compiler-generated calls may remain private". Fix: record the deviation with the architect, or scope the direct branch (e.g. compiler-generated callees only) so missing-entry foreign values get the protocol condition.

**P2 | test/yang/clojure_test.clj:1355-1384 | Tail-chain stack growth: a documented invariant was dropped, not preserved.** The base asserted `d100 = d1000` ("depth constant in the iteration count") and the base comment (clojure.cljc:618-621, rewritten in this diff) guaranteed "the semantic VM's return stack stays constant through tail chains". The renamed `test-outcome-common-call-depth` now *asserts* linear growth — 9 frames per source activation (`(= (- d1000 d100) (* 9 (- d100 d0)))`) — and deleted the constant-depth assertion for both lanes. `loop`/`recur` chains remain constant (`test-continuation-depth-gates`, clojure_test.clj:1088). No hard VM depth limit exists (3000-deep named tail recursion completes), but deep named/mutual recursion now consumes ~9 frames/activation, and A2's obligation list includes "tail behavior" (fast-path preservation; no fast path exists here). Fix: acceptable only as a recorded architect tradeoff with a follow-up fast path; otherwise the entry/bridge needs a constant-stack design for tail calls.

**P3 | src/cljc/yang/clojure.cljc:1165-1169 | Silent bad-value fallback when the captured continuation is not callable.** `(if (data/callable? escape) …common/direct… escape)` returns the continuation itself as the call's value instead of refusing. Unreachable on both current lanes (walker and semantic both evaluate `%capture` to a callable), but the branch should refuse, not yield a continuation as a value.

**P3 | src/cljc/yang/clojure.cljc:1035-1042, 1052-1055 | Named-argument binding errors ride `:yang.call/thrown`.** The nonempty-named rejection produces a slice-5 error map raised as a `:yang.call/thrown` condition, indistinguishable at the caller from a guest throw; 8.10.7 (yang.antlr.md:3852-3858) provides qualified reasons (e.g. `:yang.call/unsupported-binding`) for callee binding failures. Data is preserved either way (probes confirmed message/data/named round-trip), so informational.
