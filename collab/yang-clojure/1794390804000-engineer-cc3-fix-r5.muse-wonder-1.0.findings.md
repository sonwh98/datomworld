## Item 1 — F2 residue: scope threaded through the ACTUAL callers — FIXED

- New run composition: `fresh-admission-run` (latte_oracle_test.clj)
  allocates ONE admission run — a fresh scope supplied as plain data
  (`"<label>-<UUID>"`) plus a run-local ordinal allocator (an atom
  created per run, held only by the run map; no per-JVM global
  counter). `kernel-compile-in-run` / `kernel-row-in-run` thread that
  run through the actual callers, assigning DISTINCT ordinals within
  the run. Replay never allocates a fresh run: it explicitly
  re-supplies the retained run's scope+ordinal, or reuses the
  retained compilation (the pre-existing binding-replay pin).
- `kernel-row` now takes `[fixture run-scope admission-ordinal]`
  (the old always-`:kernel-row 0` call is gone) and records
  `:admission-origin` / `:admission-scope` / `:admission-ordinal` on
  the row; the evidence writer dissocs those three when landing the
  versioned evidence file, so generated evidence stays stable across
  fresh scopes. `kernel-gate-evidence` — the run composition of the
  evidence run — allocates its scope ONCE and threads it through
  every fixture row via `kernel-row-in-run`.
- Every other caller updated: the proof-supply doseq, the proof-loop
  doseq, and check-proof (one `fresh-admission-run` per testing
  block, distinct ordinals per iteration); the principal binding
  test (allocates its enclosing `:cc3-binding-run` identity once,
  compiles as its ordinal-0 admission, and pins
  `[(:scope run) 0]` as the origin's batch token); the duplicate-id
  test; `test-kernel-unused-arity-execution`; the h3-2 and h3-3
  families; and the attribution battery (one run threaded through
  all its rows, including the nested case-3/case-6 rows). No
  `:kernel-row 0`, `:proof-* 0`, `:check-proof 0`, or fixed
  `:cc3-binding-run 0` coordinate remains.
- Pin through the ACTUAL caller path (new deftest
  `test-cc3-caller-run-threads-distinct-admissions`): through
  `kernel-row` itself — identical content admitted twice in one run
  takes ordinals 0 and 1 under the run's one scope and mints
  distinct origins; a fresh run supplies a distinct scope, restarts
  at ordinal 0, and still mints a new origin; explicitly
  re-supplying the retained scope+ordinal 0 reproduces the first
  row's origin (replay). Constructor-level pins (distinct scopes,
  nonzero ordinal, binding replay) remain in
  `test-cc3-distinct-admissions-distinct-origins`.
