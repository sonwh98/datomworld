Answers to §9’s six questions:

1. **Occurrence inside or beside the hash:** Keep occurrence and origin inside the authenticated task body for this proposal. That follows the governing UCF rule and binds custody context to the published checkpoint. Separating an occurrence-independent execution-state address is an owner-level protocol decision; if pursued, retain a separately authenticated full checkpoint address. It does not fix the missing cell-content commitment.

2. **Packing:** Neither invariants nor semantics require one physical storage layout. Recommend individual immutable content rows plus a self-contained transport pack. Give the pack its own address when addressed; keep it distinct from the semantic root. Resolve loader interfaces and root-scoped cell identities explicitly, consistently with code-as-tuples §2.1.

3. **Nested grammar’s fate:** Recommend retaining existing versions as compatibility inputs and one canonical nested projection for single-message channels. Rows should become the proposed carrier authority once specified. Legacy nested forms normalize into it; permanent exact mutual inversion should apply only to the canonical projection. Retirement of old readers is an owner/version-support decision.

4. **Contract stamp:** A carrier-only change does not require changing executable-code `"v3"`. Existing amendments establish that distinction. It does require a new, unambiguous transport/profile revision and compatibility gate. Body version 2 cannot be reused; changing instruction or scheduler semantics would separately require an execution-contract revision.

5. **Reified continuations:** Sharing immutable register rows is acceptable. Reified and parked value classes must retain distinct outer discriminants and lowering behavior. Reified captures have no pending wait; parked references resolve in task context. The current `:regs` shape does not meet these requirements.

6. **Foreign-engine value profiles:** Required before an implementation brief claims heterogeneous execution conformance. Publish admitted values, numeric behavior, key equality, metadata, resource/profile requirements, refusal sets, and safepoint reconstruction obligations. Slot losslessness alone does not establish execution parity. Existing four-profile transport explicitly does not translate between kernels; this proposal must distinguish that from foreign engines implementing canonical semantic-VM execution.

Requested properties that passed review:

- Semantic safepoints remain `(segment-address, pc)`; deterministic instruction lowering is the correct basis.
- Tuple transport at rest and destination-native execution preserve interpretation/execution layering. Querying rows need not enter the hot loop.
- Immutable transport and isolated task/resource/module-store restoration introduce no shared mutable state.
- No hidden global state, callbacks, or implicit control flow are required by the approach. Custody completeness must be restored as described above.
- Explicit row references can satisfy “no assumed graphs,” once polymorphic references and context lookup edges are specified and validated.
- Distinct logical cells, repeated references, and one fresh native allocation per cell correctly preserve aliasing. Including the cell id in wrapper hashes is useful, but insufficient without hashing cell contents elsewhere.
- Sorted guest environment bindings lose no shadowing history: E is a persistent map, and overwritten bindings are already absent. Its separate module association must survive.
- One nil-padded `:kframe` kind is acceptable if a closed frame-type table fixes every required and forbidden slot. Distinct row kinds are optional. The same applies to reason-dispatched `:pending`.
- Positional rows are a reasonable choice: compact, closed, and compatible with existing row conventions. EAV is also expressive enough; neither the invariants nor the prior review compel its rejection.
- Physical tuple-set enumeration need not be canonicalized for a complete Merkle root. Identity payload commitments and canonical internal representations must first make that root complete; an addressed pack needs its own canonical encoding.
