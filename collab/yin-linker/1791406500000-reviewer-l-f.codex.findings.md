## 2. Findings

### F1. P2, blocking: the required prelude-sized oracle comparison is absent

Location: [free-name conformance test](../test/yin/vm/linker_test.cljc#L787), [definition/application conformance test](../test/yin/vm/linker_test.cljc#L771), [slow publication test](../test/yin/vm/linker_test.cljc#L1463).

Both oracle comparisons stop at `wide-module 12`. The 6006-row `wide-module 1000` test only publishes and checks link outcomes. It never compares the free-name records with `vm/occurrence-rules`, or the converted definition/application scanners with their query oracles. R4 explicitly requires the oracle fence on a synthetic module of the prelude's size; R5 applies the same obligation to converted scanners. A successful publication does not establish equality of the underlying occurrence records.

Engineer finding 4.5 accurately discloses the omission, but the oracle's expense is not a waiver. The slow lane exists for expensive evidence. Add a guarded slow conformance test at the required size, preserving path and enclosure comparisons, and report its result. Alternatively, obtain an explicit Architect amendment reducing that requirement. The current report cannot claim full R4/R5 conformance.

### F2. P2, blocking specification disposition: the slow test reverses the AST acceptance expectation

Location: [AST assertion in the slow test](../test/yin/vm/linker_test.cljc#L1486).

Section 3.3 requires four successful links retaining only declared primitives. The implementation instead requires `:undeclared-free` on `:yin.ast/code` and accepts any sibling export as the refused name. The test passes independently, but therefore does not pass the stated four-format acceptance gate.

The engineer's explanation in 4.1 is technically sound: every definition application is an application site, while body-read discharge requires a definition to precede every site. The same governing document's section 6 explicitly expects the AST sibling refusal pending L-b. This is a contradiction in the brief, not evidence that the new walk changed dominance or introduced the refusal.

Required disposition: amend section 3.3 to require complete publication, three successful lowered links and the expected AST refusal until L-b. Keep the current refusal regression test under that amendment. Do not change step 5a semantics merely to satisfy the contradictory sentence. An explicit amendment is needed before treating this gate as met.

### F3. P1, pre-existing architecture blocker for P2: large default verifying serves cannot make progress

Location: [attempt budget](../src/cljc/yin/repl/link.cljc#L60), [budget check](../src/cljc/yin/repl/link.cljc#L192), [fresh attempt runtime](../src/cljc/yin/repl/link.cljc#L214).

Independent reproduction used `wide-module 30`, so this defect does not require a prelude-sized image. Publish it, request `:yin.debruijn.code` by name over a local composition, and call `serve` three times with its returned pair. Under `:verifying`, each round reports the same pending request and `:progress? false`. A composition explicitly requesting `:trusted` completes in its first round.

The 64-round budget counts progressing content fetch rounds. A tree requiring more rounds exhausts it despite a responsive local store. Every retry creates fresh state and repeats the initial prefix, so additional serves cannot finish. Raising default parts bounds or removing the discarded scanners does not resolve this limit. Engineer finding 4.2 is confirmed, including its impact on the planned P2 verifying evidence and default large-module requires.

This code and budget predate L-f. Section 3.4 permits only ring-capacity tuning in this slice, which cannot repair a one-request-per-link round cap. Required disposition is a separate authorized liveness remediation, or an explicit amendment to the prerequisites and P2 evidence plan. Do not replace the required verified evidence with a trusted outcome. This finding blocks the P2 claim, rather than establishing a new L-f regression.

### F4. P3, nonblocking: the design text describes a fused walk that the code does not perform

Location: [scanner design text](../docs/design/yin.vm.linker.md#L323), [free-name scanner](../src/cljc/yin/vm/linker.cljc#L391), [shared walk implementation](../src/cljc/yin/vm/linker.cljc#L343).

The statement that all three scanners run "as one direct walk" is inaccurate operationally. Each scanner calls `tree-places` separately, so one scanned verification traverses and materializes the occurrence relation three times. The implementation shares a walker, not one execution of it. Each result is also sorted, so the complete scanner includes sorting cost beyond its linear traversal.

Correct the wording to say that each scanner uses the same direct occurrence walk. No fused scanner or performance redesign is required by this finding; the reported measurements already describe the separate calls.
