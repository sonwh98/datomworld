- (a) A, external case: require parks with one question; append allow;
  one tick completes with one response, no additional question or event.
  Existing a-late-answer-completes-the-require-with-no-typed-line-test
  also passes through the unified tick.
- (b) A, snapshot case: empty decision medium parks; append snapshot;
  one tick answers, then the driver's next round drains and responds.
  Existing an-answer-alone-is-progress-and-the-drive-continues-test
  now calls recheck-on-tick and passes.
- Initial VM run/drain assertions: A and B trace round/drain/live-root-run
  order, exactly one live root run before another round, exactly one
  drain per round. Trace uses ffi/maybe-run rather than redefining a
  protocol function. It excludes the output tokenizer's already halted
  VM run; the pending driver's live root run is the handoff contract.
- (c) B: external refusal, snapshot refusal, external allow/install error,
  and snapshot allow/install error all roll back. Refusals arrive as VM
  link errors. Whole successor equality plus explicit request, answer
  and question cursor, serial and settled-map checks prove state carry.
  Existing an-install-error-keeps-the-admission-it-settled-test also
  preserves serial advancement for the next require (P2-3).
- (d) C: no progress/event runs no VM and leaves :checks unchanged.
- Bound: D injects continuing progress and asserts exactly
  link-round-budget rounds and runs, with :checks still zero.
- Non-DHT sessions: E covers absent/local/remote content sources, no
  admission key/interpreter on creation or successor, and DHT attachment.
- Matched-answer-only progress: F drains an allow while load is pending;
  no response is appended, but progress is true and the answer retained.
  The next unchanged round is idle and preserves the successor.
- P1-2 starvation/gap/no irrelevant-answer checks: existing
  the-host-hook-drains-irrelevant-answers-without-a-re-check-test now
  exercises round, including 64 irrelevant answers followed by allow,
  capacity-4 eviction/recovery, and draining while no run is pending.
- F3/retirement: existing abandonment and late-answer tests pass through
  the one-value retire and unified tick paths, retaining all assertions.
- Layering: yin.vm.linker.layering-test passes. Source/test search finds
  no old hook/key consumers. Admission vocabulary in repl.cljc appears
  only in configuration, option documentation and pending display.

The tick first assocs the successor and node. Only if the resulting
state is value-equal to the original does it reuse the original identity,
retaining existing idle identity assertions without losing any cursor.
