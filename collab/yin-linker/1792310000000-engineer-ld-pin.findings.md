## Representation and implementation

module/link-module stores jing/segment-key of the dependency manifest in
:address, the same representation as :yin.module/requires pins. No
representation conversion was needed. The VM's :modules field holds a
registry, so module/module-entry receives (:modules (:modules vm)), the
registry's inner modules map, as its public docstring requires.

link-install checks every pinned require before lift-slice. The first
mismatch by dependency-name string order calls refuse-install with exactly
:status, :reason, :module, :name, :pinned, :linked. Missing entries carry
:linked nil. Existing export validation keeps precedence. Admission, DHT
source, dependency-bindings, and frontend code are untouched.

## Acceptance mapping

1. dependency-pins-are-checked-without-module-obligations-test, :matching:
   fresh dependency at the pinned manifest address installs; dependent
   publishes its computed n = 7 and the requiring root resumes.
2. Same test, :inherited: root first installs a different dependency,
   child inherits it, refusal names its address; dependent unpublished.
   Existing inherited store snapshots remain exactly unchanged.
3. Same test, :fresh: child installs the different dependency; refusal
   names its address; neither child module reaches the parent registry
   or module stores.
4. Same test, :absent: pinned dependency never linked; :linked nil;
   dependent unpublished and root receives refusal as require error.
5. pin-refusal-restores-every-waiter-and-allows-retry-test: two scheduler
   wait continuations wake with identical refusal; each raises that
   refusal when restored; installs/wait-set empty; next input on the same
   task retries foo successfully with a matching dependency and new ids.
6. :matching and :fresh use quoted-import-module, a hand-built manifest
   and AST fixture, not C3/yang.python. It runs a quoted require followed
   by nested get operations on a synthetic Python module object's dict.
   No dependency-qualified variable occurs. The stub response has no
   obligations, and the backend scanners are checked to retain neither
   bar nor a bar-qualified free name. This isolates the engine guard
   without importing the Python runtime or involving the DHT source.

Additional tests:
- the-first-pin-mismatch-is-in-name-string-order-test: two absent pins,
  inserted z before bar, report bar first.
- a-pin-mismatch-refuses-before-lifting-test: existing portable FaultyTask
  kernel now can fault during child closure lift. Pin refusal wins before
  the lift can throw; nothing is published.

All new acceptance tests are .cljc and use every constructor in the
existing backends harness: semantic-register, stack, register, semantic,
walker (five constructors, including the four established VM families).
The lift-order test uses the existing portable stack-kernel fault harness.
No JVM-only acceptance tests, private-var access, function rebinding,
threads/futures, or new Java interop.
