# Review: jolt host-lane plan r7 (independent, Architect review flavor)

Reviewer: claude-opus-5-5. I did not write the plan. I wrote the r5 review (R1-R10) and one mob position (`1792426582000-architect-jolt-mob-opus…`). I re-checked my own mob claims like anyone else's; one of them was wrong (see W3).

Method: I opened every new r7 citation (§6.2, J6/J8, Q5 to Q7, the defaults) in the repo and the jolt checkout. I ran nothing: no builds or probes. I did not run git in the jolt checkout. The RFC 6455 claims rest on my knowledge of the RFC; I did not fetch it. The only file written is this one.

## Verdict

**APPROVE WITH CHANGES.**

The r5 fixes R1-R10 are all present and consistent. Q7 is applied the same way in §6.1, J0b, J7, the §6 table and the Q7 entry. No WebSocket sidecar text is left except labelled decision history. The milestone labels hold together, and the three defaults are clearly marked as orchestrator proposals.

Two things must change before J6 is commissionable. Neither blocks J0a/J0b/J0c or the local milestone.

- **W1: the native WebSocket seam is under-specified.** The plan names only the per-connection `{:send! :close! :queued-bytes}`. The real host contract also has `{:connect! :bind! :unbind!}`, the adapter entry map, subprotocol negotiation and the listener lifecycle.
- **W2: Transit is missing from the plan.** `dao.stream.ws` and the JVM listener default to the Transit-JSON codec. On jolt the `:clj` arm reaches `cognitect.transit`, which wraps transit-java. My search found no transit-java implementation in jolt. A native WebSocket peer either needs a Transit-JSON port (ClojureDart needed 571 lines) or a CBOR-only composition decision.

Together these mean the plan understates the native WebSocket cost. So did my own mob position (W3).
