## NEW P1-A — jolt_target_run.clj silently swallows all child output

`print` before `System/exit` does not flush in babashka (verified: `bb -e
'(print "x") (System/exit 0)'` prints nothing; with `(flush)` it prints).
jolt_target_run.clj uses `(print out)` / `(print err)` immediately before
`(System/exit exit)` in BOTH modes, so every child's stdout/stderr is lost:

- `bb jolt -e '(+ 1 2)'` → prints header + preflight PASS, exit 0, NO "3".
  The general passthrough task's output contract is broken; callers that
  parse its stdout now get nothing, silently.
- `bb smoke:jolt` → prints only "== jolt-target-run chez --script …",
  exit 0. The six PASS checks, RECORD lines and "SUMMARY ok" are invisible.
  The author's verification (exit codes only) could not catch this — the
  gate still works (assert runs on the captured string) and the exit code
  still propagates, so it is an output-loss regression, not a correctness
  hole in the gate itself.

Fix: `println`/`(flush)` after the prints (or print to an inherited stream).
Affected: jolt_target_run.clj script mode + passthrough mode.

## NEW P1-B — jolt_j0c_stack_child.clj identity snippet inside the ns form

The snippet is placed between the ns name and its :require clause:
`(ns jolt-j0c-stack-child (when-let [t …]) (:require …))`. Babashka rejects
any non-clause form inside ns — verified in isolation: "No matching clause:
when-let", EXIT 1. Every j0c-stack child therefore crashes at load; the
j0c-stack lane cannot run. The other five child scripts place the snippet
after the ns form and are fine. Fix: move the when-let below the ns form.
