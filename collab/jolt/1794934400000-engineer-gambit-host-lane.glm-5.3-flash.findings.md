### Decision: gambit absence is FATAL in bootstrap (not a warning)
Rationale: mise.toml now pins gambit for every host, so `mise install`
provisions it before bootstrap runs (`mise-bin` fails with an explicit remedy
if not). The jolt Gambit gates are part of the lane, and a warning path would
silently emit an unset JOLT_GAMBIT — the exact "reads as green while dead"
mode jolt's GAMBIT-SKIP comment warns about (Makefile ~1694). Requiring it is
the simpler, fail-closed choice and mirrors `check-chez`.

## Mise backend chosen and why
- mise 2026.2.19 has no `gambit` in its registry (verified: `mise registry |
  grep gambit` empty; `mise ls-remote gambit` errors). The inline
  `backend = "asdf:..."` tool key is NOT honored by this mise version
  (verified: `gambit = { version = "4.9.8", backend = "asdf:joeljuca/asdf-gambit" }`
  → "gambit not found in mise tool registry"); the supported forms are the
  full tool id `"asdf:owner/repo" = "version"` or a `[plugins]` declaration.
  The `[plugins]` form was chosen because it keeps the short tool name
  `gambit`, so `mise exec gambit@4.9.8 -- which gsi` resolves as the brief
  requires.
- Chosen backend: **asdf plugin `joeljuca/asdf-gambit` at HEAD
  b8a901e7af845c8b0a0ee1adc5b67687ba4c582b** (the only Gambit asdf/vfox
  plugin that exists — GitHub search; no vfox plugin). It builds from source:
  downloads `github.com/gambit/gambit/archive/v4.9.8.tar.gz` (gambit/gambit is
  the current official repo; gambitscheme/gambit no longer exists), runs
  `./configure --enable-single-host --prefix=<install>` and `make check &&
  make install` with `make -j$(nproc)`. Verified up front that the v4.9.8 tag
  archive ships pre-generated C (lib/_gambit.c, gsc/*.c), so no Gambit
  bootstrap step is needed — matching jolt's CI, which "builds 4.9.8 from
  source" (Makefile GAMBIT_PREFIX comment, tests.yml).
- No prebuilt-binary option exists (the v4.9.8 GitHub release has no assets),
  so a source build was unavoidable.
- Caveat: `[plugins]` must be the LAST table in mise.toml. Placed mid-file it
  broke mise's TOML schema validation of the pre-existing flutter map entry
  (mise: "invalid type: map, expected a string"); moved to the end of the
  file it validates cleanly.
