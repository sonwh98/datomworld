  loads the compiled boot built from committed sources by `host/gambit/build-yin-boot.py`,
  then `host/gambit/yin-repl-driver.ss` boots `jolt.gambit.yin` and calls the real

  (`jolt.ffi/sizeof :int32` — a real FFI call result), `'dao.jing.mem`, the C4 blocking
  message, `43` (proving the session survived the refusal), and `Bye`. Any nonzero process
  status fails (lines 28-31); any unexpected `^yin> ` line sets `unexpected` and fails the

  replies — fails. Exit status alone never passes (line 2).
- Inputs are fed on stdin through `host/gambit/ffi/watchdog.sh` (2400s), which
  preserves stdin, runs in a new session, and SIGKILLs the process group on timeout
  (watchdog.sh:6-13). Watchdogged: yes.
- Negative control exists in the receipts: `build/p1c-r3/yin-gate.log` (status 70,
  "a complete Yin session was not observed") and `build/p1c-r3/yin-current.log`

  design. The committed artifact is deterministic and pinned, so this only means a
  contributor needs a Unicode-16 Python to regen; worth a README line, not a fix gate.

- The "Warning: this round's code is not in the published code index (project failed)"
  class on every round: emitted by upstream Yin (`datomworld/src/cljc/yin/repl/index.cljc:896`)
  because the gate runs `--no-state --index-store mem`, so publication cannot persist and
  the `:project` stage failure is reported each round. The gate's awk deliberately
  consumes only `^yin> ` reply lines, so the warnings cannot mask a wrong reply — they sit
  on their own lines. Acceptable cosmetic degradation of a mem-store run; it would be
  marginally cleaner to pass a flag suppressing index reporting, but it is not a defect
  and does not weaken the gate.
