• # Coverage review: `docs/agents/roles/orchestrator.md`

  1. **[gap] — Workflow / new "Failure and recovery" subsection: delegate-death escalation has no terminal state.** The doc covers retry of quiet delegates, `reassigned`/`superseded` status events, and fresh-session-by-state recovery (via the invocation reference), but never says what happens when a track's delegate has died/failed N times on the same unit — a cold agent will loop forever re-dispatching. Suggested rule: after two failed rounds on the same unit with different sessions/models, stop dispatching, record the failures in the work log, and escalate to the user with the artifact trail rather than routing to a third model.

  2. **[gap] — Authorization and security: no rule for a delegate that requests or emits credentials.** "Never expose or commit tokens" covers the orchestrator's own actions, but nothing covers a delegate that asks for an API key in its brief, prints a token into a `.stdout.log` (which then gets committed as an artifact in step 11), or needs `META_API_KEY`-style env to run. Suggested rule: before archiving, scan artifacts for credential-shaped strings; if a delegate requires credentials, that requirement is escalated to the user, never satisfied by the orchestrator pasting secrets into a prompt file.

  3. **[gap] — Coordination contract: no rollback path for pushed work.** History rewrites are covered only for "local, unpushed, unmerged" commits; once an unauthorized or defective commit is pushed, the doc is silent (revert vs. forward-fix vs. ask the user), and step 10's "a failure means the work is not ready" has no defined next action for the already-pushed case. Suggested rule: a pushed commit that fails verification is reported to the user immediately with the evidence; only the user authorizes a revert or force-push.

  4. **[gap] — Workflow step 7 / Scope of judgment: reviewer–architect disagreement has no termination.** The doc says route design conflicts "back to the Architect or the user," but nothing bounds the loop (reviewer re-disputes the architect's rebuttal, etc.), and nothing defines consensus when the user is unreachable. Suggested rule: one architect adjudication round is final for the current unit; residual disagreement is recorded as an unresolved risk in the step 8 readiness report, not silently dropped and not infinitely re-litigated.

  5. **[gap] — Workflow: no owner-silence / waiting-state rule.** Every escalation path ends at "ask the user," but nothing says what the seat does while awaiting an answer with delegates idle or metered budget burning (the 144-minute idle-session incident in the invocation reference shows this is a real cost). Suggested rule: when blocked on the user, park (don't keep polling) all delegates, record the blocker and pending question in the work log's unfinished-work entry, and end the turn — never leave a delegate session running while awaiting authorization.

  6. **[gap] — Work log / context exhaustion: the budget rule exists but no pre-exhaustion checklist.** The closing paragraph says to record unfinished work "if the remaining budget cannot finish the next coherent unit," but gives no threshold or trigger, and the Seat Handoff Template is never referenced from the budget rule — a cold agent may not connect "budget low" to "use the handoff template now." Suggested rule: name the trigger explicitly — when the seat estimates fewer tokens than one more coherent unit requires, it immediately writes the unfinished-work entry and issues the Seat Handoff Template before attempting further work.

  7. **[ambiguity] — Workflow step 5: "resume an unfinished turn" vs. the append-only artifact protocol's patience rule conflict on timing.** Step 5 says inspect the artifact and resume an unfinished turn, and also "do not terminate a healthy agent merely because it is quiet for several minutes (especially DeepSeek)" — but no timeout, poll interval, or "how quiet is too quiet" bound is given, and the invocation reference's 144-minute-idle incident proves unbounded patience is a real failure mode. Suggested rule: define a decision procedure (e.g. check log growth and `pgrep`; N minutes with neither log growth nor API traffic = stalled, recover per the CLI's quirk entry) rather than leaving "quiet vs. dead" to seat judgment.

  8. **[ambiguity] — Coordination contract / commit authority: "reconciled" findings is undefined as a gate.** Sign-off requires "step 7 review has finished and whose findings are reconciled," but nothing defines what counts as reconciled (all findings fixed? dispositioned? reviewer-confirmed via consensus follow-up?) — and the reviewer's consensus template asks for a ready-to-commit statement, suggesting the reviewer's verdict matters, while the contract makes only the Architect's sign-off authoritative. Suggested rule: define "reconciled" as every finding having a recorded disposition (fixed + reviewer-confirmed, rejected with evidence, or deferred with user approval), and state whether the architect signs off on the reviewer's ready/not-ready verdict or independently.

  9. **[nit] — Artifact protocol: referenced machinery `dispatch.sh` is invoked in the invocation reference's quirks but never introduced to the orchestrator.** The reference says "`dispatch.sh` does not know `kimi`" and its muse case is stale — an orchestrator reading only orchestrator.md has never heard of `dispatch.sh` and doesn't know it exists, where it lives, or that it's partially unreliable. Suggested rule: either link `dispatch.sh` (path, purpose, known-stale cases) from orchestrator.md's Delegate Invocation Reference section, or state explicitly that dispatch is always by direct CLI invocation per the canonical recipes.

  10. **[nit] — Workflow step 11: `src/dev/subsystems.edn` relative link and folder authority are load-bearing but unverified by the doc.** The archive procedure hinges on that registry existing and on `bb test:sub` naming; if the registry lacks a subsystem, the fallback ("name it after the durable track") is discretionary and will drift between seats. Suggested rule: when no registry entry and no existing folder fits, the orchestrator proposes the new folder name in its readiness report for user/architect confirmation rather than creating it unilaterally — folder names are durable and append-only in effect.

  11. **[gap] — Workflow: no cross-seat conflict procedure for the shared main tree.** The doc covers worktree isolation for concurrent editors and ledger row-count checks, but two orchestrator seats working concurrently in the main tree (or a seat plus the user's interactive session) can stage/commit over each other, and nothing assigns ownership of the main tree or a lock/check procedure. Suggested rule: before any step 9 commit in the main tree, re-run `git status`/`git log` against the state derived in step 2; any change not attributable to this seat's units freezes the commit and is escalated, never staged around.

  12. **[ambiguity] — Work log: "Never append to `docs/orchestrator-log.md`" references a file the doc elsewhere treats as historical.** routing-status.md describes itself as "append-only in spirit, like `docs/orchestrator-log.md`," implying that file is a living convention, while orchestrator.md bans appending to it without saying what it is now or whether it should still be read as history. Suggested rule: one sentence stating the status of `docs/orchestrator-log.md` (frozen legacy record, readable as historical claims only) so seats don't either resurrect it or ignore it.
