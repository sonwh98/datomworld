## Per-part implementation

1. **Driver.** `check-common!` accepts nil or positive integer `:fuel`, retained by the constructor and test reopen config. A configured execution uses `(if fuel (sr/run-fuel m0 fuel) (vm/run m0))` under the existing gate/halted guards. Execution, replay, emit and live-read stages return explicit `{:status :ok :state ...}` / `{:status :failed :state ... :failure ...}` outcomes. Each next stage checks tenure against the preceding completed state. The post-cycle drain is similarly guarded. Journal uncertainty and inbox refusal propagate. Failure consumption calls `end-run` with the carried state, preserving the latest completed machine behind `:ended`.
2. **Diagnostics.** Active control reports `:yin.k/at-boundary true`; no automatic hand-off policy was added. `:yin.k/retained-boundary` is inspection-only and records PC, segment, checkpoint and `:yin.k/steps-since-checkpoint`. **Unit clarification:** the latter counts completed holder execution slices/program steps, not guest instructions. The runner exposes no completed-instruction counter; the documents state the actual unit rather than deriving a false count from fuel, especially for early parks and scheduler trees. A throwing, unreturned stage contributes no invented partial machine.
3. **Export/recovery.** Removed `first-refusal`; the root's ordered ready queue moves into the export record and is reinstated for lift/abort. `kind-of` prioritizes running control and recognizes ready-only blocked tasks. Recovery metadata carries/validates ready count, and fenced extraction consumes `:yin.k/recovery-ready` into the retained record. The published pack is reproduced byte for byte. The `abort` function's authority/uncertainty conditions are unchanged.
4. **Custody/composition.** Ledger and grant offerability admit running roots, while halted-root refusal remains. Compose admits/forwards holder `:fuel` and `:yin.k/admitted-modules` (the latter is needed for the composed running-install-child transfer). No execution guard was introduced here; the 6d-a guard is reused and integration-tested.
5. **Documents.** Applied continuation §7.3, UCF exporting/lifecycle/conformance/architectural clauses and linker-DHT §14.1/related handoff text. Replaced Quiesce step 1 with ordered completed-outcome retention. Documents explicitly state last-durable-checkpoint recovery and lost progress. Updated the obsolete UCF child-quiescence paragraph to the already-landed phase/kind rules. Reader documentation and known gaps record arbitrary acknowledgement/backpressure delay.
6. **Stage E.** Added a fuelled running world, source/receiver hand-off, cuts before and after the successor offer, and expiry between slices.
