**Ruling: lower a retained FFI call only when its carried pair can be re-established.** The retry goes to the reflection attached from `:yin.k/request`; its response wait reads the reflection attached from `:yin.k/response` through the carried response cell at its kept cursor. If either endpoint cannot be served at lift or attached at lower, return `:yin.k/unsatisfied` naming that endpoint’s identity. Preserve both route markers and the cell in the UCF entry so a later reachable host can try lowering the same value. Do not retry through the receiver’s handler. UCF requires the carried pair for an outstanding call and reserves the receiver’s fixed pair for future calls ([UCF:565](/Users/sto/workspace/datomworld/docs/design/yin.vm.universal-continuation-format.md:565), [UCF:594](/Users/sto/workspace/datomworld/docs/design/yin.vm.universal-continuation-format.md:594), [UCF:614](/Users/sto/workspace/datomworld/docs/design/yin.vm.universal-continuation-format.md:614)).

Use an allocated private resource key for the request reflection as the retained `:put` entry’s `:stream-id`. Use another allocated key for the response reflection as the response cursor resource’s `:stream-id`; the resulting `:next` entry’s `:cursor-ref :id` is the allocated key for that cell. Its `:stream-id` should name the response reflection as well. The engine resolves writes by the entry’s `:stream-id`, and reads through the cursor resource’s `:stream-id` ([engine.cljc:522](/Users/sto/workspace/datomworld/src/cljc/yin/vm/engine.cljc:522)). The present lower instead selects `vm/call-in-stream-key` ([remote.cljc:607](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:607)).

**Required separate dispatch:** `semantic-restore` currently turns every successful retained request into a wait on `vm/call-out-cursor-key`, regardless of route data on the writer ([semantic.cljc:106](/Users/sto/workspace/datomworld/src/cljc/yin/vm/semantic.cljc:106), [semantic.cljc:132](/Users/sto/workspace/datomworld/src/cljc/yin/vm/semantic.cljc:132)). It must carry the retained writer’s response reflection and cursor keys into the new response wait, while ordinary new calls continue to use the fixed keys. The two slice-8 files can encode and lower those keys, but **cannot deliver correct end-to-end retained-call resume within the stated file boundary**. Do not claim that acceptance gate closed until that semantic change lands.

**Fresh-key rule:** Treat each lowering as a frame batch. Allocate one private resource key per distinct UCF cell ID in that batch and remap every reference to it to that key. Allocate stream reflection keys in the same collision-free batch allocation. A repeated cell ID within the batch shares one cursor resource; equal IDs in separately lowered frames get different keys. Check proposed keys against the receiver’s existing `:resources`, all fixed VM resource keys, and keys already allocated in the batch; regenerate on collision. A prefix or stream identity derived key alone does not establish freshness. The lower API or its composition must receive the occupied key set or a receiver scoped allocator before installation. Current lift restarts IDs at `:yin.k/c-0`, while lower uses the cell ID directly and derives stream keys from identity ([remote.cljc:447](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:447), [remote.cljc:477](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:477), [remote.cljc:522](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:522)); UCF explicitly requires fresh remapping with same-cell sharing ([UCF:934](/Users/sto/workspace/datomworld/docs/design/yin.vm.universal-continuation-format.md:934)).
