## Design defects: discrepancies between plan and code

1. **7a D2 / 7c F3:** plan §1.1's id-counter variant cannot have an equal baseline after changing the root; the baseline includes `:yin.k/root`, so it is `:variant-conflict`. The equal-baseline alternative keeps the root and reverses row order. `decode` admits unsorted packs; one root/one pack holds for sorted `emit`, not every admitted encoding. The documents state code and the owner ruling; the plan is outside this slice's edit scope.
2. **Recovery sketch:** plan §3.2 includes a redundant `:yin.k/descriptors` set and passes `:header` to raw fenced lower. Format 2 has only tag/version, pack address/root/base64 pack, local header and local state. `rehydrate-fenced` checks header/state before `rows/lower-task {:fenced true}`; attached pack descriptors rebuild the retained served table. No second snapshot body or compatibility reader exists.
3. **Custody staging:** plan §3.1 says four stages over the tree. Code runs stores, pendings/install records and dependencies as three passes, then `check-custody!` once for the tree. All precede attachment. Grammar resides in `rows/custody-baseline`; the rows inspector wraps it, avoiding a namespace cycle.
4. **Lift ordering (7a D4):** serve operations happen during the walk before exhaustion/protection/custody refusal. The holder retains successful serves and reuses them on retry; no zero-serve promise was added.
5. **7d source-index seam:** the plan's slice says holder-seams supplies source-index. Code requires a function on `compose/open!` and forbids holder override; compose forwards it to the driver. Trees are associations, not a new identity or resolver. A alone identifies code; source-index/fetch/admission keeps the AST retrievable.
6. **Install verification boundary:** Q3 is implemented through response self-consistency: non-nil parent/link-id equality, manifest-named derivation hash, tree input and image-A output, plus image admission. Code does not add an independent claimed-image-address field check or fetch/admission path; composition-known address binding stays with the linker. The stronger old prose is identified as intended contract and the actual checks are stated.
7. **Retained backends:** old plan/revision rationale said the de Bruijn kernels die at phase 8. The binding owner ruling keeps them as backends, without widening the fragment. `layout/lower-defect` checks image collision, installs, free-env procedures and register payload primitives before attach; it does not implement a universal fragment-membership gate. In particular, retained-FFI row 4 is excluded by the harness, not rejected there before attach. UCF states refuse-the-remainder as the owner's requirement, and continuation §4.6 states this code limit rather than claiming the missing gate exists. 6c Q2 remains open.
