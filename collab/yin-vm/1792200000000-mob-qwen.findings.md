## Q6 — process rule for when to stop reviewing and land

**Ruling:** stop on satisfied gates, not on a round count; out-of-scope findings mean *revert*, not another fix round. The different-family rule is untouched. Concretely (this matches the standing rule proposed in the log at `aac02a7e`, which the owner should confirm):

- **Blocking set:** P0/P1 inside the slice's declared scope, or any P2 that touches a claimed acceptance line or newly introduced public behavior. Everything else is non-blocking.
- **Scope test:** a finding in code the slice should not have written (I3's REPL admission wiring) is a REVERT instruction — fix rounds may not add public entry points, catalog ids, or frontends. This alone would have ended I3 at round 2 instead of round 3.
- **Reviewer prompts quote the slice row, the acceptance bullets, and declared deviations** (as the r3 prompt did), so reviewer scope == slice scope; CPython-parity edges outside the acceptance go to the ledger, not the reject list (I2's `__all__`-generator case was in scope because `from m import *` was claimed; a hypothetical 3.9-vs-3.12 divergence would not be).
- **Known-gaps ledger per track** (gap | evidence | owner seat | closing slice | severity), already instantiated in `docs/orchestrator-log.md`; a landed slice must leave its ledger entry, and a gap with no named closing slice is a blocker.
- **Disputed in-scope P1 after two rounds → third-family Architect ruling**, never a third engineer round; the reviewer is always a different family from the engineer (`docs/agents/team.md`, reviewer-independence rules).
- **Cost discipline:** gate rounds run the quick tier + the mutation reds only; the full slow lanes (JVM ~79 min per `collab/1791590000000-engineer-c4-i3.claude-opus-5-5.stdout.log`) run once, on the final tree, on shiva/jupiter when the owner releases them.

**Risks:** the ledger becomes a landfill (mitigation: every entry needs owner seat + closing slice; the orchestrator reviews it at each handoff); "scope" gets gamed to dodge P1s (mitigation: scope is the slice row as written *before* the fix round, quoted in the prompt). **Would NOT do:** cap rounds numerically; let the same family review its own fix; weaken different-family review to save laptop hours.
