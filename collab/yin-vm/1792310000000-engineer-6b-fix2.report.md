## F7 (High): every store-of names a module store of its own task

`check-dependencies!` (step 9, so before any attach) now builds the census of the task's module-store
rows (slot 7) and collects the non-nil store-of of every `:closure` row (slot 4) and every `:env` row
(slot 1). That covers acts, return frames, waits, parked and reified states, closures nested in values,
and closures inside module stores. It uses `rows-of … own-only? true`, and the staged loop calls it once
per task of the tree. As a result, each install child is judged against **its own** census, and a parent's
or sibling's store with the same key does not count. If any store-of is missing from the census, the
refusal is
`:yin.k/unsatisfied`, `:yin.k/discovery :incomplete`, `:yin.k/missing {:yin.k/stores #{mid …}}`. This
matches the shape of the missing-trees refusal in the same step.

Tests (`every-store-of-names-a-module-store-of-its-own-task`). Each refusal also asserts **0 attaches**:
- codex's recipe: a closure routed to `scoped {ghost 42}` and a stream in the root store. The intact
  carrier attaches once and `(f)` returns 42. After `(assoc-in task [:slots 7] [])` and `rows/emit`, lower
  refuses with `#{scoped}`.
- the same with a **present empty store** `scoped {}` and `(fn [] 7)`. The intact carrier attaches once
  and returns 7. Stripping its rows refuses.
- **frame E**: row 17 (act E routed to host.mod's store) with slot 7 emptied refuses with one missing

  the **child's** slot 7 refuses with `#{scoped}`, even though the parent carries a store with that key.

## F6 (Medium): discharge from each context's resume pc, by control flow

`encloses?` is gone. The new `live-pcs [v at]` is public, because ClojureDart cannot var-quote a
private fn. It is a worklist over `analysis/successors` (§8.1's edges, so a backward jump makes earlier
code live). For every `:closure` it reaches, it also adds that closure's body-pc, because reachable code
can still construct the closure, and the body's nested closures follow transitively. `discharge!` then
checks only the free occurrences whose pc is in `live-pcs` of the context's `(a, at)`. The answering rule
is unchanged: the context's own E, then the one active store, then primitive, installing export,
registry.

Tests (`discharge-follows-control-flow-from-the-resume-pc`):
- codex's `(if false ghost (next! (cursor (stream/make 4))))` lifts. The receiver attaches once, and
  after the source stream is fed 73, **both source and receiver complete with 73**. This holds without
  the unrelated store, with `:module-stores {unrelated {ghost 42}}`, and with `(if false (fn [] ghost) …)`
  (a closure that can no longer be constructed).
- negative: `((fn [p q] 1) (next! …) ghost)` refuses `#{ghost}` (the read comes after the resume pc in
  the same body).
- negative: `((fn [p q] 1) (next! …) (fn [] ghost))` refuses `#{ghost}`. The closure is constructed
  after the resume pc, so its body counts.
- **backward jump**: §3.1 parsing refuses any backward jump (I checked: `code/well-formed?` gives
  `:not-expression-structured` for one), so no carried vector can contain one, and an end-to-end
  transport case cannot be built. Instead the test calls `live-pcs` directly on
  `[[:const 1 false] [:branch-false 1 4] [:var 0 ghost] [:jump 6] [:const 0 1] [:jump 2] [:halt 0]]`.
  From pc 4, pc 2 (`ghost`) is live via the backward `:jump 2`. From pc 3 it is not.

The existing per-context negatives (`free-occurrences-are-answered-in-their-own-context`) all still
pass.

## Worth a reviewer's eye

- **Refusal kind for F7.** I chose `:unsatisfied`/`:incomplete` with `:yin.k/stores`, which matches how
  missing trees are reported. If the Architect's refusal table treats a store-of with no row as a
  malformed carrier, the alternative is `:undecodable`. The change would be one line.
- **`live-pcs` is public** only so the backward-jump property can be tested portably.
- **Context pc semantics.** `at` is the pc the context resumes at (an act's or frame's pc, a closure's
  entry), and it is included in the live set. If some context's `:pc` were ever the pc of an instruction
  that already completed, including it would only make the check stricter, never looser.
- The child's census is its own slot 7. Restore also builds each child's module stores from its own
  rows, so the check and restore agree.
