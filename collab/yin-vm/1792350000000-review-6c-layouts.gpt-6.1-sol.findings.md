# Slice 6c layout review — gpt-6.1-sol

Reviewed branch `srvm-phase6c`, HEAD `47ddb1d9`, `git diff master...HEAD`, against the current continuation design §§4, 5.5, 5.6, 8.3 and the engineer report. This is an independent review with independently applied mutants. No production or test changes are proposed in this worktree; only this findings file remains from the review.

**The JVM suites pass, but the slice is not ready to merge.** Free-environment values bypass conversion, legitimate alpha-distinct source segments lose their identity at native-image lookup, the acceptance matrix is reduced without an approved design amendment, and law 4 lacks decisive negative controls.

The present position normalizer retains nonidentity data, but the suite does not protect that property; descriptor erasure is already part of `canonical-under`'s specified behavior and must be guarded by a separate equivalence assertion or revised normalization contract.

## Static and task-level assessment

**Register pairing and live sets:** `register-pairs` aligns destination/uses with opcode operand order; `phys-maps` is body-scoped and first-wins, with the corpus testing every pair for agreement. At reachable boundary pcs the inverse over actual successor liveness is checked, with subtraction of virtual `rd` before mapping. Tail boundaries have no successors and `[]`. Top and each K frame recover `rd` independently from A, not the physical destination. Baseline implementation is correct on these checks. The unique-dead-preimage fallback is defensible for diagnosing tampered windows, provided its domain and ambiguity refusal become normative and receive negative tests.

**Stack:** non-push H/A correspondence, ancestor operand ordering, saved-set equality at non-tail parking instructions, `[previous-base, base)` slicing and cumulative-including lowering agree with current §4.3. The fixture pins `[0 0 0 2 4]`, six operands and five K frames. The before-slice rule is wrong and independently killed. Tail lift discards the current window/E; lower fills `[]`/nil, and both tested tail rows continue identically with junk fills.

**Environments and closures:** chain order, rightmost-wins duplicate params, nil-fill and shadowing agree with §4.4. The positional `[1 2] → canonical → [2 2]` duplicate-binder outcome is permitted: the law is canonical equality, not hidden positional-state equality. Closure arity/binders/entry and captured lexical frames are reconstructed from A and tested. **F1 limits this positive result:** the task's free environment is raw in the conversion contexts, so closures or captures inside that environment do not share the same value conversion as stores, windows and lexical frames.

**Tasks and refusals:** `canonical-task` checks active control, refuses install children, carries resources/counters/waits/parked records and feeds the ordinary row carrier. `kernel-task` derives/attaches A's images and converts stores, parked records and waits. `lower-task` runs `lower-defect` before `rows/lower-task`, therefore before any stream attachment; M8 proves the current refusal test detects reversal. Install-child lower refusal is present, but there is no dedicated before-attach install refusal assertion in the new test. `:continuation-registers` scans primitives through wait/parked state windows, lexical bindings, guest collections, closure lexical captures and reified states. It intentionally excludes the free part of E because the kernel's free environment can hold primitives. This is a state-payload restriction, not a ban on all `:prim` rows.

**Law 4/5 honesty:** baseline `machine` genuinely dispatches to three kernels, and `load-program` derives H/R for native lanes. It does not simply feed all lanes the reference VM. `crossed` explicitly asserts the receiving engine, and law 5's counts kill a skipped pair. In law 4, `apply =` over a singleton returns true; fixture-case counts do not establish lane coverage. Logical stream names come from resource keys rather than host traversal order; this is reasonable for these fixtures, but correspondence injectivity and stream/descriptor/position coherence need explicit controls. The broad descriptor erasure is design-sanctioned and cannot establish equality of arbitrary carrier states.

## Deviations and D1–D5: Architect rulings and exact amendments

API names and the scratch semantic-register restore composition (deviations 1 and 2) are acceptable implementation choices: the required algorithms exist and reuse carrier validation. The reduced corpus avoiding ANTLR, safepoint-producing variants, and visible duplicate-binder round trips (5 and 6) are reasonable and disclosed. The fallback and primitive restriction (7 and 8) need the normative wording below. Exclusions (3 and 4) describe real limitations but do not fulfill the current acceptance contract.

**D1 — ACCEPT WITH CHANGES.** Ringbuffer positions contain identity; the design's claim that marker substitution removes every lane identity is false. The current narrowly targeted rewrite is reasonable, but its protection against erasing state is untested. Replace §5.5's claim that all remaining procedure inputs are identity-free with:

> A cursor position may contain a stream identity. The fixture supplies an explicit, injective logical-stream correspondence and a transport-specific position renaming operation. That operation replaces only identity-bearing fields, preserves every nonidentity field including offsets, and rejects missing coverage or disagreement with the cursor body's stream. Stream descriptors must be shown equivalent under the same correspondence before comparison; replacing a whole descriptor with a logical name alone does not prove equivalence. After these checks, canonical-under re-emits and renumbers the task. The harness includes negative controls proving that a changed position offset, descriptor nonidentity field, saved value or lexical value changes the compared state, and asserts exactly the three distinct kernel lanes for every law-4 case.

**D2 — ACCEPT; MUST RESOLVE THE GATE.** The kernel re-park selects its own response pair. Insert in §4's required native-kernel seams:

> On completion of a retained FFI request, each de Bruijn kernel preserves the carried response cursor and response stream when constructing the response wait. If both are present, response-wait-entry is overridden with cursor-ref {:type :cursor-ref :id response-cursor} and stream-id response-stream. A partial carried pair is rejected; the kernel's composition-owned response pair is used only for entries that carry neither field. Response decoding precedes delivery, including tail delivery. Row 4 must continue on all six ordered engine pairs with the receiving composition's call pair distinct from the source's pair. This seam is a prerequisite of 6c acceptance, like the stack tail-completion seam.

The non-editable-kernel scope makes this a prerequisite/Architect decision, not a reason to silently count four missing transfers as passing. For link/install rows, the Architect must separately provide A-to-native module response adaptation and recursive install-task layouts or explicitly narrow §§5.1/5.4/5.6(8)/8.3(9–11). The current gate remains incomplete pending that decision.

**D3 — ACCEPT WITH CHANGES.** Keep the restricted inverse for valid states, but define diagnostics outside its domain. Append to §4.2:

> At a reachable boundary, virt first considers preimages in live-out*. Exactly one is returned. If there are none, it may return the body's sole named virtual preimage, solely to reconstruct a tampered window for validation. Zero or multiple such preimages, or multiple live preimages, are refused as :yin.k/non-portable :register-layout; no enumeration order selects a preimage. The harness checks an ambiguous dead physical slot is refused, a unique dead slot yields :window-extra through the frame validator, and a missing live slot yields :window-missing.

An ambiguous tamper cannot honestly be promised the `:window-extra` kind; amend §8.3(12) to permit this explicit layout refusal in that case.

**D4 — ACCEPT WITH CHANGES.** Primitives are legal carrier values; the limitation belongs to the receiving native kernel. Replace §8.3(6)'s phrase “a primitive … is no carrier value” and add to §§4.2/7.2:

> A primitive function is an admitted carrier value (:prim). The current de Bruijn register kernel cannot restore a primitive function reachable through its saved register or lexical-frame payload, including nested guest collections, closure captures and reified continuation state. Lowering a task with such a wait or parked-state payload into that kernel refuses :yin.k/unsupported :continuation-registers, with the payload path, before stream attachment. This restriction does not prohibit primitives in the task-wide free environment or in carrier values a kernel can otherwise hold. Cross-engine acceptance explicitly records unsupported payload cases; expanding this receiver domain requires a separate kernel seam.

The present negative case demonstrates a primitive in a window. Add distinct lexical/captured/nested-value refusal fixtures; do not equate those untested paths with full mutation coverage.

**D5 — ACCEPT.** Row 21 captures the innermost wrapper's `x`, not a symbol insulated from the wrapper. Add to §5.2 row 21's expectation:

> Under :depth-3, the closure captures the innermost wrapper binding x = 1; the task's free-env retains x = 99. The blocked read's E therefore binds x to 1, and all three lanes agree on that lexical result. The bare row tests the free binding 99. This wrapper-induced lexical capture is intentional and is pinned separately from free-environment preservation.

No production patch is needed for D5; the existing `env-reconstruction` test already pins read E = 1 and free-env = 99.

**Additional necessary identity amendment (F2), §4.1/6.1:**

> A is the code identity even when distinct A derive identical H or R. Native-image hashes remain checksums and must not select a source segment. The composition retains the A provenance of every current activation, return frame and closure through native attach and restore, permitting several A to share an image without conflation. Until the requisite provenance seam exists, a receiver preflights image collisions before stream attachment and reports the unsupported provenance case; this temporary refusal does not satisfy the full canonical round-trip gate for legitimate multi-A programs.

## Portability

Static review found no newly introduced `for` over long row sequences, private-var test access, multi-key `assoc` starting from nil, or unary-minus float use. Maps with multiple keys start from `{}` or known maps; pc arithmetic uses integer additions/subtraction. Catch branches include `:cljd Object` first. `satisfies?` is used for protocol dispatch and descriptor checks; `binding` wraps synchronous fixture construction; `memoize` caches the pure static segment derivation.

The **pinned** ClojureDart source (`sonwh98/clojuredart`, SHA `7d00ee2aa7fa9d990581e78ebc4a66b93cb70a31`) implements `satisfies?` (`core.cljd:513`), `memoize` (`:6809`) and `binding` (`:7623`, using Dart zones). Thus their mere presence is not a demonstrated Dart incompatibility. These are also ordinary supported ClojureScript forms. This source check is not a Node/Dart compilation or runtime result. Acceptance 13 and the phase-7 entry gate still require their prescribed host verification.
