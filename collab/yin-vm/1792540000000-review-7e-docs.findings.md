## Verified true (no action)

- Fork custody is nil on every row. `header-custody` with `custody-keys` gives the five-key slot by kind. A halted root takes origin only, and a header-bearing halt without origin refuses `:missing-header`. Children must be nil (`:child-header`) and are checked in the root's context (`task-ops`). These match continuation §2.5/§2.6, tuples §5.5 and UCF §7.7.4.
- Lift order (continuation §7.1 step 10, tuples §9, UCF §7.7.4):
  1. `lift-task*`, with `validate-frames`.
  2. Exhaustion at `max-exact` (2^52-1) on non-halted roots.
  3. `protect!` (`:unprotected-pending` / `:yin.k/unsatisfied`).
  4. The slot is written.
  5. `custody-baseline`.
  6. `emit`.

  `pack` sorts rows by `(str id)`.
- `pack-address` is `jing/segment-key` of the wire (BLAKE3 by default), which is different from `:yin.k/root`. The baseline carries `:yin.k/root` (`inspect-pack`). The grant `:checkpoint` is compared to `pack-address` (`accept-grant!`). The offer `:yin.k/id` is the pack address.
- Lower has three per-tree stages (`check-stores!`, `check-pendings!`, `check-dependencies!`), then `check-custody!` runs once, then `attach-streams!`. The custody table row matches `accept-grant!`'s checks and refusal statuses. `:fenced` skips `accept-grant!` (protection included), but the grammar and the `:exclusive` fork refusal still run.
- `check-install!` checks: non-nil parent = `:yin.link/id` (`:install-link-id`); derivation `segment-key` = manifest `[:yin.module/derivations :yin.semantic/code]`; input = `:yin.module/tree`; output = `segment-key` of `(:value image)` (`:install-image`). The docs' "self-consistency, no independent claimed-image-address check" framing is accurate.
- Fenced restore: every task is gated `:exporting`; waits go to `:yin.k/recovery-waits` and parked records to `:yin.k/recovery-parked`; the id counter is exact; `:yin.k/recovery-cell-ids` is set. `spawn-child` nils `:make-stream` and then restores it. Ordinary resume uses `max(local, carried)`.
- Recovery format 2 keys exactly match `freeze`: tag, version 2, pack-address, root, pack-bytes base64, header, and state `{:gate :origins :issued :issues :children}`.
- `rehydrate-fenced` checks the following before lower: tag/version, recovery address, inspector, root, header-agrees, valid-state. It then requires byte-identical re-encode and marks `:recovered?`. `abort` refuses `:restarted`, and custody is dissoc'd.
- Driver order is recovery object, then pack, then the `:yin.k/fenced` journal record (`export-fence-step`). That matches tuples §7's "after recovery format 2 and before journaling the fence".
- Source index is checked as a fn on `compose/open!`. It is a composition seam that `holder-config-keys` refuses. It is forwarded by `driver-config` and read by the driver. `export-version` appears nowhere in `src/`.
- The three owner-approved UCF §7.11 edits are present:

  - "the canonical kernel and its two backends" (UCF:3071).
  - The pointer to continuation §4.6, which exists at continuation:991.
