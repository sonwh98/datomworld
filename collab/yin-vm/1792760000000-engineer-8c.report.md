## Implementation

- Production publisher, ledger verification, linker re-lowering and REPL loaders use the v4 projection and A-derived H/R lowerings. The backend kernels remain. No old lowerer or old kernel was deleted.
- The single semantic format record uses `:yin.semantic/code`, contract `"v4"`, and the new validators/scanners. The serving composition has six records. All semantic-register producers and the rows lowerer use the new keyword.
- Publishing retains and materializes the AST, explicitly validates/materializes A's exact vector through `semantic-register.code/materialize-vector!`, derives the native images from that vector, and stores `tree -> A`, `A -> H`, `A -> R` records. Native format index entries are `{format storage-address}`; old checksum keys are refused at manifest admission. Schema/profile revisions were not bumped. Native `:identities` now return A; H/R are separately returned as `:checksums`.
- Manifest linking requests native bytes by A using the existing stepped fetch pipeline and a link-local format/index interpretation. The record's H/R output checks the selected bytes; it is not the native request name. Verifying a native link also fetches and verifies the semantic `tree -> A` leg, so a forged semantic record cannot rename otherwise-correct native bytes. A new test covers that chain.
- Pairing verification projects source datoms to the v4 vector and derives both checksums. The old `relowered-hashes` helper is replaced by `derived-checksums`.
- Tests that exercise the production semantic format now construct v4 vectors and use the semantic-register VM. The Dart transfer peer and its JVM fixture now transfer through a manifest, identify the code by A, and check native checksums through the linker.
- Four pre-existing kondo warnings in the changed `vm.cljc` were removed: one unused private helper and three unused local names. No validator behavior changed in that cleanup.
