                                 :pc (:pc entry)

                                 :continuation (:continuation entry)
                                 :store-of (:store-of entry)

### 2. Continuation Correctness

- **Multi-shot `:current-continuation`, tail-call `K`, and abortive invocation**:
  - Because every guest `:call` saves an immutable sparse return frame in `K` and returns `TRANSFER` to the host trampoline before the callee body runs (§2.1, [`findings.md:70-71`](file:///Users/sto/workspace/datomworld/collab/1792329904305-architect-register-wasm-lower-plan.gpt-6-astra.findings.md#L70-L71)), the native wasm stack has depth 1 during body execution and depth 0 at every trampoline boundary.
  - Multi-shot `:current-continuation` works without native stack copying because `:frames`, `:regs`, and `:continuation` in the captured payload are immutable records; invoking a reified continuation multiple times via `:call` (`:continuation` arm, [`register.cljc:729-733`](file:///Users/sto/workspace/datomworld/src/cljc/yin/vm/debruijn/register.cljc#L729-L733)) abortively replaces `:pc`, `:frames`, `:registers`, `:continuation`, and `:store-of` from the capture without mutating the captured payload.
  - Note on `:call` of `:continuation` ([`findings.md:95, 151`](file:///Users/sto/workspace/datomworld/collab/1792329904305-architect-register-wasm-lower-plan.gpt-6-astra.findings.md#L95)): In [`register.cljc:676, 729-733`](file:///Users/sto/workspace/datomworld/src/cljc/yin/vm/debruijn/register.cljc#L676), ownership is checked inside `engine/operator-kind` ([`engine.cljc:691-708`](file:///Users/sto/workspace/datomworld/src/cljc/yin/vm/engine.cljc#L691-L708)) *before* `engine/continuation-argument` validates the 1-arg arity (`:continuation-arity`). The plan should preserve that exact check order (`engine/operator-kind` before `engine/continuation-argument`) so an unowned continuation called with wrong arity raises `:foreign-continuation`, not `:continuation-arity`.
- **Linker §7.3 r6 image membership vs layout equivalence**:
  - Correctly analyzed in §3.2 ([`findings.md:142`](file:///Users/sto/workspace/datomworld/collab/1792329904305-architect-register-wasm-lower-plan.gpt-6-astra.findings.md#L142)), §3.3 ([`findings.md:157`](file:///Users/sto/workspace/datomworld/collab/1792329904305-architect-register-wasm-lower-plan.gpt-6-astra.findings.md#L157)), and §7 item 2 ([`findings.md:258`](file:///Users/sto/workspace/datomworld/collab/1792329904305-architect-register-wasm-lower-plan.gpt-6-astra.findings.md#L258)).

### 3. Invariant Audit (`docs/design/datom.world.md`)

- **No hidden global state**: Satisfied. Value arenas and linear memories are task-owned and explicitly passed (§1.1–1.2); `id-counter` is the task's counter; module registries and primitive tables remain values in VM state.
- **No implicit control flow / no callbacks**: Satisfied. No JS Promises, Asyncify, or browser event callbacks resume a retained wasm activation (§2.1, §4.1). Blocking returns `BLOCKED` to the scheduler.
- **No shared mutable state**: Satisfied in principle (§1.2–1.3, §7 item 4), subject to fixing the bidirectional Clojure-map/linear-memory synchronization noted in Finding 2 above so stepping or mutating an old VM snapshot never aliases another snapshot's active register shadow.
- **No layer collapsing**: Satisfied. Interpretation/admission (`register-image-defect`, `body-liveness`, `A → R` derivation) remains separate from wasm code generation and execution.
- **No assumed graphs**: Satisfied. CFG construction uses validated instruction tuples and explicit body bounds (§2.2).
- **Unitarity (A is the only code identity; AST retrievability)**: Satisfied. Wasm binaries have no code identity, are never published to `dao.jing` or indexed as a format identity, and are cached only as disposable local execution artifacts keyed by `(A, R, abi-version, features)` (§Decision, §5, §7 item 9).
