## Per-item changes

### 1. Init-time raise (prelude.cljc run-main, php/raise)
- Request binding moved inside the root protected region: run-main installs
  the fatal/exit escapes first, then binds the request inside the body
  `php/try`, before the body. An init-time throw-error is now delivered to
  that handler and ends as the ordinary `:php/uncaught` snapshot rendered
  "PHP Fatal error: Uncaught ..."; never an array key or Error-valued data.
- The empty-stack branch of `php/raise` is now `php/invariant-violation`, a
  defect-loud host-level failure (a deliberately arity-wrong `cell/new`
  through `php/missing-invariant-trap`); it does NOT call `php/root-fatal`
  (which would recurse through `php/raise` with no escape installed).

### 2. Invalid trigger_error levels are ValueError (prelude.cljc, programs_p5b2)

  `ValueError("trigger_error(): Argument #2 ($error_level) must be one of
  E_USER_ERROR, E_USER_WARNING, E_USER_NOTICE, or E_USER_DEPRECATED")`
  for anything outside 256/512/1024/16384 (PHP 8.3); uncaught it is the
  ordinary snapshot. No `E_WARNING`/false.
- Fixture `:trigger-invalid-level-rejected` replaced by
  `:trigger-invalid-level-throws-value-error` (uncaught ValueError) plus a
  caught case `:trigger-invalid-level-caught`.

### 3. :linked accepts requests (lower.cljc, linked_harness, test)

### 5. E_USER_ERROR default fatal (prelude.cljc, programs_p5b2)

  terminal `:guest-fatal`), NOT the operational termination: it escapes the
  body past handlers/finally, while run-main still runs shutdown functions,
  drains buffers and marks objects destructed on the way out, then answers
  `:php/fatal`. Shutdown-phase guest-fatals route through the shutdown
  escape the same way.
- Tests: shutdown output, buffered output, handled continuation,
  false-returning fallback.

### 6. Stream lifecycle (closed at the composition level)
- New `portable-harness/run-lifecycle-raw` (shared JVM/Node/Dart lane):
  the request record is appended to a composition-supplied request stream
  (the composition's own ring-buffer constructor) and consumed back from it
  via oldest-cursor/next; the consumed record rides the production channel
  as `run-main`'s second operand; every response and diagnostic record is
  emitted on composition-supplied response/diagnostics streams and drained
  back. Returns the drained `{:response [...] :diag [...]}` alongside the
  task value.
- `lower-through-stage` / `run-packet-raw` accept an optional request, so
  the portable lane can carry requests at all (previously request-less).
- New `stream-lifecycle-consumes-and-emits-over-streams-test`: superglobal
  seeding from the consumed record, diagnostic emission (`E_USER_NOTICE`
  `boom`), header-then-body emission order, nil-request defaults, drained
  streams equal to the task value's `:php/response`/`:php/diag`, and
  cross-harness `run-raw` output agreement.
- Record transport over the link (`:link-request`/`:link-response`) streams
  is NOT re-architected: the guest still answers its value map and the host
  emits the records. Guest-level stream effects would need engine support
  (prelude sexps cannot express `:stream/put` nodes).
