## Per-item changes

### 1. Request binding into the composition-supplied stream lifecycle

- `php/run-main` now takes a second operand, the request record, and calls
  `php/bind-request!` at initialization (nil / `:php/null` keeps the empty
  defaults). Missing-arg callers are safe: under-arity params bind nil
  (yin/vm/engine.cljc `bind-params`). Output, response and diagnostic
  records remain the task's emissions answered by `run-main`.
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc)
- `lower/lower-program` accepts `:request` and emits it as `run-main`'s
  second operand (`:php/null` when absent); `:request` added to
  `option-keys` so it flows through lowering-stage state.
  [lower.cljc](src/cljc/yang/php/antlr/lower.cljc)
- `e2e-harness/lower-program` accepts an optional request and passes it as
  a stage option; `run-raw` no longer postwalks any bind call — the
  test-local `bind-request!` injection is deleted (unused `clojure.walk` /
  `yang.core.uast` requires removed).
  [e2e_harness.clj](test/yang/php/antlr/e2e_harness.clj)

### 2. `$_REQUEST` recursive merge

- New `php/request-merge-into` / `php/request-merge-keys`: string keys
  overwrite in order (GET-then-POST pinned), integer keys append, nested
  arrays merge recursively. `php/bind-request!` uses it instead of
  `php/merge-loop` (`array_merge` semantics).
- New `php/request-ensure-next` (+ `php/request-max-key`): stream-supplied
  tables may carry no `:next-index` (only guest writes maintain it via
  `bump-next`); the merge seeds it from the highest integer key so appends
  land past occupied slots instead of tripping the occupancy error.
  Without this, `append-key` throws "Cannot add element..." — and since
  `php/raise` with an empty handler stack *answers* the error as a value,
  the Error object was planted as an array key (observed via
  `array_keys`: `[0, 1, Error#1]`). Worth an architect look: `raise`
  answering instead of raising when no handler frame exists makes every
  init-time throw-error a silent value (see Escalations).
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc)

### 3. Header/cookie/status semantics

- `http_response_code(x)` now answers the *previous* status (was: `true`);
  no-arg form still answers current; refused-after-output still `false`.
- `header()` honors the replace flag and the status argument (sets the
  response code + status emission); still answers null.
- `setcookie()` retains expiration/path/domain/secure/httponly/samesite on
  the cookie record (`:options` map), both positional and options-array
  forms; options-array includes only supplied keys.
- Existing `:headers-cookies-status` fixture updated: cookie record gains
  `:options {}` (bare setcookie call).
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc),
  [programs_p5.cljc](test/yang/php/antlr/programs_p5.cljc)

### 4. Error triggering

- `trigger_error`/`user_error` accept only 256/512/1024/16384; anything
  else warns `E_WARNING "trigger_error(): Invalid error level"` and
  answers false.
- Unhandled `E_USER_ERROR` runs the handler path, then ends the run
  through the terminal `php/root-fatal` escape (fatal, no `echo 'C'`).
- `set_error_handler` saves/restores callback AND mask (new
  `php.rt/error-mask` current + `php.rt/error-masks` stack cells,
  registered in `init-form` and `runtime-keys`); null callback resets to
  the default sink; mask defaults to `E_ALL`. `php/warn` consults the
  mask before invoking the handler (sink still governed by
  `error_reporting`).
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc)
