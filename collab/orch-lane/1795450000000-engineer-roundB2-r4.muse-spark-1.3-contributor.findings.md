# Round B2-r4 findings — the three architect-confirmed residuals

Branch: `feat/p5b2-lifecycle`. All three defects fixed, gates green, committed
without push.

## 1. Request-in-UAST (portable_harness.cljc:157)

Cause: `run-lifecycle-raw` consumed the request from the composition stream
(`consume-one`), then composed the consumed record into the program via
`operand-node` → `sexp->uast` — the entire request rode to the runtime as a
`:literal` operand. Lowering never saw the data, but the compiled UAST did.

Fix (harness/runtime split, `test/yang/php/antlr/portable_harness.cljc`):

- `attach-request-stream` appends the request to its own ring-buffer stream
  and attaches the handle under the VM capability secret; only the sealed
  reference is composed (`request-node` is now ref-or-nil).
- `run-lifecycle-raw` and `run-packet-raw` both route through the attached
  stream; `consume-one` is gone (nothing consumes before execution any more).
- `lower-through-stage`'s `request` parameter is now the attached reference.
- `lower.cljc` `option-keys` / `lower-program` docstrings updated to the new
  split. `e2e-harness` / `linked-harness` record-operand paths untouched
  (outside the cited defect; no consume-before-execution there).

Runtime (`src/cljc/yang/php/antlr/prelude.cljc`): new `php/resolve-request`
resolves the second operand inside `run-main` — a `:stream-ref` map is
consumed at runtime (`stream/cursor` + one `stream/poll!`, empty stream
keeps the empty defaults); records, nil and `:php/null` behave as before.

Regression (`request-never-enters-compiled-uast-test` in
`test/yang/php/antlr/p5b2_lifecycle_test.clj`): the composed second operand
is exactly the opaque reference; a postwalk over the lowered AST finds no
node carrying `:php.request/*` keys; the lifecycle run still seeds
`$_GET` from the stream.

## 2. Cookie validation ordering (prelude.cljc `php/bi-setcookie`)

Cause: the headers-sent refusal ran first, so after `echo` an excess-arity
call or an unknown/numeric option key warned-and-skipped (`false`) instead
of throwing.

Fix: validate first (arity, then option-array coercion which raises
`ValueError`), then the headers refusal, then emit. Valid-after-output
still warns and answers `false`; only the invalid cases changed outcome.

Regression (`setcookie-validates-before-headers-sent-test`): excess
positional args throw `ArgumentCountError` after output; unknown option
throws `ValueError` after output; valid call after output still yields
`xbool(false)` with the `[[2 "Cannot modify header information - headers
already sent"]]` diagnostic.

## 3. Oracle single-slot fatal diagnostic (oracle.clj:139)

Cause: `parse-stdout` recorded a plain fatal only in `:fatal`, leaving
`:diag` empty where the maintained P5b2 fixtures expect `[[256 "boom"]]`.

Fix: when a plain fatal parses, its E_USER_ERROR-class diagnostic
`[256 fatal-message]` is carried in `:diag` (chronological tail position).
`check-p5b2-fixture`'s `diag-match?` then agrees with the fixture shape.

Collateral: `src/dev/yang/php/oracle_test.clj` was stale on the base tree
(3 pre-existing failures verified via `git stash`: plain fatal expected as
`uncaught Error`, and expected maps missing the `:fatal` slot introduced
with the guest-fatal representation). Updated to the maintained contract —
single-slot `:fatal`, `:uncaught nil` — plus an explicit
`[[256 "boom"]]` assertion as the regression.
