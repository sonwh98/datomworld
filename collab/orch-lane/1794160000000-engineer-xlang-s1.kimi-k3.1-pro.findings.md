## What was wrong and changed

- `php/global-peek` was the wrong export path for these cases. A PHP arrow function assigned to `$phpfn` is a PersistentArrayMap Closure descriptor, not the inner function cell. TypeScript can reject that descriptor as a non-function, and logging it can fall into number rendering. `php/callable-fn` intentionally preserves an already-eligible descriptor, so it does not solve the identity requirement.
- The PHP donors now use ordinary named functions and exports use `php/resolve-fn`, exactly as the existing `source-call-test` composition does. This preserves the donor's function cell identity without call-node rewriting, foreign `:code` extraction, or a language-pair wrapper.
- Each export is explicitly bound by a UAST `let` in the caller task before projection. No cell is carried as a host value between tasks.
- Documentation now names PHP's global function table rather than `$GLOBALS` for the export source.
