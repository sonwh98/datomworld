### 1. Guest-fatal destructor suppression (prelude.cljc guest-fatal, run-main)

- `php/guest-fatal` now sets `php.rt/exit-status` to 255 and calls
  `php/freeze-finalizable` over the finalizable list BEFORE escaping
  through the exit/shutdown continuation. Marking every existing object
  destructed first means the ordinary shutdown that still runs (shutdown
  functions, global/static release, buffer drain) destroys without
  running destructors — `php/destroy-obj` and `php/shutdown-finalizable`
  both skip destructed objects — while shutdown-function and buffer
  output still flow. Probe shape: buffer + shutdown echo, destructor
  silent ("BS", never "BSD").
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc)
- `php/run-main` pins the fatal status 255 when the run ends guest-fatal
  through the shutdown continuation (which never passed the
  exit-status cell): `st` falls back to 255 whenever the body or the
  shutdown terminal is `:guest-fatal`. The body-fatal path already
  carries 255 via the cell; `php/handle-uncaught` with a null exception
  is identity, so skipping it on the now-non-null status changes
  nothing.
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc)
- Fixtures: all four guest-fatal fixtures now pin `:status 255`, plus a
  new `:trigger-user-error-suppresses-destructors` fixture (live object
  with `__destruct`, shutdown function, plain echo: out `BS`, fatal
  `boom`, diag `[[256 boom]]`, status 255).
  [programs_p5b2.cljc](test/yang/php/antlr/programs_p5b2.cljc)

### 2. Stream P2 (lower.cljc, e2e/portable/linked harnesses, prelude.cljc)

- `lower/option-keys` drops `:request` and `lower/lower-program` drops the
  request operand data: it takes an opaque `:request-node` (a UAST node,
  defaulting to the `:php/null` literal) and splices it as `run-main`'s
  second operand. Lowering performs no `sexp->uast` conversion of request
  data anymore — a `lower-program` call never embeds a request record,
  with or without options.
  [lower.cljc](src/cljc/yang/php/antlr/lower.cljc)
- Each harness composes the operand at the composition level from the
  stream-consumed record: new `request-node` helpers in
  [e2e_harness.clj](test/yang/php/antlr/e2e_harness.clj) and
  [portable_harness.cljc](test/yang/php/antlr/portable_harness.cljc)
  (`u/sexp->uast` of the record, converted harness-side); the lowering
  stage only ever sees the opaque `:request-node`.
  [linked_harness.cljc](test/yang/php/antlr/linked_harness.cljc)
  converts its `:request` opt the same way. `lower-through-stage` with a
  request still consumes from the request stream BEFORE lowering, and
  `run-lifecycle-raw` still returns the drained composition-supplied
  response/diagnostic streams alongside the task value.
- Header replacement is now interpreted from the appended commands, not
  by deleting earlier records: `php/emit-header!` is append-only (every
  emission is a `{header line :replace bool}` command) and the new
  `php/response-view` fold applies replace semantics (case-insensitive
  field-name match, status/cookie records pass through in order) at read
  time in `run-main`'s result. Observable `:php/response` values are
  unchanged (verified identical by the header fixtures).
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc)
- Response and diagnostic emission happen DURING VM execution on the
  composition-supplied streams: `run-lifecycle-raw` attaches both
  stream handles to the walker VM
  (`engine/attach-resource`, sealed under the task secret) and passes
  the sealed references as `run-main`'s third and fourth operands
  (`:response-node`/`:diag-node`, opaque like `:request-node`);
  `php/emit-response!` and `php/warn-sink` `stream/put!` onto them
  during the run, and the runtime no longer appends to `php.rt/response`
  / `php.rt/diag` cells on this path. The `stream` module is registered
  in both portable registries and `stream/put! stream/cursor
  stream/poll!` join `host-names` (the `prelude-reaches-no-dao-host`
  contract now admits the `stream` namespace). `run-main`'s result
  drains each stream (fresh oldest cursor + `poll!` loop) and folds the
  records through `php/response-view`; the body record is appended to
  the stream before the read. The post-completion `emit-all!` copy is
  deleted — with it gone and the gates still green, the records
  provably arrived via in-VM `put!` during execution.
  [prelude.cljc](src/cljc/yang/php/antlr/prelude.cljc)
  [portable_harness.cljc](test/yang/php/antlr/portable_harness.cljc)
  [lower.cljc](src/cljc/yang/php/antlr/lower.cljc)
- Compositions without streams are unchanged: e2e `run-raw`, linked runs
  and `prelude-test` pass two operands (missing operands bind nil,
  normalized to `:php/null`), so `php.rt/response-stream` /
  `php.rt/diag-stream` stay null and the cells accumulate exactly as
  before — `request-context` (which asserts `:response` on the
  stream-less `run-raw`) is untouched. New maintained test
  `:lowering-splices-stream-operands-test` pins the 4-operand splice
  shape and the 2-operand default.
