# Findings — Round B1-r2 residuals (engineer)

Branch: `feat/roundB1-p9-contracts`. All six architect residuals fixed in
the prelude sources, each with a regression in
`test/yang/php/antlr/builtin_surfaces_test.clj`.

## 1. P1 — json_encode nested failure (fixed)

Root cause: `php/json-encode` concatenated `"["`/`"{"` onto the result of
`php/json-array-values`/`php/json-array-pairs` unconditionally. A failed
child (e.g. `INF`) answers `false`, and the host string primitive refuses
a delimiter + `false` — the "data primitive refused" host error at the old
line 648. Fix: new `php/json-encode-value` gate passes the child through
when it is not a string (throw mode already threw inside the child; quiet
mode already warned once there, so no double warning). `json_encode([INF])`
now warns `[2 "Inf and NaN cannot be JSON encoded"]` and answers `false`;
with `JSON_THROW_ON_ERROR` it throws `JsonException`.

## 2. P2 — strrpos negative offsets (fixed)

Negative offsets now start that many characters from the end and search
back from there (`hi = len + off`, clamped to `len - nn`), instead of
shrinking the upper bound by the needle length. `strrpos("hello","l",-2)`
is 3. `off > len` or `off < -len` throws `ValueError` ("must be contained
in argument #1 ($haystack)"), and an empty needle is a `ValueError`.
`test/builtin_surfaces_test.clj:37` corrected 2 → 3 plus two ValueError pins.

## 3. P2 — diff/intersect string comparison + unique dispatch (fixed)

`php/p9-diff-others` used loose `php/p9-search`, so `array_diff(["1.0"],["1"])`
was empty. New `php/p9-diff-str-has?` compares `php/p9-string` forms:
the diff keeps `"1.0"`. `php/p9-unique-eq?` dispatch was off by one
(1 = loose, 2 = numeric); now 0 = `SORT_REGULAR` loose, 1 = `SORT_NUMERIC`,
else string — so default `array_unique(['1.0','1'])` keeps one value and
`SORT_STRING` keeps both.

## 4. P2 — array_splice replacement conversion (fixed)

Replacements now pass through `php/p9-splice-repl`, which re-indexes values
(discarding string keys); an explicit `null` replacement is the empty array
instead of a one-element `[null]`.

## 5. P2 — JSON grammar/depth/options (fixed)

- `php/json-number-end` no longer accepts `+`, so `json_decode("+1")` fails.
- `php/json-read-string-loop` rejects raw control bytes (< 32).
- Decode depth counter starts at 1, so `[1]` at depth 1 fails
  ("Maximum stack depth exceeded").
- `json_encode` takes its depth argument (default 512, `< 1` is a
  `ValueError`) and enforces it instead of a hardcoded 512.
- Flags outside the supported masks are refused with an `Error` naming the
  function (encode: only `JSON_PRETTY_PRINT` + `JSON_THROW_ON_ERROR`;
  decode: only `JSON_OBJECT_AS_ARRAY` + `JSON_THROW_ON_ERROR`).
  `JSON_THROW_ON_ERROR` propagation itself was already wired through
  `php/json-fail` / `php/json-encode-fail`.

## 6. P2 — extract/compact residuals (fixed)

- `EXTR_PREFIX_ONLY_IF_EXISTS` (= 7) is present in `builtins.cljc`.
- `php/extract-name` always keeps the `_` separator, so an empty prefix
  imports `$_z`, and `EXTR_PREFIX_ALL` imports numeric keys (`$p_0`).
- `php/bi-extract` validates: mode outside 0–7 is a `ValueError`; a prefix
  mode without a third argument, or with a non-variable-name prefix, is a
  `ValueError` (empty prefix stays legal per the underscore rule; `EXTR_REFS`
  keeps its existing `Error`).
- `compact(1)` warns `[2 "compact(): Each argument must be a string or an
  array of strings"]` and skips instead of silently dropping.
- Fixture `:extract-skip-and-prefix` in `programs_p9.cljc` pinned the old
  naming (`$p_z` + diag); updated to `$p__z` with out `"156"`.
