## Section outline (with weave plan)

1. **Opening (no header)**: today's LLM IDEs bolt a reasoning engine onto a text substrate; the bottleneck is what the model can see and prove. Thesis paragraph.
2. **"What an IDE Actually Is"**: IDE understanding is process state, not a medium (PSI per-language, in-memory, ephemeral); LLM IDEs do RAG by similarity. Weave/echo yin-vm-lsp.blog ("LSP treats the symptom... not the disease") and extend it: LLM + LSP is still the disease.
3. **"The Substrate: Code as Facts"**: brief medium recap; link chinese-characters + dao-space + yin.chp; types as claim rows with provenance and the gate observer (from yin.vm.typecheck.md). Explicit hand-off: link ide-edits-ast-not-text.blog as the editing half, this post as the reasoning half.
4. **"Retrieval Becomes Logic"**: Datalog as the LLM's search primitive: joins, recursion, guaranteed termination (weave what-makes-datalog-datalog.blog: "Datalog is an evaluation strategy, not a programming language", termination guarantee), context efficiency (facts, not text). One concrete `[:find/:where]` example over AST rows.
5. **"The Hallucination Cage"** (the user's refinement, front and center): the store doesn't make the LLM honest, it cages what can be hallucinated; the residual surface is wrong queries and wrong readings, both inspectable. Domain ontologies shrink it further: the LLM composes ontology-backed concepts, and a concept unifying with no fact is a visible type error. Weave why-llms-need-structured-code.blog and advance it: that post said "The hallucination dies at the boundary" (rejection of invented predicates); this post generalizes to caged surface + ontology-constrained query writing. Provenance: LLM-minted rows carry m=LLM, so machine claims are rankable. Light echo of power-of-restriction-datom-tuple.blog ("When the form of data is fixed, the meaning of the data becomes fluid"), noting the fixed form is the interpreter's d5 restriction per the retraction note.
6. **"The Gate: The LLM Writes Through the Same Door"**: write side as a query loop: propose -> yang lowers -> gate observer forwards or refuses with verdict rows citing claim-refs -> LLM queries the defects -> fixes. Authority is write authority on a medium; multi-agent verification as topology (a second observer recomputes verdicts). Weave russian-dolls-yin-vm-llm-symmetry.blog (LLM as isolated reasoning engine emitting data effects) and agents.blog ("The workflow is semantic, not structural").
7. **"Why Traditional IDEs Cannot Follow"**: process state vs medium; every new observer enlarges LLM surface for free (compounding); small regular tuple vocabulary vs thousands of PSI node classes is what makes it LLM-legible.
8. **"What the IDE Becomes"**: conversation over a fact space; observers mint facts, the LLM writes queries, the gate adjudicates, the human judges; editor as one view among many (link visual-ast.blog). Short vignette of one debugging session as queries.
9. **"What Exists Today"**: honesty section modeled on yin-vm-vs-unison.blog's Implemented / Designed, not yet implemented / Later triad: Implemented (yang compilers for Clojure/Python/PHP subsets, q with joins/rules/aggregates, free-name and binder Datalog demos, covered Merkle indexes); Designed (typecheck observer T0-T2, conformance observer, claim authority B7, REPL q surface); Later (real type language, cross-language lineage queries).
10. **"Related Work"**: IntelliJ PSI + Junie, Cursor/Copilot (embeddings RAG), CodeQL/Glean, tree-sitter/semgrep, Unison (link yin-vm-vs-unison.blog).
11. **"Learn more:"** footer: ide-edits-ast-not-text, yin-vm-lsp, why-llms-need-structured-code, russian-dolls, what-makes-datalog-datalog, many-syntaxes-one-ast, yin-vm-vs-unison, chinese-characters, plus /yin.chp, /yang.chp, /dao-space.chp.
