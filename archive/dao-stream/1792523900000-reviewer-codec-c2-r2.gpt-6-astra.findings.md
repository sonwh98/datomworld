The new tests add real socket corpus and Jing coverage, but do not satisfy §7.3:

2. **Only one direction for the JVM-server assignment.** `p1-corpus-chain` at lines 861-862 reads JVM → Node only. `p2-corpus-chain` at 865-869 exercises Node → JVM and JVM → Node over the Node-server session. Both roles and profiles have tests, but both directions in each role assignment are required.
3. **The live corpus is incomplete.** `ws_project_corpus.cljc:21-35` contains 25 plain values plus one Jing wrapper (26 total, not the report's 24 plus one). It omits clean metadata cases, CBOR lists/nested lists, and the Transit-specific slash-bearing keyword. The docstring at lines 6-9 incorrectly groups metadata and all lists/integral doubles as baseline exceptions. Metadata cases are in the clean fixtures; CBOR lists are clean. The CBOR exception is specifically frozen `f93c00` decoding on Node, not a blanket exemption for encode/decode of integral doubles. Required clean cases must not be dropped under the baseline-exception rationale. The Jing wrapper exercises a CBOR byte string, but does not substitute for the other required profile-specific byte cases.

The implemented Jing path itself is sound on inspection: `values` invokes `jing-stream/wrap-payload`; peer reads normalize after receiving the value (`ws_project_peer.cljc:234-239`); `normalize` validates and unwraps through `jing-stream/unwrap-bytes` before comparing unsigned octets. `check-corpus!` checks completion, count and each value. This proves useful behavior for the chosen subset when executed, not the full §7.3 claim.

**Required closure:** run against the actual F0 implementation in a sibling worktree, with any harness-only overlay identified; cover both role assignments, both directions per assignment, both profiles, and the required JVM and Node lanes. Restore the required clean corpus and profile-specific cases; preserve the precisely named baseline exceptions with their frozen outcomes.
