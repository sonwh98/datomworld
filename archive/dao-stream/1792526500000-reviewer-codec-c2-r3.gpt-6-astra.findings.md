## R2 closure

### Corpus and comparisons

`ws_project_corpus.cljc:38-83` contains 31 shared values, two Transit extras or eight CBOR extras, then one Jing-wrapped payload: **34 Transit / 40 CBOR**.

Verified the clean metadata categories: collection metadata, direct symbol metadata, symbols nested in vector and map, a symbol whose metadata contains another metadata-bearing symbol, and a metadata-bearing map key. CBOR adds lists, nested lists, list beside vector, mixed collections containing a list, nonempty/empty/nested bytes, and nested reader metadata. Transit adds `1.0` and `(keyword "user" "foo/bar")`.

The Jing value is actually constructed through `jing-stream/wrap-payload`; received wrapping is checked and unwrapped through `jing-stream/unwrap-bytes`. Comparisons normalize unsigned octets and integral doubles. CBOR comparisons additionally retain metadata and distinguish lists. Transit metadata is deliberately not compared because the codec drops it.

The live corpus excludes the named baseline exceptions: Transit list paths and JVM-encoded CBOR `1.0` / `f93c00`. Frozen exception tests continue to pin their host-specific outcomes. CBOR lists are no longer incorrectly excluded.

**Wording correction:** “The clean fixtures are all here” in the corpus docstring is too literal. The live `reader-meta` value uses a metadata-bearing symbol, whereas the frozen CBOR `reader-meta` entry contains a metadata-bearing list `(:a {:b #{1 2}})`. The requested metadata/list categories are covered, but the live corpus is not an exact replay of every frozen value. Describe it as category coverage, or include the exact frozen reader-meta value and rerun the peer matrix with updated counts. This distinction does not invalidate the demonstrated 34/40-value exchanges.
