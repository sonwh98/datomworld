## Decisions made where design/brief were silent (flag for Architect)

1. `:admit` (the function hook) is KEPT in `link/composition` for AD-2 to
   remove, although 7.5 says AD-1 removes it: the brief forbids touching
   `principal-admission`, and the I3 foreign-principal test asserts its
   exact refusal. Order in the DHT branch: resolve-name, then `:admit` if
   given, then the admission question.
2. CLI host (`yin.repl.main/boot`): the default decision is own principal
   plus an explicit trusted set. The CLI has no trust flag yet (AD-3), and
   the L5 process gate (dht_process_test), the head tests and the L4 keyed
   tests import another declared principal's module through `main/boot`.
   `boot` therefore composes `:admission {:trusted <the --dht-principal
   declarations>}`: a command-line declaration is the user's explicit
   trust choice at this host. `create-state` and `link/composition`
   themselves default to own principal only. One line in `main/boot`;
   reverse it when AD-3 adds a separate trust flag or command.
3. "A nil `:admission` on a DHT source refuses `:yin.admit/unconfigured`"
   is read as: `link/serve` handed no admission STATE. The source's
   `:admission` POLICY may be nil, which means no in-process interpreter
   (an external one answers). Direct `:name-env` entries are never asked,
   so they need no state.
4. `create-state` accepts `:admission :external`: no in-process
   interpreter, questions wait for an answer appended to the session's
   answer medium. The F3 and P1-2 acceptance needs it ("a session composed
   with an external admission interpreter").
5. `recheck-on-answers` also runs one round of the in-process interpreter
   before it drains, so a question parked on an absent decision snapshot
   is answered on a host tick once the snapshot arrives. Without it only a
   typed line would re-run the interpreter.
6. The session mints the admission state (`:admission`) for every link
   source; a non-DHT source never reads it (7.5.1 says a non-DHT source
   "has no admission pair"). `make-session` does not know the source
   kind; minting is two empty rings. Say if this must change.
7. The interpreter's own state (question cursor, decision cursor and
   snapshot) is a separate session value, `:admitter`, carried beside
   `:admission` through `link-raise`/`carry-served`.
8. The `:ok` response carries the admission keys; refusals after an allow
   (a failed load, a dependency binding) do not.
9. The REPL's first require mints link id `[:t0 1]`, not `[:t0 0]`: the
   shell's VM spends counter 0 before the request reaches the pair
   (existing behavior, not AD-1). The run interval `[base, parked)`
   covers it; the shell tests assert the base counter is 0 and read ids
   from the state rather than pinning `[:t0 0]`. The pinned `[:t0 0]`
   cases are at the seam (`retire` unit tests).
