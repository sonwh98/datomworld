## Changes and acceptance evidence

| S4 acceptance | Implementation and evidence |
| --- | --- |
| Keyed cookie; S2 stand-in gone | `dao.jing.dht/cookie-for` now takes the root secret and uses HMAC-SHA-256 twice: an epoch key from the root and tick epoch, then a 16-byte address cookie from that epoch key and observed `[host port]`. The MAC comes from JVM `javax.crypto`, Node `node:crypto`, and Dart `package:crypto` 3.0.7. Socket compositions require at least 32 secret bytes. `socket-requires-a-secret-and-cookies-depend-on-it` and `cookie-for-is-keyed-and-epoch-scoped` pass. The missing-secret test failed before the fix, and the old three-argument cookie function raised an arity error. |
| Chunk cookie gate | Request chunks are verified before `chunks/absorb`; invalid cookies leave `:partial` and routing entries empty. `unproven-chunks-never-amplify-or-allocate` sweeps chunk datagrams through the 1200-byte budget. Mutating away the chunk cookie check failed that test. |
| No spoof-source amplification | The ordinary request and request-chunk paths send at most one `need-cookie` reply, only when its encoded size is no greater than the triggering datagram; smaller packets are silent. The chunk sweep checks reply count, reply size, and state allocation. `every-raw-datagram-size-through-the-budget-is-silent-when-unproven` checks every exact size from 1 to 1200 bytes. The existing gate test covers short and padded valid requests. Removing either size check failed its targeted test; removing first-contact padding failed `first-contact-is-a-padded-ping`. |
| Source binding and claimed addresses | Replies are matched by observed `[host port q]`; `:find` peers become candidates, not proven routing entries. `unexpected-reply-source-and-claimed-peers-are-not-proven` checks both a wrong-source reply and an accepted reply with a claimed third-party address. Mutating source matching or promoting a claimed contact into the table failed the test. |
| Lookup repair | The existing retry path removes a peer from the table after `tries` timed-out attempts; the next table entry becomes eligible as the nearest window changes. `lookup-reaches-the-next-peer-beyond-dead-nearest-twenty` proves a live 21st peer is reached after the nearest 20 die and a dead entry leaves the table. Removing table eviction failed the test. Time is advanced only by tick events. |
| Bounded inbound storage | Socket compositions now require `:dao.jing.dht/max-inbound-bytes`. Successful distinct inbound stores consume byte capacity in stepped state; an over-bound `:store` replies `{:ok false}` and does not write. `inbound-storage-bound-refuses-explicitly` failed twice before the fix (successful reply and inserted bytes), then passed. Duplicate addresses do not consume capacity twice. |
| No publication without opt-in | `publish?` remains false by default. Existing `an-unpublished-peer-is-sent-to-but-stores-nothing` and `an-unpublished-node-still-routes-fetches-and-caches` tests prove no store or fetch service and no network publication while preserving fetch-only routing. Removing the inbound publication check failed the former test. |
| Non-loopback exposure | The DHT opens no socket itself. The composition still defaults `:bind-host` to loopback; an explicit non-loopback bind is permitted now only with a socket composition that supplies a validated secret and inbound byte bound. `publish?` remains a separate default-false declaration. |

The root secret is composition data, generated by the composing host from a cryptographically secure random source (JVM `SecureRandom`, Node `crypto.randomBytes`, or Dart `Random.secure`) and supplied as at least 32 bytes. The DHT keeps it in the composition/state map and never emits it on a stream or wire. It does not persist it. Epoch keys derive from the root via HMAC over the CBOR-encoded tick epoch; cookies use HMAC over the CBOR-encoded observed address. Tick advancement rotates the current epoch; verification accepts current and previous epochs. Recomposition may supply a new root, invalidating old cookies.

Inbound byte accounting belongs to the live stepped state. A composition that reuses a persistent local store across restart must preserve its usage accounting or enforce a store capacity below this layer; the DHT byte-store interface has no enumeration operation from which to reconstruct usage.
