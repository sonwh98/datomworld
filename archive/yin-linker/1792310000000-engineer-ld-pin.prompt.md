## The defect
Discharge (step 5b) compares a dependency pin (`:yin.module/requires` name -> pinned manifest address) only through a module obligation, which exists only for a retained free name qualified by the required module. A dependency that reaches the install child another way (an inherited registry entry, a fresh install, a Python-style quoted require plus module-object operations) is never compared with its pin. The DHT link source's `dependency-bindings` check covers only that source.
## The change (engine, source-blind, language-blind)
In `link-install`, in the `linked` transition BEFORE `lift-slice` publishes anything: for every `[name pinned]` of `(:yin.module/requires manifest)`, look up the halted child's linked entry for `name` (`(module/module-entry (:modules vm) name)`, an entry with `:address`). Absent entry, or `:address` not equal to `pinned`: `refuse-install` with `{:status :refused :reason :dependency-pin-mismatch :module module-name :name name :pinned pinned :linked <address-or-nil>}` (same shape discipline as `:foreign-image`; sorted, first mismatch by `(sort-by str ...)` so it is deterministic). Nothing is received, installed or published; every waiter restored with the refusal; no throw leaves the round. A manifest with no requires is untouched.
