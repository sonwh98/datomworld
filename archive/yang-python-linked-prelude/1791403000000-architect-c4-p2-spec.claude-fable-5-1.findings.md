## 1. Foundations, invariants and layering

### 1.1 What P2 is

P2 makes the Python runtime profile a linker module. The same definition
list that today is copied into every program tree is emitted a second way,
as one module tree with bare export keys, published under one schema-1
manifest named `py`, and linked by a user program whose tree holds no
prelude row. The install child defines lambdas and literals and halts;
`py/init!` allocates the task's runtime state into the module store when
the entry wrapper calls it. Nothing a Python program prints changes.

### 1.2 Invariants P2 must keep

- I1, output parity, bundled. Every C1, C2, C3 and safepoint program prints
  the same text and raises the same exception as today on every VM and
  host under the bundled profile. The four re-pinned goldens of section
  4.9 are the only expected diffs.
- I2, output parity, linked. Every program of section 4.2's corpora prints
  under the linked profile what it prints bundled, on the semantic, stack
  and register VMs, on JVM, Node and Dart.
- I3, defining runs nothing. The module tree, run by an install child on a
  composition with any host modules, allocates no heap cell and performs
  no effect: `(:heap child)` is empty at halt, and the lift of its export
  slice is never refused `:cell`.
- I4, one Python process is one task. Classes, the builtins dict and the
  three runtime cells are allocated once per task into the `py` module
  store by `py/init!`, and every unit of that task sees the same cells.
- I5, no ambient store. A `py` closure's free reads resolve against the
  `py` module store and the registry, never against the task's own store.
  No user-program value is reached by a prelude body except through its
  arguments.
- I6, one source, two emitters. `prelude/definitions` is the only
  definition list. `uast` (bundled) and `module-uast` (linked) are derived
  from it; neither adds a definition the other lacks, and a test says so.
- I7, no new host seam. `host-names` is unchanged in content; a test
  asserts it equals the host-qualified free names of the module tree.
  `register-integer-module` and `admit` are unchanged.
- I8, the linker learns one thing. The only linker and engine change is
  the host-export arm of step 5b (section 2.3). No format record, scanner,
  schema, publication rule or install phase changes.
- I9, Rule R. `yin/def` appears only in the two prelude trees, always with
  a literal symbol key. The linked user program contains no `yin/def`.
- I10, derive, do not persist. Exports, placeholders, primitive
  declarations and host names are computed from the definition list and
  the registry; no new hand-kept table.
- I11, clean breaks. No compatibility shim between the bundled and linked
  wrapper shapes, no alias for the two renamed keys.

```text

| Layer                        | P2's part                                                                          |
+==============================+====================================================================================+

|                              | or publication.                                                                    |
```

Below the prelude: the VMs, encoder, lowerings and install phases are
untouched. If step 0 or the linked corpus exposes a VM, scanner or
store-context defect, that is a finding for the Architect, not something
to route around in the prelude or the lowering (section 5).

Beside the prelude: `safepoint.cljc` is untouched. It stays bundled with
the bundled profile in P2; `pysp` linked and `attach!` are P3, and P3 will
need `py` to expose the runtime cells it reads today by store key
(section 6).

Above the prelude: the REPL is not involved (F2, F3). No `import`, no
`sys.modules`, no module objects, no `__name__` (I1). No publication of
user programs as modules (I3).

## 2. Semantics

### 2.1 The module emitter

Input: `prelude/definitions`, the `[store-key form]` vector P1 left: every
`py/*` function, `[py.rt/state :py/uninit]`, `[py/init! (init-form)]`.

Renaming. `strip` maps a symbol with namespace `py` to its bare name and
leaves every other symbol as it is. It is applied to every definition key
and to every `:variable` name and every literal symbol in every form (the
quoted keys inside `py/init!`'s body are `py.b/*` and `py.rt/*`, so they
pass through unchanged). Before stripping, the single source itself
renames `py/conj` to `py/vconj` and `py/not` to `py/lnot` (D4), in every
definition body, in `lower.cljc`, in `safepoint.cljc` if it names either
(it does not today), and in every test that names them. The bundled tree
sees the same two renames; nothing else about it changes.

Placeholders. `runtime-keys` is the sorted set of every key `py/init!`'s
body defines: the three cells, every `py.b/*` key of `builtin-classes`,
`builtin-functions` and `method-implementations`, and `py.b/builtins`. It
is derived from the same tables `init-form` reads, so the two cannot
drift; a test walks the generated `py/init!` form and asserts equality.
Each runtime key gets the module-level definition `(yin/def k :py/uninit)`.
Reading a placeholder before `py/init!` yields `:py/uninit`; no prelude
body reads a runtime key before `py/init!` has run, since the wrapper
calls it first and `py/init!` itself reads none before defining it.

Layout. `module-definitions` is: the placeholders in sorted order, then
`definitions` with keys and forms stripped. `module-uast` is one
application:

```clojure
((fn [%d0 %d1 ... %dN] nil)
 (yin/def py.b/ArithmeticError :py/uninit)   ; placeholders, sorted
 ...
 (yin/def py.rt/state :py/uninit)
 (yin/def cell? (fn [x] ...))                 ; every definition, stripped
 ...
 (yin/def init! (fn [] ...)))
```

built with `u/app`, `u/lam` and `u/def!`, parameters `%d<i>` generated
(`%` cannot begin a Python identifier). The operands run in order on the
main sequence; the one `:call` comes after all of them; the lambda's body
is a literal. Under the scanner rules of `linker.cljc` 1086 to 1157 every
definition is unconditional and precedes every application site, so every
body read of a sibling or of a runtime key is discharged, and the only
retained obligations are the primitives and host exports the manifest
declares. The `then` chain of `u/seq-nodes` cannot do this (status notes
above), and `publish/sequenced`'s shape is the same chain; neither is
used for the module tree. Step 0 checks the claim on all three vector
formats before any edit.

The tail marks: `module-uast` is passed through `u/mark-tails` as `uast`
is. The lambda's nil body is in tail position; the operands are not.

Exports. `module-exports` is the set of stripped keys of `definitions`
whose original namespace was `py`: every function, `init!`, `run-main`,
`object-class`, `vconj`, `lnot`. `py.rt/state` and the placeholders are
not exports. A test asserts `module-exports` is disjoint from
`(keys vm/primitives)` (D4) and that every export is a key the module tree
defines at module level (`publish/definitions` finds operands of an
application, so the wide layout satisfies `publish-module!`'s
`:undefined-export` check).

`functions-uast` and `uast` stay as they are, over the renamed source;
P2 adds `module-uast` beside them. `prelude/uast` keeps the bundled
wrapper's call to `(py/init!)`.

### 2.2 The `py` manifest

`prelude/module-spec registry` answers:

```clojure
{:name       'py
 :ast        prelude/module-uast
 :exports    prelude/module-exports
 :requires   {}
 :primitives {= {:yin.k/profile ... :yin.k/class :pure ...}       ; vm/primitives entries, as profile-of answers
              + ...
              cell/new {:yin.k/profile <addr> :yin.k/effects #{:cell/new}}
              data/str-concat {:yin.k/profile <addr> :yin.k/effects #{}}
              integer/add {...} ...}}
```

The primitive declarations are derived: the free names of `module-uast`
(the tree's own definition keys and `yin/def` excluded), each either a
key of `vm/primitives` (declared with `(vm/profile-of vm/primitives n)`)
or a qualified name whose namespace is a host module of `registry`
(declared with the profile address the registry entry's
`:manifest :yin.module/primitives` holds for the bare export, and the
effect set the registry's `:callable-effects` index holds for that
export's function, `(get (:callable-effects registry) (get-in entry
[:slice bare]))`, or `#{}` when it holds none). A free name that is
neither is a defect: `module-spec` throws `ex-info` with
`:yang.python.antlr/refusal :yang.python.antlr/undeclared-free` naming it,
before anything is published. A test asserts the host-qualified part of
that set equals `prelude/host-names` (I7, I10).

`publish-module!` then mints the manifest:

```clojure
{:yin.module/name        py
 :yin.module/schema      1
 :yin.module/contracts   {:yin.ast/code ... :yin.semantic/code ... :yin.debruijn.code ... :yin.debruijn.register ...}
 :yin.module/tree        <address of module-uast's canonical rows>
 :yin.module/derivations {:yin.semantic/code <record> :yin.debruijn.code <record> :yin.debruijn.register <record>}
 :yin.module/index       {H <address> R <address>}
 :yin.module/exports     #{init! run-main object-class global-get ...}      ; every py/ key: 276 today plus the three new rows
 :yin.module/requires    {}
 :yin.module/primitives  {= <pp> + <pp> ... cell/new <pp> cell/get <pp> cell/set! <pp> data/... integer/...}
 :yin.module/footprint   {:store-keys #{...} :effects #{:cell/new :cell/get :cell/set!}}}
```

Its address is the "pinned manifest address" of acceptance A1: a function
of the tree, the three derivation records, the H and R image addresses,
the export set, the primitive profile addresses and the footprint, all of
them content the float fix and the linker already make host-stable. The
golden is computed on the JVM and asserted on Node and Dart.

What the manifest pins and what it does not: it pins the profile address
of every host export, so a composition whose `cell`, `data` or `integer`
module publishes another profile (another class, arity list, effect set or
host-state claim) is refused by name at step 5b. It does not pin integer
limits or `data/max-items`, which are not in any profile address today;
that is the deferred half of L-a (section 6). `admit`'s presence check is
subsumed: a missing export is `:unresolved-free` by name.

### 2.3 Host-export obligations at step 5b (the minimal L-a)

Today, `linker/declared-obligation` turns a declared `cell/new` into
`{:name cell/new :kind :primitive :profile <addr>}`, and
`linker/declared-discharge` looks the name up in the receiver's
`:primitives` map only. P2 adds one helper and two arms:

`yin.vm.module/host-export-profile registry qualified-sym`: when
`qualified-sym` has a namespace, `(module-entry (:modules registry) ns)`
is a host-registered entry (its `:address` is nil, `register-host-module`'s
shape), and that entry's `:manifest :yin.module/primitives` holds the bare
name, answer that profile address; else nil. A linked entry (non-nil
`:address`) never answers: its `:yin.module/primitives` are the primitives
it assumes, not exports.

`linker/declared-discharge`, `:primitive` arm: the obligation is
discharged when either the receiver's `:primitives` entry has an equal
profile (today's rule) or `(host-export-profile modules name)` equals the
obligation's profile. A nil profile on either side still resolves nothing.

`engine/discharge-defect`, the second pass: `actual` becomes the first
non-nil of `(vm/profile-of (:primitives state) n)`, `(get
(:primitive-profiles state) n)` and `(module/host-export-profile (:modules
state) n)`.

Refusal shape, unchanged: `{:status :refused :reason :unresolved-free
:name cell/new :kind :primitive}` from the linker arm, or `{... :name
cell/new :expected <addr> :actual <addr-or-nil>}` from the engine pass.
Either reaches the program as the require's error (`engine/refused-entry`).
"Refused by name" means the refusal carries the qualified export name.

Nothing else moves: `publish/free-declaration` keeps refusing host-module
names in `module-from-index` (the REPL's derive path, where the design
still wants a declared profile, not an inferred one); `resolvable?` and
`shadowed?` are unchanged; no format record or scanner changes.

### 2.4 The linked wrapper and the lowering profile

`lower-packet` gains an arity `[packet {:keys [prelude] :or {prelude
:bundled}}]`; the one-argument arity calls it with the default.

```clojure
;; :bundled (today, except the entry name)
(then prelude/uast
      (py/run-main (fn [%globals %globals-fn] body)))

;; :linked
(do (require 'py)
    (py/init!)
    (py/run-main (fn [%globals %globals-fn] body)))
```

The linked form is `u/seq-nodes` over `(u/app (u/v 'require) (u/lit
'py))`, `(u/app (u/v 'py/init!))` and the `run-main` application, then
`u/mark-tails`. `require` is the primitive `vm/primitives` already
publishes (effectful, `:module/require`); `(require 'py)` parks the task on
its link pair until the serving composition answers, exactly as section
7.2 of the linker design says, and a task composed without a link pair
fails as it fails for any module. `(py/init!)` runs after `linked`: the
closure carries `:yin.k/store-of <py manifest address>`, so every
`yin/def` inside it writes the `py` module store through `put-active`,
and the second unit of a task finds `py.rt/state` already `:py/ready`.

`lower-transform` reads `(:prelude state :bundled)` and passes it on.
`open-stage` gains the arity `[cst program diagnostics {:keys [medium
max-digits prelude]}]`; the three positional arities are unchanged.

The user body under either profile reads only `py/*` exports, `cell/*`
host exports, `%globals`, `%globals-fn`, generated `%` names and
primitives (`=`, `+`, ...). The lowering emits no `py.b/*` or `py.rt/*`
name any more (D8), and a test asserts it for the whole corpus
(section 4.7).

### 2.5 `py/init!` under the module store

The body is P1's, unchanged. What changes is where its writes land: under
the bundled profile `store-of` is nil and the writes go to the task store;
under the linked profile the closure carries the manifest address and
the writes go to `[:module-stores <address>]`. Idempotence holds per task:
the guard reads `py.rt/state` from the same store it writes. A second
unit's `(py/init!)` in the same task allocates nothing (A6).

`py.b/builtins` and the class cells are values in the module store that
reference cells in the task's one heap. The heap is task state, not
module state; two tasks hold two heaps and two module-store instances, so
no identity leaks between Python processes (ruling 1, section 8.5.6
"two tasks importing one module get independent namespaces").

### 2.6 `py/run-main` and `py/object-class`

```clojure
[py/run-main
 ;; the entry wrapper's call: today the same as run-module; I1 gives it
 ;; __name__ and the module object
 (fn [body] (py/run-module body))]

[py/object-class
 ;; the implicit base of a class statement with no bases: CPython uses
 ;; object without a name lookup
 (fn [] py.b/object)]
```

Both are ordinary `core-definitions` rows, so both emitters carry them.
`lower-classdef` emits `(app* 'py/object-class)` in place of `(u/v
'py.b/object)`. `py/run-module`'s resets of `py.rt/out` and `py.rt/ctx`

## 5. Rules, judgement calls permitted and prohibited

Permitted without asking:

- The names of generated parameters and private helpers, docstring
  wording, test names, where in `prelude.cljc` the new rows sit, whether
  `strip-form` is one function or two.
- Choosing a different fixed packet for A3 if `x-equals-1` is awkward.

  compile time asks for it.
- Making a private helper of `linker_require_test` public only if copying
  it would duplicate more than about forty lines; say so in the report.

Prohibited:

- Changing the module layout, the stripping rule, the placeholder rule or
  the two renames to make a scanner or a VM happy. If step 0 or the
  linked corpus fails on any VM, stop and report with the output; the
  design decides.
- Any change to a scanner, a format record, the manifest schema or key
  set, `publish-module!`, the install phases, `lift-slice` or
  `receive-module`. The only linker and engine edits are section 2.3's.
- Putting `py.b/*` or `py.rt/*` keys into exports, or stripping them.
- Reading a runtime key from the lowering or the user program. `object`
  reaches the user program through `(py/object-class)` only.
- Patching a VM to make store context survive a continuation invoke.
  That is D7 slice C and an Architect finding; report the failing program
  and VM.
- Deleting or disabling the bundled profile, `prelude/uast`, `admit` or
  any bundled test. Ruling 5's gates have not passed.
- Running the walker under the linked profile or marking its refusal
  expected without the assertion of A1.
- Adding a `yin/def` arm to `sexp->uast`, a `do` node type, or any new
  UAST node.
- Publishing anything from `prelude.cljc`, or requiring `dao.jing` or
  `yin.vm.linker.publish` from it.
- Backgrounding a test lane, committing, or touching `collab/` in git.

Things that look like shortcuts and are not:

- Keeping `seq-nodes` for the module tree "because it works in
  `publish/sequenced`". It works there because each test module defines
  its read key first.
- Declaring `cell/new` as a `:requires` entry. Host modules have no
  manifest address; `requires` maps to manifests.
- Making `discharge` accept any `:primitive` obligation whose namespace
  names a registered module. Presence is not equality; the profile
  address must match.
- Giving the renamed keys aliases `py/conj` and `py/not` "for the tests".
  No shims (I11); rename the tokens.
- Letting `module-spec` fall back to `#{}` effects for a host export whose
  function the `:callable-effects` index does not hold, silently. Record
  it in the report; the footprint is what dependency completion reads.
