## Finding P2-R1: missing receiving-task verification gate (medium)

Location: [linked_harness.cljc](../test/yang/python/antlr/linked_harness.cljc), `source`; [linked_prelude_test.cljc](../test/yang/python/antlr/linked_prelude_test.cljc), publication and execution tests.

The [remediation ruling, section 6](1791405500000-architect-c4-p2-remediation.claude-fable-5-1.findings.md) explicitly requires one additional guarded slow test, `a-verifying-serve-links-py`, that executes a fixed program on the semantic VM through a `:verifying` serving composition, compares its output with the trusted run, and asserts `:trust :verified` in the receiving task's registry entry.

That test is absent. The harness always constructs `source` with `:derivation :trusted`. `manifest-address-test` checks the publisher's local verifying links, but does not exercise a verifying response through receiving-task discharge, install, lift, receipt, and execution. Thus publication evidence does not cover the explicitly required integration path.

Required revision: add the named test using an explicit `link/composition` with `:derivation :verifying`, pass it as `:link-source` to `h/run-linked`, assert output parity with the trusted run, successful halt, and verified trust on the received `py` entry. Retain trusted serving for corpus legs. Run the guarded test on JVM, Node, and Dart.

## Architectural and invariant assessment

- The module emitter derives from `definitions`; stripping changes only symbols in namespace `py`. Qualified runtime keys remain internal. `runtime-keys` derives from the initialization tables, with literal placeholders emitted before the definitions.
- The wide application places definitions on the unconditional execution sequence. Install-time values are closures or immutable literals; initialization remains an explicit consuming-task operation. No mutable host state or hidden runtime allocation was introduced by the reviewed emitter.
- Primitive collisions are addressed by `vconj` and `lnot`; baseless classes use `py/object-class`, avoiding a linked program's direct read of `py.b/object`. `run-main` delegates to the existing module runner, with I1 behavior explicitly deferred.
- `module-spec` derives its free names, excludes definition keys and `yin/def`, declares primitive profiles and qualified host-export profiles, and throws on an unsupplied name. Host effect sets come from the registry's callable-effect index.
- Host profile discharge is limited to host-registered entries. Linked entries with their own primitive assumptions cannot satisfy host-export obligations. Equal, wrong, absent, and linked-entry profiles have direct tests; receiving-task tests also cover wrong profiles.
- The harness uses `:trusted` explicitly, as R6 permits for the publishing composition. The walker is excluded and its expected `:refused :undeclared-free` sibling read is asserted by name. L-b remains the owner of that limitation.
- P2 does not change scanners, format records, manifest keys, publication, install phases, lift, or receipt. The R1-R6 linker work is inherited from L-f; R7-R10 boundaries are respected by the reviewed changes.
- A1 and A3 have exact manifest and program-root goldens matching the design text. A2 adds portable C3 corpus parity and JVM source execution legs. A4-A8 and A10 have dedicated tests; A9 is in `prelude_parity_test`; A12 derives row-count and depth budgets from the emitted tree.
- A11 timings are recorded in the design: publication about 37-45 s, linked execution about 4.4-5.3 s versus 0.4-1.0 s bundled. The execution target is exceeded. The ruling explicitly treats this as an Architect finding, not authorization to tune the linker within P2. These measurements were not independently reproduced in this review.
- The changed linked test files contain no em dashes or first-person pronouns. `git diff --check f0ade63e` reports no whitespace defects. Design text discloses the walker and remaining L-a scope.
