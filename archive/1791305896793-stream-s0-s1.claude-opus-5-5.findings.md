## 1. Changes

### docs/design/dao.stream.remote.md (S0), accepted as is

New section `### 3.0 Stepped channel composition boundary and resource
bounds` (+33 lines, before 3.1 WebSocket). It:
- restates the invariant: dao.stream is the sole boundary, and neither
  yin.repl nor yin.vm.linker knows or cares whether the transport is TCP
  WebSocket or UDP. Swapping transports keeps handle ops, outcome
  algebras, opaque cursors, gap/recovery semantics and append semantics.
  A raw network drop is never reported as a source-retention gap.
- says cadence belongs to the driver: no ambient timers, daemons or
  threads.
- defines the bounds contract: `:max-sessions` admission cap (a newcomer
  at the cap is rejected after expired and closed sessions are reaped: its
  handle is closed and no ack is sent), `:idle-timeout` reaping on
  accept-step ticks (closing the handle and ring), an optional `step!`
  event `budget`, and per-session failure isolation.

I made no edits. It covers every point in the brief. Note that this
section states the target contract. Today `yin.vm.linker.head.ws` and
`yin.repl.serve/connect` still build `:ws` descriptors; S3a/S3b of the
consensus migrate them.

### src/cljc/dao/stream/ws_project.cljc (S1)

The existing edits did all of the following, and I verified each:
- `step!` gained an optional `budget` arity. `(step! p)` behaves as
  before. With a positive integer budget, it reads at most `budget` events
  per call. Ok reads, including foreign-attachment events, and gaps both
  count against the budget, as D3 requires that gaps count.
- `make-acceptor` validates `:max-sessions` (nil or a positive integer)
  and `:idle-timeout-ms` / `:idle-timeout` (nil or positive; the `-ms`
  key wins), and stores them as `:max-sessions` and `:idle-timeout`.
- `adopt!` takes `now`. For a valid offer it reaps first. If the active
  count is still at or above `:max-sessions`, it closes the offered handle
  and returns, with no ack append and no `make-media` call. Admitted
  sessions carry `:last-activity-ms`.
- `accept-step!` wraps each session's projection step and mirror step in
  a try/catch. On a throw it closes that session's handle and ring and
  marks it `:closed?`, and the end-of-tick reap drops it.
  `:last-activity-ms` updates when the projection cursor or the mirror
  cursor advanced.
- New private helpers: `session-closed?`, `session-idle?`,
  `close-session-resources!`, `reap-sessions!`.

My corrections:
1. **`reaped` no longer closes the handle of a session whose projection
   closed.** The prior edit closed the handle and ring of every reaped
   session. The original contract was that a closed session's last mirror
   pass "answered what the handle accepted" and the session is just
   dropped. Its projection closed because the transport reported
   closed/ended/not-found/transport-error or the medium ended, so its
   socket is already gone. Now only idle-reaped sessions get
   `close-session-resources!`, as the brief specifies. Error-isolated
   sessions are closed in the catch itself. `reaped` is back to a single
   arity, `[m idle-timeout now]`.
2. **Reaping runs outside `swap!`.** `reaped` closes handles, and a side
   effect inside a `swap!` fn is unsafe if the swap retries.
   `reap-sessions!` now reads the atom, reaps, then does
   `swap! assoc :sessions`. The driver is the only writer.
3. **`:idle-timeout` validation uses `integer?`**, not `number?`, to
   match the brief's "positive integer or nil".
4. **Removed the 1-arity `(accept-step! acceptor)`**, which defaulted
   `now` to nil. Nobody asked for it, and all callers (`yin.repl.serve`
   :696, `yin.vm.linker.head.ws` :286) pass `now`. I also tightened the
   per-session body (fewer temporaries, same logic) and added
   `:last-activity-ms` to the `sessions` docstring.

When `:max-sessions` and `:idle-timeout` are nil, behaviour is unchanged
from before. The `no-bounds-keeps-sessions-unbounded` test and all
existing dependents confirm this.

Brief item "reap sessions whose :handle is closed": dao.stream has no
public closed-handle predicate, and the consensus says not to add one.
Handle closure therefore shows up in two ways: the transport's terminal
event closes the projection, or the catch path sets the session's
explicit `:closed?` mark. `session-closed?` checks both.

### test/dao/stream/ws_project_test.cljc

- Fixed the EOF read error: `max-sessions-rejects-newcomers-at-cap` was
  missing its closing paren (the form opened at line 485).
- Deleted the `acceptor-with-config` helper, which was a ~50-line copy of
  `acceptor-over`. `acceptor-over` now takes an optional `config` map
  merged into `make-acceptor`, and also returns `:acks`.

  tick, but the acceptor adopts one offer per slot per tick and the
  offer ring holds one value, so att-2 was never admitted and then
  `(second @media)` was nil. It now admits the two on separate ticks, and
  it also asserts that the failing session's handle was closed.
- Tests now in place for the bounds:

  - `max-sessions-rejects-newcomers-at-cap`: the newcomer is rejected,
    its handle is closed, the ack ring still shows only att-1, and no
    media were composed for it.
  - `idle-sessions-are-reaped-and-free-capacity`: the idle session is
    reaped at admission time and the newcomer takes the freed slot. The
    reaped session's handle and channel ring are both closed.
  - `idle-reaping-runs-on-a-tick-without-offers` (new): reaping happens
    with no newcomer, and the `:idle-timeout-ms` key is honoured.
  - `session-activity-resets-idle-timeout`: still alive 40ms after the
    last activity, reaped at exactly 50ms (`>=` boundary).
  - `no-bounds-keeps-sessions-unbounded` (new): the default stays
    unbounded.
  - `invalid-bounds-are-a-composition-error` (new): 0, negative and
    fractional values for both bounds throw.
  - `session-error-isolation`: the failing session is reaped and its
    handle closed, and the healthy session answers in the same tick.
- Extended the ns docstring to describe the bounds coverage.
