# Adversarial Review: Track A Phase C4 Slice P3 (`pysp` linked & safepoint hooks)

Verdict: **READY_TO_LAND** (JVM gate green; Node runtime and slow Dart lanes

## Invariants

1. **Load order inversion: holds.** `prelude/module-spec` publishes `py`
   with `:requires {}` (`prelude.cljc:3187`); `safepoint/module-spec`
   publishes `pysp` with `:requires {py <manifest address>}`. Nothing in
   `py` names `pysp`. `linked-program` orders `(require 'py)`,
   `(require 'pysp)`, `(py/init!)`, `(pysp/attach! py.sp/signals)`, then
   `A'`.
2. **Signal delivery linked: holds.** `deliver` raises
   `(py/call (py.sp/class {:py/str "KeyboardInterrupt"}) [])`.
   `py.sp/class` is `(py/global-get (py/dict-new) n)`, so it reads the
   builtins dict. It cannot be shadowed by a user global, because the
   globals dict is a fresh empty one. Under the linked profile on all
   three vector VMs, the suite covers a bare interrupt, an interrupt
   caught by `except KeyboardInterrupt`, the no-park case and a
   registered Python handler (`linked-interrupt-test`,
   `linked-no-park-test`, `linked-registered-handler-test`).
3. **Recursion tracking across the module boundary: holds.** The hooks
   reach `py.rt/ctx` and `py.rt/limit` only through `(py/rt-ctx)` and
   `(py/rt-limit)`. Each safepoint calls them again, so the hooks always
   see the cell that `py/run-module` and the generator machinery hold.
   `linked-recursion-error-test` (default limit 1000),
   `linked-escape-restores-depth-test` and `linked-generator-depth-test`
   (limit 100) give the same outputs as the bundled suite.
4. **Determinism, no site marks in prelude bodies: holds.**
   `module-uast` is built with `u/sexp->uast` from the definition list,
   and no `:yang/site` metadata is attached. The module never passes
   through the safepoint stage. `stage-input-contains-no-prelude-row-test`
   checks that neither the stage's input nor its output holds a
   `yin/def`, a `py.b`/`py.rt`/`py.sp` symbol, or any operand of either
   module tree. `insertion-is-deterministic-test` checks that two
   derivations are equal. Separately, I traced attach! idempotence:
   `:module-stores` live in the per-task VM state (`engine/active-store`,
   `engine/put-active`). The `:py/uninit` guard therefore scopes to one
   task, and no cursor can leak from one run into the next.

## Findings (none blocking)

1. **(Low, test/doc mismatch) The fail-closed test does not use a
   `pysp`-free name environment.** `fail-closed`
   (`linked_safepoint_test.cljc:332`) runs the unwrapped `A'` through
   `on-every-vm`, which always serves `h/safepoint-source`, so `pysp` is
   in the name env. What the test proves is "no `(require 'pysp)` → the
   hook name is unresolved". §8.11 P3 now claims "a `pysp`-free name
   environment still runs the naive linked program and refuses the
   derived one by hook name", and that claim is untested as written. Fix:
   run the unwrapped `A'` (and the naive program) under `h/source`
   (`{py a}` only), or reword the doc line.
2. **(Low, doc) Stale status line.** `docs/design/yang.antlr.md:2642-2644`
   still says "F1, P1 and P2 have landed". P3 should be added to that
   sentence, and the P3 row of the slice table could note that it landed.
3. **(Advisory, authority) `py/rt-ctx` / `py/rt-limit` widen `py`'s
   exported surface.** Any module that requires `py` can now read and
   write the recursion-limit and dynamic-context cells, for example to
   reset the depth and dodge `RecursionError`. This is incremental, since
   `py/restore!` and `py/init!` already export writers of the context.
   It still fits §8.5.6's "exports only closures". It is worth an
   Architect note if per-module capability narrowing (ShiBi) later
   applies to `py`'s exports.
4. **(Advisory, perf) The bundled profile pays the module-boundary
   bridge.** Under bundled too, every call safepoint makes two extra
   closure calls (`py/rt-ctx`, `py/rt-limit`), and every return makes
   one. This is the price of "one source, two emitters" and is
   acceptable. If the long-loop timings regress, a per-profile body for
   `enter`/`return` is the lever.
