## Decision and source precedence

Implement a **compiled register backend with resumable body functions and an explicit trampoline**. Each declared body becomes a wasm function with one local per physical register. Intra-body control initially uses generated `br_table` dispatch; guest calls and returns update explicit machine state and return to the trampoline. No guest continuation ever depends on a wasm activation. Define host services through the versioned plain-data linear-memory IMPORT ABI in §4.1.1. The existing CLJS engine is one conforming embedder; a native service implementation shared by Wasmtime and Wasmer adapters is another. Neither JS nor a browser is required to execute the same emitted binary.

The toolchain is a JVM Clojure emitter producing deterministic WAT, assembled with WABT and instantiated unchanged by Node/browser, Wasmtime or Wasmer. This is emission from register images, not compilation of ClojureScript to wasm. W0 names exact toolchain pins below; these are implementation acceptance targets, not tools claimed to be installed or tested here. A Rust native embedder implements the ABI and semantic services without invoking Node, embedding a JS engine, or delegating transitions to a CLJS subprocess. Wasmtime is required beside Node from W1; Wasmer joins the release gate by W5. Browser embedding uses the same ABI. JVM and Dart remain semantic reference lanes; binding wasm into their application APIs is separate from the required standalone native embedders.

The mandatory feature profile is **core wasm 1.0 with mutable globals and the original function table / `call_indirect` facility**: i32/i64/f32/f64, structured control, one non-shared wasm32 memory and one function table per module, single-result functions, active data/element segments. No externref or first-class reference values, typed function references, `call_ref`, `return_call`, WasmGC, bulk-memory/table instructions, multi-value, multi-memory, memory64, SIMD, exceptions, threads, component model or JS string builtins are assumed. The baseline table element kind used by `call_indirect` is not permission to emit the later reference-types instruction set. Copy/clear uses scalar loops; no implicit `memory.copy`, `table.set` or `table.grow` instruction may slip in through optimization. Mutable globals need not cross the import boundary; instance base coordinates can use immutable scalar imports.

Every extension requires a separate named profile, W0 validation/probe on all target engines and matching cache key; the baseline artifact must continue to work without it. WABT/Binaryen defaults are not the feature contract. Uneven native-runtime support for post-MVP features is the reason for this deliberate cut, not an unresolved portability risk. WasmGC remains a non-goal despite its inclusion in the September 2025 Wasm 3.0 standard; standardization does not require this backend to adopt it. [Wasm 3.0 announcement](https://webassembly.org/news/2025-09-17-wasm-3.0/).

WASI stays outside the VM core and its imports. A WASI-based embedder may implement stream transports/FFI below the same ABI; the generated program imports neither WASI nor runtime-specific system calls. Binaryen is optional after parity; no wasm-ld pipeline is required for generated guest code. Native embedder builds have their own pinned native toolchain.

Read authorities (source symbols are semantic specifications for every embedder; calls to existing CLJC helpers below mean direct reuse in CLJS and equivalently tested native transitions, not a requirement for native hosts to load Clojure): `src/cljc/yin/vm/debruijn/register.cljc`, `debruijn_register_code.cljc`, `debruijn_register_effects.cljc`, `semantic/derive.cljc`, `semantic.cljc`, `engine.cljc`, `values.cljc`, `yin/vm.cljc`, `linker.cljc`; the four requested VM design documents; and the two requested corpora. In particular:

- The register contract is version 4 / `"r2"`, with exactly 23 opcodes. Preserve the image, physical L/T allocation, instruction pcs, BLAKE3 checksum, and six in-band live operands. Do not allocate another guest register namespace.
- The October amendments to the register and semantic designs make **A the code identity**. R is the register image checksum. Existing `:hash`, `:image`, and offset rows still use R for native compatibility. Do not publish wasm binaries as a new code identity, fetch code by a wasm checksum, or bypass A-to-R admission. Retain access to the Universal AST through existing provenance/addressing.
- Older paragraphs in register §5.2 still put code-space fields on return frames and restore code from payloads. Linker §7.3 r6/r7 and the implementation supersede them: return frames contain no code space; restore never rewinds it. Engine documentation also contains historical `:store-updates` wording; current ready entries update private `:resources` through `:resource-updates`.
- Current `vm/machine-data?`, used by register restore and payload validation, recursively accepts kernel-minted Closure/Continuation wrappers by their payloads, as well as exact-integer carriers. It is not identical to `plain-data?`. Arbitrary host functions/errors remain invalid. Preserve the predicate, not an approximate JSON test.
- The current module-slice encoder in `engine/encoder` explicitly refuses reified and parked continuations with `:yin.k/status :yin.k/non-portable`, kind `:non-canonicalizable`. Thus universal linker transport of every register continuation is not already implemented. This lane must support the existing native payload where admissible, and preserve qualified refusals elsewhere; it must not silently promise a new universal migration mechanism.

## 1. Value representation and linear-memory layout

### 1.1 Values: i32 references into a task-owned value arena

Choose **i32 ValueRef locals**, not NaN boxing and not externref registers. Reserve 0 = nil, 1 = false, 2 = true; all other values use checked arena indices. Every integer, float, string, symbol, keyword, collection, primitive, closure, continuation, and sealed stream/cursor reference is an arena entry. Numeric computation initially remains in embedder primitive services: the CLJS adapter uses existing implementations, and the native service implements the same declared primitive profiles, integer carriers, float behavior, equality and metadata semantics. W0 codec/profile fixtures prohibit substituting Rust or JS default numeric/coercion rules. Zero, empty strings, and empty collections remain truthy: only references 0 and 1 are false.

Each embedder owns an explicit per-task arena, not a process global. Linear memory contains a parallel descriptor table: kind, generation, opaque host-slot and optional machine-record offset. The slot is a task-local numeric identity, never a JS object address or native pointer. All service exchanges serialize plain-data messages in linear memory (§4.1.1), including in Node; there is no privileged direct-object fast path. Known immutable arena values may be referenced by checked task-local ids in those messages, with definitions transmitted on first use.

CLJS reconstructs its actual values and uses `values/closure`, `values/continuation` and typed effects. The native service uses a tagged value implementation with equivalent ownership, structural equality, hashing and opaque printing. Trusted kernel constructors mint closure/continuation identities; literal maps remain data regardless of keys. Native primitive/effect capabilities are supplied explicitly by the composition, never encoded as function pointers. Pointer/handle equality is not guest equality. Round-trip tests include metadata, keyword versus symbol, exact integers, float bit representations, nested collections and trusted wrappers.

Stream and cursor *references* are sealed plain data, not host types in `yin.vm.values`. Their underlying stream handles and mutable cursor resources stay in `:resources`. `:make-stream`, primitive functions, and bridge handlers are composition services, never serialized guest values. Any returned effect must pass `module/effect?` and `engine/check-callee-effect!`; a map shaped like an effect is not dispatched.

Using i32 handles avoids passing i64 values as JS numbers or requiring externref persistence. It costs host crossings and arena indirection. This is acceptable for the first semantic implementation: register instructions themselves contain no numeric arithmetic opcode. A later native scalar fast path needs explicit numeric laws and benchmarks, not a change to the public image contract.

### 1.1.1 Three encoding domains; native hashing is mandatory

The native service must implement **three distinct codecs**, not substitute the convenient ABI transport encoding for repository identity bytes:

| Domain | Existing authority / exact obligation | Observable products |
|---|---|---|
| Private import messages | §4.1.1 TLV codec, reference expansion, framing and NaN rules | ABI request/response bytes only; not code identities or seals. |
| Executable register scalar/image encoding | `src/cljc/yin/vm/debruijn_code.cljc` `scalar-class`, `encode-scalar`, and `framed`; `src/cljc/yin/vm/debruijn_register_code.cljc` `encode-register-image`, `descriptor-hash`, `register-hash` | R for empty/base/attached/composed images, layout slice checks and continuation self-consistency. |
| Jing canonical content encoding | `src/cljc/dao/jing/cbor.cljc` `encode`/`decode` and its existing corpus; `src/cljc/dao/jing.cljc` `canonical-bytes`, `content-hash`, `segment-key` | Owner tags, reference seals, primitive-profile addresses, module/semantic addresses and existing content admission. |

Port executable framing exactly: class tags and eight-hex-digit **UTF-8 byte length** prefix content; some content is hex-encoded numeric bits, while string content is the actual string. `jing/blake3` hashes the UTF-8 bytes of the resulting **string**, not hex-decoded bytes. R is BLAKE3 of the string concatenation of descriptor-hash text and encoded-register-image text (`debruijn_register_code.cljc:258–271`). Do not replace it with a CBOR hash or hash the ABI node bytes. Preserve descriptor material, body order, tuple operand order, exact scalar classification, no NFC, unsupported-value rules, numeric endian rules and canonical-key collision refusals (`debruijn_code.cljc:198–203, 224–242, 350–378, 410–465`). The native backend matches the admitted CLJS scalar profile where that host rejects JVM-only scalar classes; broader Jing integer support does not silently widen register-image admission.

Port Jing’s actual canonical CBOR profile, not a generic library’s defaults: keyword/symbol/list tags, exact integer/bignum, float64 carriers, decimal/rational forms, collection ordering, metadata stripping/validation, equality-collapse and duplicate checks, depth limits, surrogate refusals and decode/re-encode identity. The private ABI may carry a lone UTF-16 surrogate for in-machine fidelity; that does not make it hashable by either repository codec. Keep that domain distinction and the existing qualified refusal. `jing/content-hash` digests canonical CBOR bytes directly and returns lowercase hex; `jing/segment-key` applies the exact namespace/algorithm/digest spelling. The default here is BLAKE3; any advertised alternative algorithm must reproduce the repository registry’s behavior rather than aliasing BLAKE3.

Required formulas are the actual inputs in source: owner = content-hash of `[:yin.k/owner secret]` (nil secret → nil owner); seal = content-hash of `[:yin.k/seal secret kind id]` with issue-ref’s missing-secret refusal; primitive profile = content-hash of the exact description in `vm/primitive-profile`, followed by the `:yin.k.pp/blake3-…` keyword construction; module address = segment-key of the manifest. Preserve A’s existing canonical construction as well. Equal test secrets, identities and input data must yield **bit-identical** R, owner, seal, profile and address across CLJS and Rust. Do not normalize these fields away or let the native service trust supplied digest strings instead of recomputing them.

W0 ports/verifies these codecs and hashing primitives before native execution gates. Reuse `test/resources/dao/jing/cbor-v1.json` and its README/errata plus `test/dao/jing/cbor_conformance_test.cljc`, `test/dao/jing/hash_registry_contract_test.cljc`, `test/yin/vm/debruijn_code_test.cljc` and `test/yin/vm/debruijn_register_code_test.cljc`; do not regenerate existing goldens. Add cross-embedder vectors for descriptor-hash/R (including empty and concatenated images), exact encoded bytes, owner/seal/profile inputs and manifest addresses. W1 verifies load/primitive profiles, W2 recomputes continuation hashes, W3 checks every minted reference seal, and W4 checks compose/attach/layout/module addresses and received slices. These are native service obligations independent of the ABI codec implementation.

### 1.2 Proposed private memory ABI

Use imported, non-shared wasm32 memory, little-endian and bounds checked. One task owns one memory arena; all its compiled image instances import that arena. Separate tasks receive separate arenas even when compiled Module objects are cached. A supplied coremem can implement the same interface only with task isolation and allocation ownership; shared mutable guest state is not introduced.

| Region / record | Contents and rules |
|---|---|
| Task header | ABI version, run status, absolute pc as unsigned 64-bit field, body id, active register count/pointer, lexical-chain pointer, return-stack pointer, store-of ValueRef, value ValueRef, host-state token, code-layout generation, scratch/request pointers. Pointer fields are u32. |
| Body directory | Absolute start/end pcs, register/local counts, image row, compiled function slot, body-relative entry mapping. Append-only while attached. |
| Active register shadow | Dense array of u32 ValueRefs of exactly the current body's `:registers` size. L slots are initialized from positional arguments; T slots start nil. Wasm locals cache this array while a body executes. |
| Lexical frames | Immutable vector records: count followed by ValueRefs. Chain is an immutable outermost-first vector of frame pointers. Depth d indexes `count - 1 - d`, then position. |
| Return stack | Immutable/persistent vector of return-record pointers, innermost last. Records contain site-pc, return-pc, frames pointer, sparse pairs pointer, live vector pointer, dest, optional store-of. No segment/hash/layout snapshot. |
| Sparse snapshots | Count followed by sorted `(u32 register-index, u32 ValueRef)` pairs. Records do not alias mutable active-register storage. Only the verified live set is captured. |
| Continuation record | Immutable snapshot metadata: format/hash/image ValueRefs, capture-time segment and optional images ValueRefs, site-pc, pc, frames, sparse regs/live, return stack, destination presence/index, resume mode, optional store-of. Engine/FFI transport fields remain losslessly represented in the host payload. |
| Value descriptors | Kind/generation/host slot plus optional closure or continuation record pointer. Host slot contains the actual immutable value or trusted wrapper. |
| Engine state roots | ValueRefs/tokens for store, module-stores, free-env, primitives, modules, wait-set, ready-queue, parked, resources, heap/gc, owner, origin/ancestry, id-counter, `:yin.k/gate`, `:yin.k/issued`, and `:yin.k/closes`. Preserve all other extension keys as well. The actual issue-counter key is `:yin.k/issued`, distinct from id-counter; do not invent `:yin.k/next-issue`. These are state/arena retention roots, not an expansion of the engine’s logical heap-GC root set. The full existing state map is authoritative for engine extension keys. |
| Exit mailbox | Pending instruction site/op and argument refs, pending result/error ref, completion kind. Private implementation state, never a portable continuation. |

Pcs use 64-bit fields so wasm32 pointers do not silently narrow the existing layout domain (up to `2^52-1` in `compose`). Functions use small body-relative i32 dispatch indices after checked resolution. Reject resource/address exhaustion with a qualified backend diagnostic before allocation/attach; never wrap a pc, handle, or byte offset. The counter remains the existing host integer value and advances only through engine operations.

The program store is logically an immutable map, usually name-keyed but **not restricted to names**: `:store-get`/`:store-put` accept `:data` keys, including keywords and numbers in the corpus. Its linear-memory representation is a root ValueRef to the embedder’s persistent map, not a second wasm hash map; the map and updates are addressable through ABI value definitions/state messages on every runtime. All writes go through `engine/put-active` → `engine/store-put`. Non-nil store-of selects only that module's store, with no ambient fallback. Private resources and heap are distinct from program store.

### 1.2.1 Mandatory map ↔ memory synchronization

The public CLJS VM remains a persistent record with ordinary map keys, not a token that requires callers to use `read-state`. A native embedder exposes the equivalent immutable named-field state and explicit snapshot replacement; it need not implement Clojure records, but must preserve their transition semantics. The ABI serializes these snapshots and checked value references. Treat linear memory as a private execution cache. The synchronization protocol is:

1. **Public entry / host-to-wasm:** `step`, `run`, and restore accept the supplied map as authoritative. Import `:pc`, `:registers`, `:frames`, `:continuation`, `:store-of`, `:value`, `:halted?`, and `:blocked?`, plus the current code layout and engine state. W1 imports unconditionally. A later cache may skip only after proving all relevant keys agree with its last materialized snapshot; a retained private token alone is not proof. In particular `(assoc parked :pc 2 :halted? false)` must execute the requested state. Import a copied or privately owned active shadow so running an old or externally modified map never mutates another returned map.
2. **Wasm-to-host:** before every state-consuming `engine/*` call, including handle-effect, pinning, collection, scheduler, park/resume and module work, materialize all eight execution fields onto the VM record. Materialize them also at every public `step`, `run`, restore or inspection return. Keep the record’s protocol implementations so `module/gc-roots` can inspect the current map. Dense memory synchronization without map synchronization is insufficient.
3. **Host completion:** the returned host state is the new authority, including its execution fields and every extension key. Apply only the current opcode’s specified post-service changes to that returned state, then reimport it into memory. Never overlay a pre-service header onto it. In particular handle-effect sets `:value` even for nonblocking effects; preserve that value, resource/heap/GC updates, stores, counters, queues and custody fields. A plain non-tail primitive call, by contrast, only updates pc/rd in the kernel and does not automatically set `:value`.
4. **Seam pc:** before a host service, the map contains the instruction’s absolute site pc, unless the source transition explicitly advances it first (such as parking in the FFI path). Capture the payload at the site; apply the opcode’s pc update exactly once after service completion. Mailbox state does not count as a completed guest instruction.

This is also a GC safety requirement: `:cell/new` may collect *inside* handle-effect, before the adapter receives its result. At that moment map-based registers, frames, continuation and value must already be current. Reuse the engine’s exact logical heap tracing rules; arena retention of a host value cannot substitute for marking the heap cells that value references.

### 1.3 Ownership, spilling, and collection

Start with a dense shadow synchronized on every register write and before every return to the host. The local is the execution operand; the shadow makes complete current state and GC roots available. Sparse saved frames and payloads are nevertheless mandatory: never retain the full dense shadow through a call or park. On a successful call/restore, replace the active shadow; clear abandoned mailbox/argument roots when no longer needed. A parked VM's observable active register vector may still contain dead slots, as the reference VM does; do not confuse those current-state roots with the sparse payload.

No collection runs while wasm holds unreported local values. Initially run arena collection only after full materialization at an exit; engine heap collection may run inside a host service after the mandatory map barrier in §1.2.1; later dirty-slot spilling can replace write-through with a separate GC/inspection barrier. Mark active registers, frames, value, continuation, parked/wait/ready entries, stores, module stores, engine heap and pinned/outgoing values, constants, and pending mailbox arguments. Traverse trusted wrappers via `values/payload` and preserve the register kernel’s `module/gc-children` implementation and its treatment of code. Integrate `engine/pin-refs` for arguments leaving through FFI. Keep embedder arena ownership and the existing logical heap GC distinct, with explicit roots connecting them. Reclaim only unreachable implementation storage, not stream history or persistent datoms. Avoid handle reuse initially; later reuse needs generations checked at every host import.

External state inspection produces immutable host snapshots. Resuming one snapshot cannot mutate another snapshot's frames, values, or registers. Persistent snapshots share immutable arena objects, never a mutable register buffer. The first implementation may copy the active dense vector at every public IVM transition; optimize only after snapshot-alias tests pass.

## 2. Code generation strategy

### 2.1 Choice among the alternatives

| Strategy | Benefits | Costs / semantic obligations |
|---|---|---|
| Fully structured body functions with direct guest `call` | Small fast code for ordinary functions; conventional optimizer input | Captured continuations require every caller activation to be materialized and abandoned; arbitrary resume PCs need secondary entries; suspension cannot retain native stack frames. A shadow stack alone does not unwind native callers. |
| One interpreter loop over instruction records | Small wasm binary, trivial append and pc resume | Runtime operand decoding and memory-indexed registers on every step; does not exploit known register operands as locals. Initial test oracle; retained as a W6 optimization axis with services moved into wasm if serialized crossing cost dominates. |
| **Compiled body dispatch plus trampoline** | Static register locals and operands, arbitrary entry PCs, appendable bodies, constant native stack depth, explicit continuations | More generated code than interpreter; indirect dispatch and spills at transfers; per-body branch tables may be large. |

Choose the third. A body function has conceptual signature `(state-ptr i32, entry-index i32, budget i32) -> status i32`; updated budget/state lives in the header. All bodies share the same signature for a function table. The trampoline resolves absolute pc, calls one body function, then loops on transfer. A body **never invokes a guest callee directly**. Guest call saves a return frame (unless tail), installs callee state, and returns TRANSFER. Return installs caller state and returns TRANSFER; final return returns HALTED. The trampoline's wasm `call_indirect` is an implementation dispatch, not the guest call stack. On HOST_SERVICE the body has returned; a shared runtime service thunk serializes the mailbox and invokes the import ABI. It decodes the completed response or returns the blocked/error status. No guest activation remains live across an asynchronous wait. The same thunk and body binaries run on each embedder.

Consequently flattening is exact and incremental: every pending guest call is already a sparse memory record before its callee runs. Capturing K copies/shares those immutable records; abortive application replaces the current chain and returns from the one active body. No stack walk, Asyncify, native-stack copying, wasm exception unwinding, or retained JS Promise continuation is needed.

`return_call` is **not required or emitted**. Tail guest calls retain K unchanged and replace the active lexical chain/register file. This gives bounded native stack depth on engines without the tail-call extension. A later direct-call optimization may be allowed only for a proven noncapturing, nonsuspending region with a deoptimization protocol; it is not part of this plan.

### 2.2 Structuring algorithm

1. Admit the image with the exact contract check and `register-image-defect`. Preserve body ranges and the original source instruction vector as metadata. Reuse `body-liveness`/`live-slot-index`; do not derive live sets from the optimized wasm graph.
2. Build each body's CFG using the existing successor rules: conditional two-way edge; jump target; no successor for return/halt/resume or tail call; ordinary call and other operations resume at pc+1. Jumps must remain inside their body. Do not assume a hand-authored valid image is the structured syntax emitted by `derive`.
3. For W1, make every instruction an entry case. Load locals from shadow, enter a wasm `loop` containing nested void `block`s and a `br_table` selecting the pc case. Each case consumes its operands into locals, leaves an empty operand stack, updates the next pc/case, then branches to dispatch or returns one status. All branch targets have the same empty result type. Functions return their status only at the common exit. Invalid entry takes a qualified fault path, not execution of arbitrary memory.
4. For W6, merge straight-line instruction cases into basic blocks, retaining leaders at targets, body entries, all resume pcs, and every externally observable step/exit site. Preserve an entry path for each supported pc; debug one-step mode can retain instruction cases. General irreducible CFGs keep dispatch. A subsequent measured optimization can compute dominators/SCCs and structure single-entry regions as `block`/`loop`/`if`, retaining a local dispatcher for multi-entry SCCs. There is no need to ship a full relooper to get a correct backend.
5. Check budget at instruction boundaries for bounded/debug execution. A budget yield materializes the **full** active state and returns YIELDED; it is not a new guest suspension site, has no invented sparse live operand, and is not serializable as an r2 continuation. `step` counts one guest instruction, even when several host service transitions implement it.

### 2.3 All 23 opcode lowerings

Here `r` means ValueRef local, `next` means pc+1, and “host service” means a synchronous ABI message exchange implementing the specified engine transition after returning from the body, not an application callback or new external FFI path. The mailbox records the already-read operands so re-entry never repeats an effect.

| Opcode | Lowering and observable behavior |
|---|---|
| `:const rd value` | Load interned literal reference into rd; next. Preserve actual scalar/collection value and metadata. |
| `:load-bound rd depth position` | Read frame chain at `count-1-depth`, then position. Preserve `:load-bound-depth` and `:load-bound-position` failures. Never substitute reserved L locals for the runtime chain. |
| `:load-free rd name` | Host `engine/resolve-var` with free-env, active store, primitives, modules. Preserve lookup order, present-nil bindings, Rule R, and module resolution. Write rd; next. |

| `:move rd rs` | Read rs before writing rd; next. |
| `:call rd fn-reg arg-regs tail? live` | Read operator and ordered arguments first. Use `engine/operator-kind`. Closure: nil-fill/drop extras to arity, append bound frame to captured chain, initialize L args and nil T slots; push exact sparse caller frame only for non-tail; set closure store-of and body pc; TRANSFER. The return-result restore case first changes pc as specified in §3.2. |

| `:gensym rd prefix` | Engine gensym using the same task counter as stream/park ids; rd/next. |

| `:stream-next rd cr live` | Build site payload; typed next effect. Immediate result → rd/next; blocked → reader wait entry, advance pc, BLOCKED; all other outcomes follow engine. |
| `:stream-close rd sr` | Typed close effect and engine result, rd/next; nonblocking. |
| `:current-continuation rd live` | Snapshot before writing rd at next pc, mint owned Continuation with `:type :reified-continuation`, write rd; next. Destination is excluded from saved live set. |
| `:park rd live` | Snapshot and advance pc, call engine park-continuation. Adds id/type to parked record, increments counter, sets value to record and halted true. PARKED status; do not invent a stream wait. |
| `:resume parked-id rs` | Literal keyword id and value from rs. Engine resume-continuation performs custody gate/missing-id checks and removes parked entry, then register restore. Abort current path; no next-pc fallthrough. |
| `:ffi-call rd op arg-regs live` | Require call pair first; snapshot and read ordered args; pin outgoing refs; park under correlated call-id and advance pc; append request; enter reader wait or full writer wait. Always yields to protocol; no direct call of bridge handler from wasm. |

### 2.4 Exact host-function effect completion

For `:call` whose `apply f args` result satisfies `module/effect?`, first use the state returned by `engine/check-callee-effect!`. Build `payload-of` at the original call site from the materialized state and relocated combined instruction. Tail calls use `:resume-mode :return-result`, `:dest nil`, and their verified empty live set; non-tail calls use `:write-result` and rd. Pass `{:park-entry-fns (park-entry-fns payload)}` to `engine/handle-effect`, with builders for `:stream/put`, `:stream/next`, and `:module/require`. The module handler uses the require builder as fallback for `:module/try-require`; gated stream poll uses the next builder as fallback. Do not wire only the dedicated stream opcodes.

Given `{:state state :value value :blocked? blocked?}` from handle-effect:

- Blocked: return `(assoc state :pc (inc site-pc))`, with no destination write and no return transition, even for a tail call. The payload retains the pending destination/return mode for later delivery.
- Nonblocked tail: run `return-transition` on the **post-effect state** and value. Do not pre-increment pc: if K is empty, this immediate path halts at the call site. This differs observably from a blocked tail effect later restored at the payload’s next pc.
- Nonblocked non-tail: set pc to next and write value into rd of `(:registers state)`, preserving the rest of the post-effect state, including `:value` set by handle-effect.

Never reconstruct the result from the pre-effect wasm header: module attachment, store/module-store writes, resources, heap/GC, counters and custody bookkeeping may have changed. A non-effect host result follows the separate plain-result arm of `register.cljc`, including preservation of old `:value` on a non-tail call.

## 3. Continuation capture and resume

### 3.1 Exact external/native shape

At a six-op boundary at p, export exactly the payload built by `effects/continuation-payload`:

```clojure
{:segment capture-time-segment
 :site-pc p :pc (inc p)
 :frames outermost-first-frame-vectors
 :regs [[live-index value] ...] :live [live-index ...]
 :continuation [return-frame ...]
 :dest rd-or-nil :resume-mode :write-result-or-return-result
 :format :yin.debruijn.register
 :hash capture-time-register-hash
 :image identity-of-row-containing-resume-pc
 ;; :images capture-time-offset-table when count > 1
 ;; :store-of module-address when present
}
```

Return-frame shape is `{:site-pc :return-pc :frames :regs :live :dest}` plus optional store-of. Frame order, sparse pair order, absent-vs-present optional fields, and keyword values are preserved. The `image-row` convention includes the one-past-last-row endpoint for address helpers; that does not make it a valid write-result continuation pc: continuation-defect still requires the site's and resume pc's body to agree.

Materialization recursively resolves ValueRefs, never puts numeric handle IDs into payload values. Import performs the inverse into immutable records. The capture-time segment/hash/table are validation data and must survive later attach unchanged. They can share immutable objects in memory, but a plain-data export must contain the actual required image data. A wasm function index, memory pointer, instance id, or private ABI version is not a guest format identity.

### 3.2 Restore algorithm and failure ordering

Expose one adapter restore with the same `(base entry val) -> state` contract and use it from both engine resume paths:

1. Check `:format` equals `:yin.debruijn.register` and entry `:image` is in base `:images`; preserve `:rule :continuation-format`, `:reason :foreign-format`, and diagnostic context. Do **not** compare entry hash to current base hash.
2. Run the existing `effects/continuation-defect` against the entry, preserving deterministic first-defect results, including capture-time hash recomputation and per-component image/table validation.
3. Check the actual `vm/machine-data?` predicate on val; reject unsupported host functions/errors with `:rule :resume-value`. Do not turn an error-shaped ordinary map into an exception.
4. If request-sent, enqueue `ffi/response-wait-entry` using call-id and remain blocked with `:yin/blocked`, halted false. Do not deliver writer acknowledgement into rd.
5. Otherwise remove call-id from parked when present and apply `ffi/call-result` to its response. For write-result allocate the receiving body's register count, nil-fill, copy sparse pairs, then write dest; restore pc, frames, K, store-of, value and halted false. For return-result first assoc `:pc (:pc entry)`, `:frames (:frames entry)`, `:continuation (:continuation entry)`, `:store-of (:store-of entry)`, and `:halted? false` onto base, leaving `:registers` equal to `(:registers base)`; then run the ordinary return transition. With empty captured K this halts at the entry’s next pc, retains base registers and captured frames, and clears store-of. With nonempty K, the popped caller frame replaces pc/registers/frames/store-of as usual. Preserve base's store, resources, queues, counters, modules, and code space.

Do not clear blocked universally in the low-level restore: the engine clears it in ready-queue resumption; direct paths preserve the source's exact field behavior. Public APIs should route through engine scheduling instead of manufacturing a partially cleared state. Failed restoration must not commit a mutated arena/state snapshot: stage validation and allocations before publishing the successful transition.

A `:call` of a trusted reified continuation uses the distinct internal path: `engine/operator-kind` ownership classification first, `engine/continuation-argument` arity check second, format/image membership third, then write-back; it deliberately skips continuation-defect/machine-data gates. For an unowned continuation with wrong arity, ownership fails first with `{:reason :foreign-value :kind :continuation}`, not `:continuation-arity` (and not the reviewer’s `:foreign-continuation`). A live primitive in an internal capture is valid and must not be rejected merely because it could not cross a wire. This is abortive, and applying a retained capture more than once is allowed; do not mutate its saved records. Explicit parked-id consumption is separate and removes that parked map entry.

### 3.3 Host transport and different layouts

Same-layout native payloads with transportable values can round-trip between interpreted register and wasm execution. Every wasm/embedder boundary inside the same task now serializes a private ABI message. Trusted wrappers travel as checked task-local capability references or trusted-constructor results, not raw host objects. This internal serialization does not grant those values external stream portability. On a real stream boundary use existing lifting/lowering and codecs, preserve literal-map escaping and authenticated resource rebinding, and refuse values that those facilities cannot encode. Never export host slots on a guest stream or mint a Closure from an untrusted map. ABI task-local references are valid only within the trusted implementation channel and cannot be treated as portable continuation data.

For the present module/linker path, keep the existing non-canonicalizable continuation refusal described above. If a future authorized transport carries register continuation coordinates image-relatively, it must translate **site-pc, pc, every return frame's site/return pc, and recursively all closure body pcs**, attach admitted origins, reconstruct self-consistent segment/hash/live metadata, and apply normal native restore. Raw payloads with absolute pcs must not be fed to a differently ordered receiving layout merely because one R is present. W0 must gate the native transport API to a verified matching layout/prefix or return qualified `:continuation-format`; this transport restriction does not change same-task `register-restore` semantics. General rebasing and canonical semantic UCF migration remain outside this backend's completion claim.

## 4. Blocking, effects, and FFI protocol

### 4.1 Embedding contract

The instance exports conceptual `run(state, budget)`, `step(state)`, `read-state(state)` and validated state-install operations. The host-facing adapter provides `create/load`, `attach`, `run`, `step`, `resume-parked(id, value)` and `restore-ready(base, entry, value)`; names are proposed ABI, not existing functions. Public native payload imports go through §3 before an internal wasm installer can write records. All these entry/exit paths obey §1.2.1: callers can directly read or assoc the VM map keys, host calls see current map roots, and every post-host state is imported before wasm continues. `read-state` is a convenience, not a prerequisite for correct map contents.

Use finite status values: TRANSFER (continue trampoline), HOST_SERVICE (complete current instruction), YIELDED (budget), BLOCKED, PARKED, HALTED, ERROR. These statuses are private scheduling results; exported VM maps retain exact `:blocked?`, `:halted?`, `:value`, wait-set, ready-queue, and parked behavior. **Blocking is a normal return, never a trap.** Unexpected wasm validation/memory traps are backend faults and never substitutes for `:yin/blocked` or an FFI error envelope.

Each embedder supplies the same step/restore and scheduler contract over the ABI. The CLJS adapter delegates to the shared engine; native adapters use a common native service library implementing the same transitions. For the `step` method of `yin.vm/IVM`, run one guest instruction or the existing scheduler-round when inactive. For the `run` method of `yin.vm/IVM`, honor `engine/run-loop` ordering: active work first, then wait polling and ready queue, then halt; wrap bridge dispatch with the equivalent of `ffi/maybe-run`. An optimized run chunk may execute many pure instructions, but returns before every host service and exposes the same boundary state. It must not poll early, reorder ready entries, or stop on a halt while ready work remains. Preserve `halted-with-empty-queue?` rather than equating any private HALTED status with public completion.

The service mailbox is implementation glue, with no application callback. All adapters invoke primitives and sanctioned stream-handle operations through the message contract. JS event handlers or native I/O completion handlers only classify and append plain-data events; a separately driven pump polls them and enters the adapter. External host effects remain request/response streams. Neither a browser callback nor a native future resumes a retained wasm activation. Import execution completes synchronously with a response or blocked status; the import never waits on an external operation or holds a suspended stack. Re-entry of the same task during an exchange is prohibited.

### 4.1.1 Import ABI `yin.register.host.v1` (proposed, not existing source)

The following names are a **new implementation ABI**, not repository functions or a guest r2 schema change. All runtimes supply identical imports. The shared runtime module imports `memory` (one wasm32, non-shared memory), `functions` (one original function table), and **`exchange(control_ptr: i32) -> i32`** from module name `yin.register.host.v1`. Generated component modules import the same memory/table and the service entry as needed, plus declared immutable i32 base-offset words. No import/export passes a JS value, externref, Rust pointer, string object, multi-value result or i64 through a host-call signature. i64 pcs/numbers are bytes in memory; core i64 computation inside wasm is allowed.

**Offsets and ownership.** Reserve bytes 0–255 for ABI control, initially zeroed; control_ptr is 0 for v1. At offsets +0/+4/+8/+12 store little-endian u32 magic `0x31524e59`, major 1, minor 0, header length 64. Offsets +16/+20 hold request pointer/length; +24/+28 response pointer/capacity; +32 response written length; +36 required response length; +40/+44 exchange sequence low/high; +48 transport status; +52 flags (zero in v1); +56/+60 reserved zero. Initial request region is [256, 32768), response region [32768, 65536); task allocation starts at 65536. For larger messages, allocate checked disjoint buffers in the same memory and update the descriptor; these initial sizes are not semantic limits. Neither request nor response may overlap control or machine records. W0 records maximum message/depth/arena budgets and exact qualified resource-limit results.

The guest writes the complete request/header, then invokes exchange. The host reads/copies and validates it, performs at most one transition, writes response bytes and result lengths/status, and returns the same status as i32. The host cannot grow memory or re-enter guest exports inside exchange; guest allocation/growth occurs between calls and all memory views must be refreshed afterwards. The host must bounds-check unsigned pointer+length sums without overflow. It may write only response/control output fields, not mutate the register shadow behind the guest’s back. The guest imports response state only after checking ABI/task/sequence and decoding completely.

**Transport status values:** 0 COMPLETE (response available), 1 NEED_SPACE (completed response retained, required length at +36), 2 BAD_MESSAGE (malformed bytes/descriptor), 3 ABI_MISMATCH, 4 RESOURCE_LIMIT. VM execution status is a field of a successful decoded response: TRANSFER/HOST_SERVICE/YIELDED/BLOCKED/PARKED/HALTED/ERROR as already specified; guest blocking is never NEED_SPACE. Qualified semantic refusals/errors are ERROR responses containing plain diagnostic data, never host exceptions crossing the import. The CLJS public adapter raises its normal host exception only after decoding that result; native public APIs return/raise the equivalent diagnostic. Unexpected wasm traps remain implementation faults.

**Exactly-once response delivery:** task+exchange sequence identifies one request; the host retains its response until the guest acknowledges it in the next request. On NEED_SPACE, resize and issue a transport `fetch-response` for that same sequence; do not replay the semantic action. Repeat fetch returns the retained bytes. A repeated sequence with different request content is BAD_MESSAGE. An effect is never repeated merely because its encoded response did not fit. A future retry after process failure is not implied by this in-memory guarantee; external effect correlation continues to use the existing stream protocol.

**Plain-data encoding:** the proposed private codec has one framing rule: `u8 tag | u32 payload-byte-length (LE) | payload`. The length excludes the five-byte header. There are **no inner element counts or text code-unit counts**. Parse exactly to the enclosing byte boundary; truncated nodes, excess trailing bytes, arithmetic overflow, malformed arity and duplicate/colliding map keys or set elements are BAD_MESSAGE. A top-level message is exactly one node. The following table fixes v1 payloads; implementations must not infer a format from their serializer defaults.

| Tag | Payload (no inner count) |
|---|---|
| 0 / 1 / 2 | Nil / false / true: length zero. |
| 3 | Exact integer: sign byte 0/1, then minimal big-endian unsigned magnitude bytes. Zero is sign 0 with no magnitude; negative zero and leading-zero magnitudes are noncanonical. |
| 4 | Float64: length exactly 8, IEEE-754 little-endian, with every NaN encoded as `00 00 00 00 00 00 f8 7f` (numeric bit pattern `0x7ff8000000000000`). |
| 5 | String: only UTF-16LE code-unit bytes, even byte length; empty string has length zero. No prefix count or implicit terminator; lone surrogates round-trip in this private domain. |
| 6 / 7 | Keyword / symbol: exactly two complete child nodes, namespace (nil or tag-5 string) and name (tag-5 string). Identifier validity follows the receiving value domain. |
| 8 / 9 | Vector / list: zero or more complete child nodes, in original sequence order, ending exactly at outer byte boundary. |
| 10 | Map: zero or more complete alternating key/value child nodes; odd child count is invalid. Canonical underlying-value order below is required. |
| 11 | Set: zero or more complete child nodes, in canonical underlying-value order below. |
| 12 | Metadata pair: exactly two child nodes, value then metadata. This private order does not replace Jing’s distinct `[meta value]` wire convention. |
| 13 | Checked task-local arena reference: length 8, u32 id then u32 generation, both LE. Never itself a value-order key. |

**Ordering independent of interning:** define expanded canonical ABI bytes of a plain value by recursively resolving every checked arena reference and encoding its value without tag 13. Map keys and set elements sort by unsigned lexicographic comparison of these complete expanded bytes (shorter prefix first); this comparator is a private ABI rule, not Jing’s ordering rule. Compute the order **before** choosing reference compression, including references nested inside compound keys. The actual emitted key/element may use a reference once sorted; decoder resolves definitions and verifies the same order. Reject duplicate canonical encodings and equality-collapsing members before constructing a host map/set. A missing/foreign reference is BAD_MESSAGE, never a numeric fallback sort key. Thus changing arena numbers, preinterning or inline-versus-reference representation cannot change entry order.

For a trusted non-plain value used as a key/element, obtain a pure, non-minting structural sort descriptor from the trusted value arena: kind plus owner/payload for Closure/Continuation, registered composition capability identity/profile for a primitive, kind/payload for a typed effect. Canonicalize the descriptor’s expanded value bytes under a distinct kind prefix, so a literal lookalike map cannot collide with a trusted type. It must contain no pointer, arena id or iteration-dependent id. Descriptor generation must neither lift resources nor allocate cursor/stream ids. W0 fixes descriptor tags alongside fixtures; a composition exposing an unnamed host callable must supply a stable capability identity for this private ordering (it remains non-portable on guest streams). Runtime-opaque values without such a descriptor cannot be advertised as supported ABI keys; this is an explicit capability admission failure, not unstable ordering or silent data loss. Trusted-value order descriptors never authorize minting the value from ordinary guest data.

**Float classification and round trips:** classify a CLJS Float64 carrier before testing exact-integer?, and use `yin.vm.integer.host/exact-integer?` semantics for plain numeric inputs: plain JS safe integers are integers, **-0.0 is not**. Decode every tag-4 node into `dao.jing.cbor/float64` or `float64-from-bits` on CLJS so 1.0 and +0.0 remain floating content; Rust retains a distinct Float64 variant. Preserve all non-NaN bits, especially negative zero and infinities. Encode every NaN payload/sign as the one quiet NaN above; reject a noncanonical NaN wire node as BAD_MESSAGE. This matches the existing canonical NaN conventions in the two repository codecs, without treating ABI bytes as their hash inputs. A plain JS Number 1 without a carrier cannot recover an earlier float distinction; fixtures must construct the carrier explicitly. Exact integers beyond the safe range remain tag 3 with exact magnitude. W0 tests value→wire→value→wire identity, including integer 1 versus Float64 1.0, ±0.0, infinities and multiple NaN payloads.


Messages are maps with ABI version, task id, sequence, acknowledgement, operation, input state revision, execution snapshot, argument values/references and newly defined arena values; responses carry sequence, output revision, execution status, result, post-service state and newly defined values or diagnostic. Every execution snapshot includes pc/registers/frames/K/store-of/value/halted/blocked, plus layout generation. Host-owned fields and immutable image/value data may be referenced by previously acknowledged definitions; missing or foreign definitions refuse. Mutation is represented by a new state revision, not mutation of a saved snapshot. Unknown extension fields in named state are preserved. W0 emits golden request/response bytes and locks required-field/type checks for each operation; both sides use those fixtures, not serializer defaults.

Arena-reference tag 13 is an internal task-scoped reference, not a portable value or a way for guest data to mint authority. Trusted capabilities (primitive, Closure, Continuation, typed effect, stream service) are installed by the composition or checked kernel constructors and recorded in the trusted arena. Generic literal decoding cannot create them. Plain-data descriptor maps in the service protocol may name a trusted constructor operation, but guest literal maps and FFI data never enter that operation channel. The native value service implements the same owner/type/arity and effect-authorization checks as the reference. External continuation export resolves arena refs to the payload values in §3 or refuses; it never exposes tag 13 as a guest transport representation.

**Required operations:** handshake/capability-profile negotiation; value definition/lookup and trusted closure/continuation minting; free-name/store/gensym services; primitive application with typed-effect authorization and the exact §2.4 completion; stream/effect/FFI transitions; scheduler-round and ready/parked restore; collection/pinning; admitted module attachment/spawn and closure/resource lift/lower. Each operation specifies its reference CLJC transition and read/write field set in W0. Requests carry the materialized state before any service that can collect. Pure body control, register moves and guest closure calls stay compiled; the service is not allowed to “run the remaining program” to manufacture the expected trace.

**Native implementation obligation:** implement this operation set in a host-language-independent semantic service library, initially Rust with separate Wasmtime and Wasmer runtime wrappers. Port the exact relevant transitions from the named CLJC authorities, including persistent values, primitive profiles, machine-data/continuation validation, scheduler ordering, custody gates, GC roots, module stores and FFI two-step. The Node adapter decodes the same bytes into current CLJS records and delegates to existing helpers. Native support is real execution using native services, not a recording replay, CLI-only wasm validation, JS subprocess or success-only primitive stub. Both adapters expose state and injected events as data for the same trace runner. Unsupported *external capabilities* return existing qualified outcomes; omitting required kernel services is a failed slice, not a permitted parity exemption.

The trade-off is explicit: every host-service invocation on every embedder serializes/deserializes linear-memory messages. Acknowledged immutable definitions reduce copying but do not bypass the ABI. W6 measures this cost and may move value/scheduler services into a self-contained wasm interpreter/runtime, leaving the ABI only at stream/FFI boundaries. That is an optimization axis, not a portability prerequisite or a claim of present speed.

### 4.1.2 Deterministic service traversal (shared prerequisite)

Source verification found real unsorted map/set walks that can mint ids or choose diagnostics. Rust must not reproduce them with its default map order, and canonicalizing only the final ABI bytes is too late. Introduce an explicit **shared deterministic traversal policy in the CLJC helpers and the native service**, then use that revised reference for wasm parity. This is a planned semantic stabilization of previously host-order-dependent behavior, not an already satisfied property of current source and not a wasm-only patch. No source edit is performed by this report.

For currently unordered traversal sites use a pure order key: for ordinary machine values, the fully expanded canonical ABI value bytes defined above; for trusted values, their non-minting structural descriptors. Sort maps by key and sets by element, using unsigned lexicographic comparison, never arena numbering, hash-table iteration or the output of a resource-lifting encoder. Build keys for a collection before invoking any id-minting traversal of that collection. Retain vector/list order, ordered exports, wait/ready queue order and first-occurrence deduplication. Retain **existing explicit source orderings** such as sort-by str on cursor ids/module-store addresses and sort-by key on attached image identities, with cross-host fixtures for those comparators; do not replace them with ABI order under the guise of fixing unordered maps.

| Site (existing symbols in engine.cljc unless qualified) | Required shared traversal change / preserved order |
|---|---|
| `encoder`, `encode-store` | Sort raw literal-map/store keys before visiting key then value; sort sets before recursively encoding. Never sort the already encoded output: `cell-for!` has already minted `:yin.k/c-N` by then. Keep vector/list and explicit export sequence order. |
| `markers` | Maintain pre-order tree walk; for maps visit values in sorted-key order (preserve the source’s values-only walk), for sets sort elements, for vectors/lists preserve sequence order. No incidental host map order may determine first stream discovery. |
| `lower-resources` | Preserve sorted used-cursor ids and the direct-stream-marker pass followed by cursor-derived streams; consume canonically traversed marker sequences, deduplicate by stream identity at first encounter, then mint gensym ids. Do not reorder queues or change aliasing of repeated cursor cells. |
| `receive-module` | Keep its explicit sorted image attach order. Enumerate slice values and fresh-store values in sorted-key order before lower-resources; use the same order for bindings/store decoding and deterministic error selection. Preserve slice-before-fresh-store phase order and first-link-wins stores. |
| `module/module-entries`, `module/list-modules` (module.cljc) | Walk registry child maps in sorted-key order and return top-level module names in that order. Missing-module `:available` vectors and registry consumers no longer inherit host map iteration. |
| `resume-from-run-queue` | Keep FIFO entry selection and terminal-check ordering; sort resource-update keys before selecting the first non-keyword diagnostic. Preserve updates and merge semantics. |
| `lift-slice`, `decode-store` and adjacent consumers | Preserve ordered export input; if a collection is a set, sort before visitation. Audit downstream unordered traversal for id minting, first-error choice or observable vectors, and route those paths through this policy. |

The helpers named above exist; the ordering policy/helper itself is proposed implementation work. It must land with shared CLJC/native regression tests before the corresponding W3/W4 acceptance gate. This deliberately can change old host-specific `c-N` assignments, stream ids/seals, slice-entry vectors or diagnostic order; record those deltas as the named prerequisite, never normalize them out. A fixed CLJS-only historical map order is not a cross-runtime contract. Existing canonical R/Jing hash algorithms and frozen byte corpora remain unchanged.

W0 inventories unordered observation sites and freezes order-key fixtures. W3 implements resource-update diagnostic order and validates counters/seals; W4 completes module lift/lower ordering and tests equal maps built with different insertion histories, small and large maps spanning CLJS map representations, nested maps/sets, repeated stream/cursor refs, multi-store modules and multiple invalid update keys. Compare exact minted ids, seals, `:yin.k/entries`, `:cells`, `:available`, counters and resource maps. A parity failure here blocks the slice; it cannot be hidden as implementation-private arena variation.

### 4.2 Stream and park transitions

Stream make/cursor/close finish without suspension under the current contract. Put-full and next-blocked create per-site wait entries using the same builders as register.cljc. Advance pc once, set blocked true/halted false/value `:yin/blocked`, and return to the scheduler. Explicit park instead produces the parked record as value and sets halted true; it is not automatically blocked and has no wait-set entry. The scheduler may still have other ready work.

Resume from a ready entry uses `engine/resume-from-run-queue`: pop FIFO entry, validate resource-update keys, merge updates into resources, clear flags, and handle terminal wake diagnostics before adapter restore. The same errors must occur whether a stream failed immediately or after blocking. Exported entries contain no callbacks, raw stream handles, timers, or stale service-mailbox data. `effects/wait-entry-defect` is an acceptance oracle only for its four newly built stream/FFI forms: put/next writers/readers and request-sent/call-id writer/reader entries. Do not apply it universally to the wait set: link-request, link-response, install and gated observe entries are outside its shape vocabulary. For these, check `effects/continuation-defect` on the register payload plus the owning module/engine reason-specific fields and transitions. Do not apply a newly parked-entry oracle to stale-key-bearing ready entries either.

### 4.2.1 Custody gates are preserved engine semantics

Retain `:yin.k/gate`, `:yin.k/issued`, `:yin.k/closes`, entry issue numbers, and every extension key across synchronization and public map edits. Use `vm/gate-mode` and existing engine/FFI/module handlers; do not replace them with one generic “gate means error” switch.

- Any gate suppresses `ffi/put-request` append and returns full, so FFI retains its request as a request-sent writer. Link misses likewise park as link-request without minting a response cursor or appending; already-resolved module and install-join branches still follow the handler’s ordering.
- Any gate suppresses autonomous link retry/response scans, FFI response polling, and put/next retries in `check-wait-set`. Gated install children are stamped/stepped only in running mode; ungated scheduling remains unchanged.
- Running stream cursor creation creates the sealed reference and unminted resource cell without a stream cursor call. Exporting/ended immediate observation paths refuse through the existing gate checks.
- Running put uses the engine’s deferred observation path and stamps a blocked writer with `:yin.k/issue`, advancing `:yin.k/issued` independently of id-counter. Running blocked poll becomes `:reason :observe, :op :poll`, using the call-site next builder fallback; its application remains the driver’s operation.
- **Current source nuance:** running stream close queues a record in `:yin.k/closes`, increments the issue counter, returns nil and does not call the stream handle. Exporting/ended close refuses. The review’s claim that close refuses under *any* gate does not match the current `handle-close` implementation.

W3 tests these transitions through both direct stream opcodes and effect-returning host calls, with scripted handle-call counts proving that deferred operations do not touch streams. W4 completes the module install/attach gate cases. Keep driver apply operations routed through their existing gate checks and the same synchronization barrier.

### 4.3 FFI two-step, without duplicate sends

1. `ffi/require-call-pair!` runs before allocating an id or parking. Read args in vector order, pin references, build the boundary payload, derive `ffi/call-id` from task identity and park-id, and park under that correlated id. Increment the shared id-counter once through park.
2. Build `apply2/request` and invoke `ffi/put-request`. On ok, enqueue response-wait-entry. On full, enqueue payload plus request-sent true, call-id, op, reason put, call-in stream id and the exact request datom. Other outcomes preserve the existing qualified error. Under any custody gate put-request returns full without appending; retain the request for the driver rather than retrying it autonomously.
3. The ungated engine retries a full writer. Its wake means the request append completed: restore converts it to a response reader, strips stale wake/writer fields through `ffi/response-wait-entry`, and stays blocked. It must neither append the request again nor advance the guest beyond the pending result.
4. On correlated response, terminal response-loss handling runs first, then call-result unwraps success/error, parked call-id is removed, and rd or tail return receives the result exactly once. Use constants from `yin.vm` for reserved resources.

Test full→ok→response, immediate ok→response, unrelated response ids, bridge exceptions, response loss, repeated scheduler polls, and two tasks with the same local counter. Keep the bridge in the existing host interpreter; do not implement wasm imports named after arbitrary FFI operations.

## 5. Modules and code growth

Compile each independently admitted image into a wasm Module whose body entry functions import the same ABI memory and services. Instantiate it for the receiving task and install its functions into the task's imported function table using the runtime embedding API. This table maps implementation body ids to uniform functions; it is not the guest offset table.

Attach is a staged, append-only transaction:

1. Apply the same contract/validator gates as `attach-image`. Empty images are no-ops; duplicate component R is a no-op. Production admission retains the existing A-to-R derivation check before executable attachment.
2. Compute offset = held instruction count. Relocate every operand whose opcode-table kind is `:pc`; shift body start/end. Compute the exact combined segment and `register-hash`, and append `[component-R offset length]`.
3. Compile/instantiate the new component, reserve directory/table capacity, install its body entries, then publish the new code-layout generation atomically. Prefer component-relative constants plus an instance base offset so the same compiled Module can serve different task layouts. Every pc generated from a component-relative coordinate adds the instance base exactly once before entering public state: header/exit pc, payload site/next pc, return-frame site/return pc, and minted closure body-pc. Incoming absolute restore/return pcs are already absolute and must not receive another base. Resolve absolute pcs through the combined body directory and subtract the selected body start for local dispatch.
4. Preserve pc, registers, frames, K, all pending payloads, stores, and queues. No existing function slot or instruction pc is renumbered; old compiled instances remain reachable. Failure before publish leaves the old task executable. Attach only while wasm is at a materialized boundary.

For every boundary payload, fetch the instruction as `(nth (:instructions (:segment vm)) (:pc vm))` from the current relocated **combined** segment at the materialized absolute site pc. Pass that instruction and current segment/hash/images to `effects/continuation-payload`; never pair component-relative site metadata or a component-only segment with absolute payload pcs. The cached component image is compilation input, not the current capture-time code space. Even where the live operand is numerically unchanged by relocation, all payload coordinates and validation context must agree.

An empty-image creation seeds `:images [[empty-R 0 0]]`, `:hash nil`, `:pc 0`, `:registers []`, and `:halted? true`. Attaching a nonempty image of length n at offset 0 keeps the empty row and produces `[[empty-R 0 0] [R 0 n]]`; it does not unhalt the task, resize registers, or initialize a body. Reset or a valid execution-entry transition performs that separate work. A later capture includes `:images` because the row count is two, even though only one row contains instructions. Keep the zero-length row in payload validation and layout operations; it is distinct from the rule that attaching an empty image is a no-op.

There is no machine-code patching and no need to grow an existing wasm Module's function section. The baseline preallocates table capacity (W0 test profile: 65,536 slots) and uses host table installation plus directory append for new functions; exhaustion is a qualified resource refusal. No guest `table.grow`/`table.set` instruction is required. Optional host-API growth must pass the W0 probe on each runtime and must not change the baseline module feature profile. Dynamic instantiation/attachment occurs outside an active exchange after returning a staged host-work result; the next synchronized state publishes the new layout. The same component bytes and import names are used on all runtimes. Old call frames use absolute return-pc and resolve in the grown directory. Captures retain their old segment/hash for validation, but resume sees the current code space. Reset preserves offset rows as in the kernel; load-image replaces the code space and resets execution, so old continuation membership checks can fail.

`spawn-module` creates a fresh task/memory/arena/owner/counter/resources context, with exactly the composition options copied by the existing kernel. It does not borrow the parent's mutable register shadow or per-module store. Reuse the module scheduler child-task lifecycle, encoder/decoder and `module/IModuleKernel` seams. Closure lifting uses image-relative body references and store-of; lowering validates binding/format, attached origin, and arity against actual closure instructions before minting the receiver's trusted value. Module store snapshots and authenticated stream/cursor lowering remain engine work. Cache compiled code by A, r2 derivation/checksum, wasm ABI/emitter version and feature profile; R alone is not executable admission authority.

## 7. Risks and open questions

1. **Native continuation transport is narrower than the prompt's broad wording.** The sources support same-model payloads and qualified transport refusal, while the module encoder currently refuses continuations. Keep this distinction visible in API docs/tests. A full portable continuation design would require separate authorization and compatibility work, not an ad hoc wasm-only decoder.
2. **Absolute pc layout compatibility.** The kernel's format check tests image membership, not complete receiving-layout equivalence. That suffices for grow-only same-task use; it is not proof that arbitrary imported absolute pcs mean the same thing. The transport adapter must enforce matching layout/prefix or use a separately specified rebaser. Preserve legacy restore diagnostics without presenting the legacy check as stronger than it is.
3. **Host boundary overhead.** A ValueRef implementation deliberately leaves semantic services in conforming embedders, with mandatory serialized messages even for CLJS. Measure whether compiled dispatch helps before moving collection/value/store services into wasm; the native host implementation needed for portability is already required by W1–W4. It remains a real lowering: instruction selection, register operands and branches are compiled, not fetched as bytecode by a host interpreter.
4. **Persistent public state over mutable memory.** Snapshot aliasing and old-state retention are correctness concerns, not just GC details. Decide in W0 whether each public state owns a copy-on-write arena root or a copied active shadow; require old-state replay tests before optimizing.
5. **Host exceptions and partial effects.** Catch host failures at the adapter boundary for shaped diagnostics, then reproduce the existing public exception behavior. Do not roll back an already appended stream event or retry a completed effect. The mailbox needs a single completion/commit rule.
6. **Module growth and code retention.** Wasm module code cannot be appended in place. Many image instances may increase memory and startup cost; function-table limits and compile failures require explicit resource refusals. Code unloading while live absolute pcs exist is out of scope.
7. **Large bodies and dispatch size.** One instruction per case can create deep block nesting and large binaries. W0 should pin practical limits; W6 can shard dispatch into bounded pages/helpers while keeping entry-pc precision. Such helpers must never hold suspended guest state in their native stack.
8. **Predicate drift.** machine-data?, value wrappers, integer carriers and effect authorization have evolved beyond old doc prose. Reuse the source helpers, and make ABI tests fail when their contracts change. External plain-data serialization and internal trusted-wrapper values are separate gates.
9. **Canonical admission and provenance.** Bare hand images remain useful under the existing raw kernel API; production module execution must retain A derivation verification. Compiled wasm caches are disposable artifacts. They cannot become another authority for code or continuation identity.
10. **Host coverage.** Node/CLJS and native Wasmtime/Wasmer are shipping targets under one pinned baseline ABI/profile. Browser and later JVM/Dart application integrations may have different resource limits and must rerun the same parity suite. Native semantic-service drift and ABI codec fidelity are the principal portability risks; uneven post-MVP feature support is already addressed by the deliberate baseline cut, not left as a speculative runtime requirement.

The implementation is complete when the same emitted baseline binary for an admitted r2 image has the same values, store transitions, continuation records, refusals, parking/wake behavior and module growth under Node, Wasmtime and Wasmer as under the existing register kernel, with full-trace parity and no suspended computation held on the wasm stack.
