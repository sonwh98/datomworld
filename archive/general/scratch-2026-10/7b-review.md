## What I checked, item by item

1. **`holder/export.cljc`.** `prepare`/`encode` lift through `rows/lift-task` with `:header`, `:source-index` and `:serve-keyed` (`rows.cljc` threads the task path through `install-node` so child answers are keyed `[['host.mod] sid]`). `encode`'s server throws on an unprepared key and never calls `serve!`. D4 is honoured: the lift serves during the walk, the `once` closure records every answer before the lift's post-walk refusal, and a retry is seeded by handle from the retained table through the machine's bindings (`seeded-by-handle`), so no successful serve repeats (mutant M13 killed by four tests). Recovery v2 carries exactly `{export-recovery, version, pack-address, root, pack-bytes, header, state}`; `state` is `{gate origins issues issued children}` recursively. No snapshot body, no descriptor set, no lease/epoch/holder (the header's `:yin.k/origin` carries the predecessor's lease as lineage evidence, which the plan allows; the pack never carries `:yin.k/enrolled`, pinned by test). The deviation from the plan's sketch (no `:yin.k/descriptors`) follows the owner's "only holder-local engine state beside the pack" and is sound: rehydration rebuilds the served table from the attached descriptors.
2. **Rehydration.** Order in `rehydrate-fenced`: tag/version, recovery address, `checkpoint/inspect` (pack address vs bytes, carrier, custody grammar), root equality, `check-header!`, `header-agrees?` against the inspected custody, `valid-state?` against the decoded tree, then `lower-task {:fenced true}`. All before the first `attach` (tests pin `before = @attaches`). The fenced lower carries `id-counter` exactly (M03 killed, 68 assertions), builds `:yin.k/recovery-cell-ids` from the census, moves waits and parked records out of the scheduler (M04 killed), gates every task `:exporting`; `extract-recovered` restamps issues and strips custody/closes/counters from the receiver. Zero program IO: M02d (ungated poll of the recovered waits) killed by six tests; M02b (rows-level fenced gate dropped) killed by `rows-custody-test` only, because `extract-recovered` re-asserts the gate itself (defence in depth, not a gap). `:make-stream` is nilled on a copy of the receiver passed to `spawn-module` and restored on the child; nothing is mutated, so there is no leak on exception. The recovered record re-encodes the published pack byte for byte (every rehydration test asserts `reproduces?`); a reordered-row pack of the same root is refused `:recovery-inconsistent`. Abort of a recovered record is refused `:restarted` (M05 killed).
3. **Q3 install checks.** `check-install!` requires `parent = (:yin.link/id response)` and a `:derivation` record whose address is the manifest's `:yin.semantic/code` entry, whose input is the manifest's tree and whose output is `segment-key` of the delivered image. The response shape (top-level `:manifest`, `:derivation`, `:image {:value}`) is exactly what `yin.vm.engine` reads at install (engine.cljc 1209, 1295, 1394) and what `linker/link-manifest` emits (`linked-image` merges `:manifest`, `:derivation`, `:trust` beside fetch's `:image`), so a valid linker-produced install is not refused; `:trusted` links also carry the record. A forged install passes only if manifest, record and image are mutually consistent: the check is self-consistency within the response, which is what the owner asked for ("image address = the manifest's"); binding the manifest to a composition-known address is the linker's admission, not the lower's. M06 and M07 (each check removed whole) killed; the three conjuncts of the image check separately: tree input (M07b) and image output (M07c) killed, record address (M07a, M07a2) **survived**, see F2.
4. **The driver.** `lowered` wraps `rows/lower-task` with the refusal-as-data contract; `lower` passes `:exclusive`, `:protection`, `:grant {:checkpoint address ...}`; `step-validating` inspects first, then lowers under `:exclusive` with no grant (awaiting-grant before any attachment; halted → `:safepoint` ended); `rebuilt-cell` checks `:yin.k/pack-address`, header equality, bytes vs base64 pack, then `rehydrate-fenced` and re-encode equality; `reopen-holder`/`reopen-exit` read kind/occurrence through the rows inspector. `:export-version` is gone from `driver.cljc` and `compose.cljc` (seam list, `bare-composition`, `driver-config`, docstrings); `source-index` is a required composition seam (`check!`) and a required driver seam. Occurrence minting and journaling precede prepare (unchanged `source-mint`/`exit-mint`); `export-fence-step` stores the recovery object first, then the pack (M11 **survived** at the test level, see F1); journal vocabulary unchanged, and renaming a journal tag or the store action (M12a/M12b) is refused by the driver's closed frame vocabulary so loudly that the test process cannot even load the suite (killed at process level).
