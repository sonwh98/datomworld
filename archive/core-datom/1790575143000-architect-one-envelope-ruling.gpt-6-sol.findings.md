## Ruling

Converge **the application wire vocabulary** on `dao.stream.apply`. Keep `dao.stream.apply` as the open envelope contract and `dao.stream.rpc` as the client driver. This is a small breaking change while the rpc vocabulary is newly landed and gated; a compatibility shim would leave two accepted wire languages and prolong the drift this ruling is meant to end.

There are two corrections to the proposed direction. First, the present rpc client has random safe ID allocation and tracks outstanding requests, but it has **no numeric cap on the outstanding map**: `request!` allocates whenever there is no retained unsent request, and acceptance adds an entry to `:outstanding` without a size check ([rpc.cljc:212](/Users/sto/workspace/datomworld/src/cljc/dao/stream/rpc.cljc:212), [rpc.cljc:233](/Users/sto/workspace/datomworld/src/cljc/dao/stream/rpc.cljc:233), [rpc.cljc:254](/Users/sto/workspace/datomworld/src/cljc/dao/stream/rpc.cljc:254), [rpc.cljc:301](/Users/sto/workspace/datomworld/src/cljc/dao/stream/rpc.cljc:301)). Add an explicit, caller supplied positive outstanding limit, with a documented finite default. At the limit, return a local backpressure outcome without allocating an ID or appending a request. Second, “plain apply envelopes” describes the **values on the request and response streams**; the lower `dao.stream.remote` protocol still wraps stream operations in its own id, identity, and outcome envelope ([remote.cljc:48](/Users/sto/workspace/datomworld/src/cljc/dao/stream/remote.cljc:48), [remote.cljc:138](/Users/sto/workspace/datomworld/src/cljc/dao/stream/remote.cljc:138)). It must carry the apply value verbatim.

**Errors.** Keep transport or client failures as rpc completion reasons unless a server is actually sending an application error response. Define distinct, stable apply-qualified reason words for `not-found`, `detached`, `ended`, `no-surface`, `oversize`, and `transport-error`. Map remote `no-surface` to `:dao.stream.apply/no-surface` and remote `oversize` to `:dao.stream.apply/oversize`; do not collapse them into the generic transport reason. `no-surface`, `oversize`, `not-found`, and `ended` are terminal for that binding; `detached` alone permits rebind; a generic transport failure follows the existing terminal path. The current mapping distinguishes only `not-found` and `channel-gone`, while `rebind` already accepts only `detached` ([rpc.cljc:432](/Users/sto/workspace/datomworld/src/cljc/dao/stream/rpc.cljc:432), [rpc.cljc:445](/Users/sto/workspace/datomworld/src/cljc/dao/stream/rpc.cljc:445), [rpc.cljc:568](/Users/sto/workspace/datomworld/src/cljc/dao/stream/rpc.cljc:568)). **Identity.** An apply response requires its correlation ID, not a stream identity. Keep it that way: an application envelope can be used over a local pair with no remote identity ([apply.cljc:89](/Users/sto/workspace/datomworld/src/cljc/dao/stream/apply.cljc:89)). A *remote protocol answer* already names `:dao.stream/identity`; its reflection must accept it only when **both** the ID and identity equal those of the outstanding request. Enforce that in `remote/absorb!` before removing the outstanding entry, marking a reflection gone, filing an answer, installing `more`, or emitting an append outcome. A mismatch is a diagnostic, leaving the legitimate request outstanding. The mirror echoes the request identity, but `absorb!` currently looks up only by ID ([remote.cljc:82](/Users/sto/workspace/datomworld/src/cljc/dao/stream/remote.cljc:82), [remote.cljc:401](/Users/sto/workspace/datomworld/src/cljc/dao/stream/remote.cljc:401)). This is correlation integrity within the remote protocol, not authentication of whoever can write to the channel.

## Serving and end-to-end acceptance

The serving composition creates the call-in and call-out media, mints their cursors from their actual handles, registers each handle and declared surface in its remote mirror table, and retains that table, channel, cursor, and any lease for as long as the call can be resumed. The remote mirror serves stream operations; the FFI interpreter reads apply requests and appends apply responses. `apply/serve-once!` already takes caller-owned cursor state, retains a computed response across `full`, and never mints a cursor itself ([apply.cljc:217](/Users/sto/workspace/datomworld/src/cljc/dao/stream/apply.cljc:217), [apply.cljc:301](/Users/sto/workspace/datomworld/src/cljc/dao/stream/apply.cljc:301)). The mirror likewise holds only its returned channel cursor and forwards the served stream’s cursors ([remote.cljc:185](/Users/sto/workspace/datomworld/src/cljc/dao/stream/remote.cljc:185)).

Specify the UCF `serve!` callback as **idempotent per live handle within one export binding**: repeated calls return the same identity and channel and refer to the same table entry; retirement or lease reclaim ends that binding explicitly. `lift-frame` can call `serve!` while minting cells and again while lifting entries, so unstable markers would break a single frame ([ucf/remote.cljc:217](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:217), [ucf/remote.cljc:435](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:435)). Implement a production composition that owns this registry and its lease lifecycle; the UCF facade only accepts the callback and makes remote descriptors from it ([ucf/remote.cljc:37](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:37), [ucf/remote.cljc:144](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:144)). A refusal returns `nil` before publishing a lift, as the facade specifies ([ucf/remote.cljc:41](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:41)).

“VM FFI call answered remotely, end-to-end” is accepted only when a real VM call emits its original apply request; the remote serving composition exposes its call-out request stream to an rpc-driven responder; that responder reads the **unchanged** request, appends a valid apply success or error to the response stream; and the VM resumes or raises the corresponding error through `yin.vm.ffi/call-result`, with the same ID and any extra request keys preserved where the request is retained or transported. Verify pending append retries, response `full`, gap, detach and rebind, terminal not-found, and UCF lift/lower of a retained call. The VM already constructs apply requests and checks apply response correlation ([semantic.cljc:467](/Users/sto/workspace/datomworld/src/cljc/yin/vm/semantic.cljc:467), [ffi.cljc:88](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ffi.cljc:88)); UCF already carries a retained request envelope verbatim ([ucf/remote.cljc:328](/Users/sto/workspace/datomworld/src/cljc/yin/vm/ucf/remote.cljc:328)).
