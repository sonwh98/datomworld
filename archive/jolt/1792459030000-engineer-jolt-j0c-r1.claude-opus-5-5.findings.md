## R3: the wrapper and the jolt call (DONE)

- **Location:** `native/jolt-parser/` (`CMakeLists.txt`, `jolt_parser.cpp`). It is a new top-level directory for hand-written native sources:
  - not `src/`, whose roots are Clojure source roots on jolt's classpath;
  - not `antlr/`, which holds only pinned grammar inputs and manifests;
  - not `build/`, which is for generated and untracked output.
- **ABI** (`extern "C"`, C types only):
  - `int32_t jolt_parser_parse(const uint8_t* src, size_t len, uint8_t** out, size_t* out_len)`
  - `void jolt_parser_free(uint8_t*)`
  - `int32_t jolt_parser_layout_version(void)`
- **Error handling:** every entry catches `std::exception` and `(...)` and returns −2/−3 with a message buffer. −1 means invalid arguments, −4 means over the 64 MiB output bound.
- **Buffer layout:** private, fixed-width, little-endian: magic `JPT1`, layout version, status, rule-name table, symbolic-name table, preorder records, collected listener errors. The full layout is documented in the source header.
  - Each rule record carries its index and child count. Each token record carries type, code-point start/stop and UTF-8 text.
  - This is raw marshalling only: no Jing encoder, no `toStringTree`, no packet. It is a subset of the §7.3 field list (first-failure evidence and context start are later).
- **Build:** `bb build:jolt-native` links `libjolt_parser.dylib` against the pinned static runtime and the generated sources (`r3-build.log`, exit 0, 49.95 s).
  - SHA-256 `fd8ac980a123ac9610743d36c12930bc539de1b40edb2e649f40f9e4b8f9df76`, **identical across three builds**. Mach-O arm64, 1,356,232 bytes, depends only on `libc++` and `libSystem`.
  - **Finding:** `CXX_VISIBILITY_PRESET hidden` applies only to my own translation units. The three `jolt_parser_*` entries plus about 1,556 `antlr4::` C++ symbols from the static archive are exported (`nm -gU`). A later round should use an exported-symbols list (`-exported_symbols_list` / a version script) so the runtime cannot interpose or be interposed.
- **jolt side** (`src/dev/jolt_parser_probe.clj`, run with `"$JOLT_HOME"/bin/jolt -Srepro -M:jolt src/dev/jolt_parser_probe.clj`):
  - **Load and bind:** `ffi/load-library` loads the dylib by absolute path. `(ffi/defcfn c-parse "jolt_parser_parse" [:pointer :size_t :pointer :pointer] :int :blocking)`, plus free and version.
  - **Call:** `parse-bytes` copies the UTF-8 source into an `ffi/alloc` buffer and calls the parser. It copies the result with `ffi/read-array` into a jolt byte array, frees it through `jolt_parser_free` in a `finally`, and frees its own cells. No pointer leaves the function.
  - **Decode:** the decoding is plain Clojure over the byte array.
- **Result for `"1 + 2\n"`:** status 0, a 3196-byte buffer consumed exactly, parse call 2.7–3.6 ms. The decoded tree:


- **Checks: 7/7 PASS** on three runs (`r3-probe-1.log`, `r3-probe-2.log`, `final-probe.log`):
  - the layout version is 1;
  - magic, layout and exact consumption;
  - no errors;
  - the root is `file_input`;
  - the token sequence with code-point spans `NUMBER 1 [0,0]`, `ADD + [2,2]`, `NUMBER 2 [4,4]`, `NEWLINE [5,5]`;
  - the last token is EOF;
  - malformed `"1 +\n"` returns status 0 with a syntax-error buffer of two listener errors (`no viable alternative at input '+'` at 1:2, `extraneous input '\n' …` at 2:0), and no exception crosses the boundary.
- **One iteration fixed:** the first run failed the EOF check because ANTLR's EOF type is −1 and my decoder looked only in the non-negative symbol table. The probe now names −1 `"EOF"`, as the packet contract does. The wrapper was unchanged.
- **Not compared against the JVM yet.** The NEWLINE span `[5,5]` comes from the ported positioned patch, and the EOF span `[6,5]` (zero-width at index 6) is plausible but unchecked.

## Collect-safety observations (nothing built on `:blocking` semantics)
