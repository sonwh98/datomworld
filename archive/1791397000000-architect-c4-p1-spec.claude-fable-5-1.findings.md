## 1. Foundations, invariants and boundaries

### 1.1 What P1 is

P1 changes when and by whom the prelude's runtime state is allocated, and
where guest code finds the builtins. It does not change what any Python
program prints. The bundled profile stays the only profile (ruling 5):
every program tree still carries its own prelude copy, and `isinstance`
across units still fails, as section 8.5.1 records. P1 is the last
reshaping of `prelude.cljc` before P2's module emitter, so its one
structural promise is that P2 adds an emitter and changes nothing in the
definition list.

### 1.2 Invariants P1 must keep

- I1, output parity. Every C1, C2, C3 and safepoint program prints the
  same text and raises the same exception on every VM (AST walker,
  semantic, stack, register) on JVM, Node and Dart. Rendered output is
  the only guest-visible surface; addresses are not.
- I2, defining runs nothing. `functions-uast` loads on a composition with
  no `cell`, `data` or `integer` module and halts ok. After P1 it
  contains one more kind of form than lambdas: literal definitions
  (section 3.2). A literal allocates nothing.
- I3, canonical references inside the interpreter. Prelude bodies and the
  hook prelude keep reading builtin classes by store key (`py.b/TypeError`
  and so on). Rebinding or mutating a builtin name from guest code never
  changes which class an interpreter-generated exception carries
  (ruling 2).
- I4, Python's own lookup order. A module-level name resolves in the
  module dict, then in the builtins dict, then is `NameError`. A present
  module key always wins. Deleting the module key restores the builtin.
- I5, one Python process is one task. The builtins dict, the three
  runtime cells and the class cells are allocated once per task by
  `py/init!`, never per module and never per call.
- I6, idempotence. A second `(py/init!)` in the same task observes the
  flag the first set and allocates nothing: the same class cells, the
  same function cells, the same builtins dict, the same three runtime
  cells, by cell-ref identity.
- I7, no new host seam. `host-names` is unchanged. `py/init!` needs only
  `cell/new` and the `py/*` functions. `admit` still proves the
  composition before any program runs (ruling 7's end-to-end profile
  enforcement is L-a, P2's prerequisite; P1 adds nothing to it and
  removes nothing from `admit`).
- I8, no lowering knowledge of builtins. After P1 the lowering has no
  table of builtin names and emits no `py.b/*` variable. Adding a builtin
  class or function touches one table in `prelude.cljc` and no other
  file (section 8.5.6, "a new builtin class no longer touches the
  lowering").
- I9, `yin/def` discipline. `yin/def` appears only inside the prelude
  tree (the lowering's `program-shape-test` keeps asserting it), and
  only with a literal symbol key (Rule R).

### 1.3 Boundaries

- Below the prelude: the VMs, the encoder, the linker and the
  `yang.safepoint` stage are untouched. If a VM turns out to refuse or
  mis-handle a definition inside a lambda body or a redefinition of a
  key, that is a VM defect to report, not something to route around in
  the prelude (section 5, step 0 probes it first).
- Beside the prelude: `safepoint.cljc` is untouched. Its reads of
  `py.rt/*` and `py.b/*` resolve at hook run time, after `py/init!` has
  defined them (the wrapper calls `py/init!` before `py/run-module`, and
  every hook site is inside the module body).
- Above the prelude: the REPL is not involved (F2 and F3). No `import`,
  no `sys`, no `builtins` module (I1 and later). No `del` statement
  (still refused by the lowering); the only module-level unbinding the
  lowering emits is the `except E as name` cleanup, which P1 uses as its
  Python-level shadow-then-delete probe.
- Not in P1: the module emitter, namespace stripping, publication, the
  linked wrapper's `require`, `py/run-main`, `sys.modules`, the hook
  prelude's `attach!`, cross-module exception identity (its test is P2's,
  because it needs two units sharing one task's prelude).

## 2. Semantics

### 2.1 `py/init!`

Signature: `(py/init!)`, a prelude function of no arguments, value
`:py/None`.

Precondition: `functions-uast` has loaded (every `py/*` function and the
literal slot `py.rt/state` are defined) and the composition supplies the
cell module. The wrapper guarantees the first; `admit` the second.

Effect, when `py.rt/state` reads `:py/uninit`:

1. Define the three runtime cells, with today's initial contents:
   `py.rt/ctx` as `(cell/new (py/ctx nil 0 0 nil))`, `py.rt/limit` as
   `(cell/new 1000)`, `py.rt/out` as `(cell/new [])`.
2. Define every builtin class, in `builtin-classes` order, each as
   `(yin/def py.b/<Name> (py/make-class "<Name>" <base-key-or-None>))`,
   `StopIteration` wrapped in `py/stop-iteration-class` as today. Order
   matters: a base is defined before its subclass, as the table already
   guarantees.
3. Define every builtin function and every method implementation, in
   table order, each `(yin/def py.b/<key> (py/make-function ...))` with
   today's forms.
4. Define `py.b/builtins` as a fresh Python dict (`py/dict-new`) and seed
   it, in order: every Python-visible class from `builtin-classes`, then
   every Python-visible function from `builtin-functions`
   (section 3.1), by `(py/dict-set py.b/builtins {:py/str "<name>"}
   py.b/<key>)`. Method implementations (`list-append`, `set-add`,
   `dict-*`, `gen-*`) are not Python names and are not seeded.
5. Define `py.rt/state` as `:py/ready`. This is the last write, so a
   host failure part-way through (a composition that passed `admit` but
   whose cell module refuses, say) leaves the slot at `:py/uninit`; the
   task has failed anyway, and no half-initialized prelude ever reports
   ready.

Effect, when `py.rt/state` reads anything else: none. Value `:py/None`.

Failure behavior (the design's "defined failure behavior"): `py/init!`
has no guest-catchable failure. Every failure is a host failure of the
run, before any guest statement executes, and the only reachable one is
a missing host export, which `admit` refuses earlier by name. There is
no partial-success state visible to guest code because no guest code
runs before the wrapper's `(py/init!)` returns.

Where the writes land: each `yin/def` inside the `py/init!` body goes
through `engine/put-active`, which writes the task's own store today
(bundled, no `:store-of`) and the prelude's own module store under P2
(a closure carrying `:yin.k/store-of py`). This is the design's sentence
"`py/init!` initializes the prelude's own active module store once,
idempotently" taken literally, and it is why P2 can reuse the P1 body
unchanged.

### 2.2 The state slot

`py.rt/state` is the single slot the design names ("writes one state
slot"). It is defined in the pure definition list as the literal
`:py/uninit`, which allocates nothing (I2, and P2's empty-heap install
child), and `py/init!` redefines it to `:py/ready` as its final act. The
runtime cells and class cells stay separate store keys rather than
fields of a record in the slot, for three reasons: every prelude body,
the hook prelude and several tests already read them by key; a free
store read is cheaper than a record lookup on every handler push and
every raise; and section 8.5.6 itself says `py/init!` initializes the
module store, which is a set of keys. The slot is the idempotence flag,
not a container.

### 2.3 The builtins namespace dict

`py.b/builtins` is an ordinary Python dict cell (`{:py/type :dict :index
:keys :vals}`), one per task, created and seeded by `py/init!`. Its keys
are `{:py/str name}` values, the same key shape as a module dict, so
`py/global-get` reads both with the same index lookup and no
normalization difference can arise.

Insertion order is the seeding order (classes in table order, then
functions in table order), deterministic on every host, so a later
`dir(builtins)` or `builtins.__dict__` (I1 or later) renders the same
text everywhere.

Guest mutation: nothing in P1's Python surface reaches the dict (no
`builtins` module, no `__builtins__`). The prelude-notation tests mutate
it directly to prove ruling 2's two claims: a mutated entry is what
`py/global-get` falls back to, and interpreter-generated exceptions keep
their canonical class regardless (I3).

### 2.4 Global lookup

`py/global-get g n` becomes:

```clojure
[py/global-get
 ;; a module-level read: the module dict, then the task's builtins, then
 ;; NameError (Python's LOAD_GLOBAL)
 (fn [g n]
   (let [c (cell/get g)
         slot (get (get c :index) n :py/missing)]
     (if (= slot :py/missing)
       (let [b (cell/get py.b/builtins)
             bslot (get (get b :index) n :py/missing)]
         (if (= bslot :py/missing)
           (py/raise-new py.b/NameError
                         (py/str (data/str-concat "name '" (get n :py/str)
                                                  "' is not defined")))
           (get (get b :vals) bslot)))
       (get (get c :vals) slot))))]
```

`py/global-or g n fallback` keeps its three-argument shape and its
meaning (module dict, else `fallback`) and is used for exactly one name
after P1: `globals`, whose value is the per-module function object
`%globals-fn` that `py/run-module` builds. `globals` cannot live in the
shared builtins dict because its value differs per module. The lowering
special case for `globals` therefore stays; it is not a `py.b/*` read.

`py/global-set` and `py/global-del-quiet` are unchanged: they write and
delete module dict keys only. The builtins dict is never written by a
module-level assignment or unbinding, which is what makes shadow then
delete restore the builtin (I4): the assignment adds a module key that
wins; the deletion removes it; the next read misses the module dict and
finds the builtin again.

`py/class-ns-get cls name fallback` is unchanged; its `fallback` thunk is
the lowered `read-global`, which now ends in the dict path.

### 2.5 The lowering

`read-global` loses its first branch:

```clojure
(defn- read-global
  "A module-level read at run time: the module dict, then the task's
   builtins (`py/global-get`); `globals` is the module's own function
   object, so it is the one name read with a fallback the lowering
   supplies."
  [_n name]
  (if (= "globals" name)
    (app* 'py/global-or (u/v globals-sym) (global-key name) (u/v globals-fn-sym))
    (app* 'py/global-get (u/v globals-sym) (global-key name))))
```

`prelude/builtin-names` is deleted; nothing else in `lower.cljc` changes.
`lower-packet` keeps its shape `(then prelude/uast (py/run-module ...))`
because `prelude/uast` itself becomes "functions, then `(py/init!)`"
(section 3.3), which is the bundled reading of the design's linked
wrapper `(do (require 'py) (py/init!) (py/run-main ...))`.

`py/run-module` is unchanged in P1. It still resets `py.rt/out` and
`py.rt/ctx` on entry; those resets are redundant after `py/init!` for a
fresh task and harmless, and F3's persistent `__main__` is the slice
that revisits them.

### 2.6 What the guest observes

| Program | Before P1 | After P1 |
|---|---|---|
| `print(len([]))` | `global-or` reads store key `py.b/len` | `global-get` misses the module dict, finds `len` in the builtins dict |
| `len = 1; print(len)` | module key wins | module key wins |
| `except E as len: ...` then `print(len([]))` | handler exit deletes module key `len`; next read is `global-or` with the store builtin | handler exit deletes module key `len`; next read falls back to the dict |
| `print(map)` (not provided) | `global-get` raises `NameError` | `global-get` raises `NameError` from the dict miss, same text |
| `class C: x = len` | class dict, then `read-global` | class dict, then `read-global` via the dict |

No row changes its output. Section 4 pins each.

## 3. Data structures and the refactoring plan

### 3.1 Tables in `prelude.cljc`

Keep `builtin-classes` as it is: `[["object" py.b/object nil] ...]`, each
row `[python-name store-key base-store-key-or-nil]`. Every row is
Python-visible.

Split today's `builtin-function-definitions` into two tables by
visibility, since the single definition list must know which keys become
Python names without a second hand-kept map:

- `builtin-functions`: rows `[python-name store-key form]`, the
  twenty-five Python-visible functions today's `builtin-names` lists
  (`len`, `isinstance`, `hash`, `divmod`, `print`, `range`, `list`,
  `tuple`, `set`, `sum`, `any`, `all`, `next`, `iter`, `int`, `float`,
  `str`, `repr`, `bool`, `abs`, `pow`, `round`, `hex`, `oct`, `bin`), with
  their existing `py/make-function` forms moved verbatim.
- `method-implementations`: rows `[store-key form]`, the function objects
  `py/getattr` and `py/gen-attr` hand out (`list-append`, `set-add`,
  `dict-items`, `dict-keys`, `dict-values`, `dict-get`, `gen-send`,
  `gen-throw`, `gen-close`, `gen-next`, `gen-iter`), forms verbatim.

A sanity check in the parity test derives the set of seeded names from
these two tables and compares it with the twenty-five plus the class
names, so the split cannot silently drop a builtin.

### 3.2 The single definition list

`definitions` (public; rename of `function-definitions`, keep the old
name as nothing more than an alias only if a test outside this slice's
reach still reads it, otherwise rename the two test reads) is one vector
of `[store-key form]` in this order:

1. every row of `core-definitions` (unchanged, still a quoted literal);
2. `[py.rt/state :py/uninit]`, the literal slot;
3. `[py/init! <generated form>]`.

Item 3 is built by a private Clojure function `init-form` from the three
tables:

```clojure
(defn- define
  "`(yin/def (quote key) form)` in prelude notation: the key quoted, so
   `sexp->uast` reads it as the literal symbol Rule R requires."
  [key form]
  (list 'yin/def (list 'quote key) form))

(defn- init-form
  "`py/init!`'s body: every definition `state-definitions` held, then
   the builtins dict seeded from the tables, then the ready flag, under
   the uninit guard."
  []
  (list 'fn []
        (list 'if (list '= 'py.rt/state :py/uninit)
              (concat
                ['do
                 (define 'py.rt/ctx '(cell/new (py/ctx nil 0 0 nil)))
                 (define 'py.rt/limit '(cell/new 1000))
                 (define 'py.rt/out '(cell/new []))]
                (mapv (fn [[nm key base]]
                        (define key
                          (cond->> (list 'py/make-class nm (or base :py/None))
                            (= "StopIteration" nm) (list 'py/stop-iteration-class))))
                      builtin-classes)
                (mapv (fn [[_ key form]] (define key form)) builtin-functions)
                (mapv (fn [[key form]] (define key form)) method-implementations)
                [(define 'py.b/builtins '(py/dict-new))]
                (mapv (fn [[nm key _]]
                        (list 'py/dict-set 'py.b/builtins {:py/str nm} key))
                      builtin-classes)
                (mapv (fn [[nm key _]]
                        (list 'py/dict-set 'py.b/builtins {:py/str nm} key))
                      builtin-functions)
                [(define 'py.rt/state :py/ready)
                 :py/None])
              :py/None)))
```

Notes for whoever types this. `u/sexp->uast` has no `yin/def` arm
despite its docstring: `(yin/def k v)` is read as an application of the
variable `yin/def` to the *variable* `k`, which Rule R's definition-shape
check refuses. The key must be `(quote k)`, as `int_heap_test` already
writes it; `define` above does that. Do not add a `yin/def` arm to
`sexp->uast` in this slice (it would have to accept both spellings and
is not needed). The `:py/str` literal maps and the `:py/uninit` keywords
fall through `sexp->uast`'s `:else` to literals; `mapv`, not `for`,
because this Clojure runs on Dart at load (the `for` over a chunked seq
trap). The outer `if` has an explicit `:py/None` alternate because
`sexp->uast`'s `if` takes three forms. The top-level rows of
`definitions` still go through `definitions->uast`, which uses `u/def!`
and needs no quoting.

`state-definitions` is deleted. `definitions->uast` stays as it is.

### 3.3 The two trees

```clojure
(def functions-uast
  "Every definition: lambdas and the literal state slot. Defining them
   runs nothing, so this loads on any composition, with or without cells."
  (definitions->uast definitions))

(def uast
  "The bundled prelude: every definition, then the task's runtime state
   allocated by `py/init!`."
  (u/then functions-uast (u/sexp->uast '(py/init!))))
```

`functions-uast` is what P2's module emitter will take (with the `py`
namespace stripped from keys and internal references); `uast` is the
bundled emitter's output, and `(py/init!)` is the call the linked entry
wrapper makes. One source, two emitters, as section 8.5.6 says.

Every consumer of `prelude/uast` (the lowering, `int_ops_test`,
`int_conv_test`, `int_literal_test`, `int_contract_test`,
`prelude_parity_test`, `lower_test`, `float_address_test`, `e2e_test`'s
`closed-names`) keeps working unchanged: after `uast` loads, the store
holds `py.rt/ctx`, `py.rt/out`, `py.b/ValueError`, and every other key
those tests name, exactly as before. Every consumer of `functions-uast`
(`int_heap_test`, `prelude_parity_test`, `float_address_test`) keeps
working: the forms they run do not raise, so they never reach a `py.b/*`
key.

### 3.4 `builtin-names` and `host-names`

Delete `builtin-names`. `host-names` is unchanged (I7). `min-integer-bits`,
`register-integer-module`, `admit` are unchanged.

## 4. Acceptance criteria and test obligations

Every test below runs on all four VMs; `.cljc` tests run on JVM, Node and
Dart. The four acceptance bullets of section 8.5.6 row P1 (lines 3099 to
3102) are A1 to A4.

### A1. Full corpus output unchanged on every VM and host

Obligation: every existing test in `test/yang/python/antlr/` passes with
no change to any expected `{:py/out :py/exception}` value. The only
permitted edits to existing tests are the four structural ones listed in
section 4.6. Evidence: `bb test` green on all three lanes, plus
`clojure -M:test -i :slow -n <ns>` for each changed Python namespace
(the slow e2e, e2e-c1, prelude-parity, safepoint, float-address and
int-contract sets), per `docs/agents/build-n-test.md`.

### A2. A composition with no cell module halts ok on `functions-uast`

New test, `prelude_parity_test.cljc`, `functions-load-without-cells-test`:
build each of the four VMs over `{:modules (module/empty-registry)
:primitives vm/primitives ...}` (no cell, data or integer module; model
it on `safepoint_test/hook-prelude-loads-alone-test` and `on-every-vm`),
run `prelude/functions-uast`, and assert `[(vm/halted? vm)
(vm/blocked? vm)]` is `[true false]` and nothing throws. This proves the
literal slot and the `py/init!` lambda allocate nothing at load.

### A3. `py/init!` twice yields one set of class cells

New test, `prelude_parity_test.cljc`, `init-is-idempotent-test`, in
prelude notation after `prelude/uast` (so `py/init!` has already run
once by the wrapper):

```clojure
(let [c1 py.b/ValueError
      f1 py.b/len
      b1 py.b/builtins
      ctx1 py.rt/ctx
      out1 py.rt/out
      lim1 py.rt/limit
      s1 py.rt/state
      _ (py/init!)
      _ (py/init!)]
  (py/conj ... [(= c1 py.b/ValueError) (= f1 py.b/len) (= b1 py.b/builtins)
                (= ctx1 py.rt/ctx) (= out1 py.rt/out) (= lim1 py.rt/limit)
                (= s1 :py/ready)
                (= (py/global-get (py/dict-new) {:py/str "ValueError"}) c1)]))
```

Expected: every element `true`, on every VM. Cell refs compare by
identity through `=`, so a re-allocation would show as `false`. Add a
second clause: the state slot read before any `py/init!` (run under
`functions-uast` alone) is `:py/uninit`.

### A4. Shadowing then deleting a builtin name makes the builtin visible again

Two tests, one at each level.

Prelude level, `prelude_parity_test.cljc`, `shadow-then-delete-builtin-test`:

```clojure
(let [g (py/dict-new)
      a (py/global-get g {:py/str "len"})
      _ (py/global-set g {:py/str "len"} 1)
      b (py/global-get g {:py/str "len"})
      _ (py/global-del-quiet g {:py/str "len"})
      c (py/global-get g {:py/str "len"})
      d (py/try (fn [] (py/global-get g {:py/str "nosuch"}))
```
