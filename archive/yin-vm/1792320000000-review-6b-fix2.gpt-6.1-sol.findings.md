## Reachability and context assessment

`live-pcs` follows `analysis/successors`, whose return, halt, resume and tail-call instructions terminate control flow. It adds each reachable closure's body entry to the same worklist, so nested closure construction is followed transitively. Closure creation captures the current E in the evaluator; answering a future closure's free occurrences against the creating context is consistent with that behavior. `scan/free-occurrences` removes lexical binders through the enclosure chain.

Existing carried closures do not depend on reaching their constructor again: `closure-node` records an independent entry/E context whenever `lift-value` encounters them. This includes closures in the result, windows, E, free-env, root store and transitively discovered module stores. Module-store discovery finishes before discharge. Separate probes show a nested future closure and a closure retained for later invocation through a captured binding both refuse missing `ghost`; a valid nested future closure has no missing obligation. Existing independent-E and routed-store negatives still pass.

Acts and return frames record their resume PCs. Parked-table entries and reified continuations use `state-node`, so they contribute the same contexts and recursively visit their windows and K. A tail state's own dead activation contributes no running context; its K still contributes contexts and carried values. Install children call `lift-task*` with their own machine and accumulator. Their environments/stores cannot answer a parent's or sibling's contexts.

I found no additional false acceptance or false refusal in these supported contexts. The explicit backward-jump unit probe exercises reachability; admitted expression-structured vectors currently forbid backward jumps, so it is not an end-to-end backward-jump transport proof. Branch reachability is conservative over both successor edges, not constant propagation.
