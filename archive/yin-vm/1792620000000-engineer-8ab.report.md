# Phase 8ab engineering report

Implementation complete; verification results are recorded below. No commit was made.

## Changes

Both backend descriptors drop `:dim/lift-to` and declare `:hash :blake3`.
All six surviving production hash sites use explicit `jing/blake3` on the
portable hosts. `lowering-contract-version` remains 2; register
`contract-version` remains 4. H and R are derived checksums; A is the sole
code identity. Descriptor comparisons against HEAD passed: exactly the
lift-row removal and encoding `:hash` change, with no other data change.

The H descriptor golden now lives in the surviving `debruijn-code-test`.
The register descriptor golden remains in `debruijn-register-code-test`;
its duplicated declaration/test was removed from the old compiler test.
The linker image helpers and stack-parity image producer use `derive`.
The stack parity test retains the old adapter only for the side-table
assertion, which tests old lowerer behavior until 8e.

`encode-scalar` needs no move: `yin.vm.debruijn-code` survives to compute H
and supplies the register encoder. Its public function, descriptor reference
`:yin.debruijn-code/encode-scalar`, and scalar tests remain valid. Neither
backend kernel was widened or removed.

## Deviations and design findings

- The plan says 11 pins in `derive_test`; the code has 10 H plus 10 R pins.
  All 20 were regenerated. `debruijn_code_test` has four additional H
  goldens omitted from the inventory; all four were regenerated. Stack
  parity has four distinct image/H rows and four wire-byte pins, rather
  than the plan's six hashes/two hex images. Every wire-byte pin stayed.
- The old register compiler test still exists until 8e. It has 11 image
  checksum pins, not 12. Removing only its duplicated descriptor golden
  while leaving stale checksum pins makes this slice fail. Those 11 pins
  were regenerated from their printed images, preserving all image and
  execution assertions until the planned deletion. No shim was added.
- Production's named-root pairing verifier still uses the old register
  allocator until 8c. Its authentic-pairing test explicitly produces the
  old allocation locally; general linker helpers use `derive` as requested.
  Switching production here would silently import an 8c semantic change.
- `py` and `pysp` manifest addresses already change in 8ab because their
  derivation outputs and checksum-keyed indexes embed H/R. Both were
  regenerated now, with printed complete manifest maps. Their contract/map
  shape and production pipeline remain current; 8c necessarily regenerates
  these manifests again when that pipeline and manifest shape change. The
  plan's claim that manifests move only once in the whole phase does not
  match this intermediate slice dependency.
- The registry/classification documents had stale claims that the register
  implementation was absent and that four SHA-256 sites were current.
  They now describe the six implemented BLAKE3 sites. Historical H0/H1
  no-change obligations remain historical; SHA-256 remains an explicit,
  permanent Jing registry member and the DHT routing contract stays SHA-256.
- The broad suite found `handoff-v2.txt` embeds an H checksum in its CBOR
  payload, despite the plan's claim that old transport fixtures contain no
  H/R. Its plain hex does not expose the ASCII digest to a raw hash grep.
  The fixture's image H and checkpoint address were regenerated using the
  printed image and decoded body. The decoded body differs only by replacing
  the embedded H throughout; its version, code rows, floats and cursor IDs remain identical; layout
  structure is unchanged and its H references regenerate with that checksum. The reproduction script also verifies exact
  fixture bytes. The fixture stays until its planned 8d deletion.
- A raw root preimage containing old child hashes cannot be regenerated by
  merely substituting the dimension hash. The essay root was recomputed
  from its printed AST with the public projection function instead.

No new architectural defect was found. The pairing/manifest sequencing
issues above are existing phase-plan boundaries and are kept explicit.
