### F1 (High): carrier refusals before attachment

`check-task!` is split into four steps. `lower-task` runs **each step over the whole task tree before the
next** (§3.3):

1. `check-stores!` (task context, beside X1): no key of the root store or any module store is a reserved
   name → `:yin.k/undecodable :reserved-name`, `:yin.k/role :store-key`. Before this fix, a module-store
   `yin/def` was not refused at all. Restore builds module stores with `into {}`, not `store-put`, so the
   lowered machine silently held `{host.mod {yin/def 42 …}}` (mutant A's log shows the machine).
2. `check-pendings!` (step 8): see F2.
3. `check-dependencies!` (step 9): requires/code agreement, trees, then **every carried vector must load
   in the receiver's kernel under its A** (`attaches?` = `module/attach-module` on the receiver,
   discarded; a vector whose address is not its key is refused too) → `:segment`. Then each closure row,
   via `check-closure!`, must name a `:closure` tuple of its vector with that entry (`:closure-origin`)
   and the tuple's binders (`:closure-binders`). These are the same conditions `lower-closure` enforces
   late. `:prim` names are checked after that, as before.
4. `check-custody!` (step 10).

Tests (`carrier-defects-refuse-before-attachment`, each asserting 0 attaches): root store `yin/def`
(codex's recipe), module store `yin/def` (row 18), closure entry `999999999` (codex's recipe),
closure binders changed.

### F2 (High): install records validated before attachment

`check-install!` runs in step 8 for every install record:
- phase ∈ `#{:running :parked}` → else `:install-phase`;
- retained response: a map, `:status :ok`, manifest naming this module, exports a collection of
  symbols, `:image` a map whose `:value` the receiver's kernel loads (the same validation `spawn-child`'s
  `load-vector` runs) → else `:install-response`;
- relation to the carried child: the child's kind must be `:blocked` → else `:install-child`. Reason: the
  engine routes a halted (or explicitly parked, hence halted) child to `link-install` in the sweep it
  halts in, and a running child is not at a safepoint, so a carried child is always blocked (see B1).

Tests (0 attaches each): response `{}` and phase `:bogus` (codex's recipes), image value `[]`, manifest
naming `other.mod`, child kind `:halted`.

### F3 (High): occurrence- and context-sensitive discharge

The lift's walk now records a **context** `{:a A :at pc :env E}` for every closure (its entry), every
`:act` (its pc) and every return frame (its pc). `:tail` states record none: they resume through K, and
their segment never runs again. After the walk, `discharge!` takes each context, finds the body holding
`:at` (`code/parse`, `code/body-index`), and checks every free occurrence (`scan/free-occurrences`) whose
body is that body or nested in it. Resolution follows resolve-var's order:
1. reserved;
2. **that context's own E**;
3. **the one store `engine/active-store` selects for it**: the root store when E has no store-of,
   otherwise that module store only, with no ambient fallback. Both travel: the root store whole, and
   the module store through `store-of!` → `module-store-nodes`;
4. a primitive (host-state refused here, i.e. only when resolution reaches the primitive step);
5. an installing module's export;
6. the module registry (deviation 4's composition prerequisite, unchanged).

Removed: the union of all module-store keys, the global "bound anywhere" set, and the global free-env
answer. A carried E already holds the free env it was created under (E2 relies on that).

Tests (`free-occurrences-are-answered-in-their-own-context`):
- `(fn [] ghost)` refuses `#{ghost}`;
- adding `:module-stores {unrelated {ghost 42}}` still refuses (codex's negative case);
- a closure routed to module store `scoped` that lacks `ghost` refuses even though the root store has
  it;
- the root store answers a top-level closure;
- reachable only through the store;
- another closure's E binding `ghost` answers nothing, while its own E does;
- reachable only through a module store that a routed closure reaches;
- reachable only through another closure's E.

Positive scoped case: a routed closure with `scoped {ghost 42}` beside `unrelated {other 1}` lifts with
0 serves. Only `scoped` travels. It lowers with 0 attaches, and calling the lowered closure on the
receiver answers 42.

## Uncertain / worth a reviewer's eye

- **Context precision.** An occurrence is checked in every context whose body encloses it, including
  occurrences earlier in the same body than an `:act`'s pc (they cannot run again). This is conservative
  and can over-refuse only in a body with both a branch-skipped occurrence and an earlier-pc read.
  Nothing in the corpus hits it.
- **Uncarried code.** Code a context cannot reach at all, such as a segment carried only by a `:tail`,
  creates no obligations. That is deliberate.
- **Names the code defines itself.** A name that the carried code itself `def`s later is still refused
  unless it is already in the store, as before.
- **`attaches?` cost.** It re-validates every carried vector once per lower, plus each install image.
  That is cheap at corpus size.
- **Install image vs child code.** I did not require that the install image's A be among the child's
  carried segments. A child blocked after tail calls need not reference it.
- **Registry prerequisite.** Free-name obligations answered by the source registry are still not
  re-checked against the receiver (deviation 4/5, accepted as composition prerequisites).
