# F1b receiver custody isolation

Implemented on `srvm-phase8-f1b`; the production fix and tests are UNCOMMITTED and unstaged for Architect review. No `test/yang/` file changed.

## Diff and contract

`rows.cljc` now dissociates `:yin.k/closes`, `:yin.k/issued`, `:yin.k/gate`, `:yin.k/custody`, `:yin.k/recovery-waits`, `:yin.k/recovery-parked`, and `:yin.k/recovery-cell-ids` from the restoration base and the spawned install child. `with-custody` then establishes the lower's own state. Forks contain none of these keys; exclusive roots number their retained puts and set their gate and accepted custody; fenced tasks establish their recovery data and exporting gate.

The existing populated-receiver regression now poisons all seven keys, asserts their absence on the root and resumed task/child, and compares the clean/populated select-keys exactly. The addressed `receiver.mod` registry entry is shared by both receivers and asserted resolvable after lowering; this preserves the existing whole-install-child equality without normalization. A sibling test lowers an exclusive blocked reader with the same public grant construction used in rows-custody-test: no closes, issued 0, running gate, exact accepted custody, no stale recovery data. It also compares fenced recovery state to a clean lower at both the install root and child, with waits/parked state out of the scheduler.

The registry remains composition-owned, including addressed entries, pending the owner/linker's ruling. Resources still merge and the original allocation/collision/resumption assertions remain. No row grammar, encoder, carrier fixture, or expected root id changes.
