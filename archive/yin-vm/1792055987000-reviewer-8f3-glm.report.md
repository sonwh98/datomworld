## Findings

**P3-1 — reset coverage weaker than claimed (semantic_register/vm_test.cljc:74-89).** The ledger maps semantic_test/reset-test to attach-load-ast-and-reset as "code preserved and program reruns". Code preservation, empty window and nil value are asserted; "program reruns" is not — nothing on the semantic-register kernel asserts `vm/reset` restores `control` to pc 0 or that a reset machine re-runs to its value (the `(vm/eval a nil)` assertion continues a mid-run machine; the pc-0 assertion exists only on the native de Bruijn register backend, debruijn/register_test.cljc:496-499). Two `is` lines in attach-load-ast-and-reset would close it. Not a behavior change — `reset` is implemented as pc-0 control restore (semantic_register.cljc:338-339).

**P3-2 — bare-row-set nil-origin slot unpinned (semantic_register/linearize_test.cljc:124-137).** The old lower-rows-provenance test asserted that a row set projected without an origin carries `nil` in the provenance origin slot; every current provenance assertion passes an explicit origin (or asserts only paths). One `(is (nil? (nth (first (:provenance (linearize/project-rows bc))) 1)))`-style line restores it.

**P3-3 — writer-entry EDN round-trip composite no longer spelled out.** blocked-put wakes the original in-memory `:put` entry; the EDN round-trip-then-wake is now pinned for reader entries (engine a-wait-set-read-back-from-edn-resumes, effects stream-outcomes-and-edn-wake) and FFI wait-sets, and the `:put` carrier path is pinned by ucf.remote put-round-trips, but no test round-trips a blocked writer's wait-set through EDN and then wakes it on the register kernel. The pure-data fact itself is still pinned structurally (exact entry equality in blocked-put).

**P3-4 — dead fixture (test/yin/vm/malformed_rows.cljc:54).** `malformed/malformed-vectors` lost its last consumers (semantic_test, code_test) and now has none; the v4 twin lives in semantic_register/code_test `refusals`. Harmless (unused public var, no kondo noise); drop it or leave it for 8f-2's file moves.

No P1/P2 findings: every deleted language/VM behavior fact I could identify has a same-strength successor on the new kernel, the RETIRED-OK set is v3-representation-only (and matches ruling R2/R5 exactly), the consumer ports are assertion-preserving, and the counts (81 out / 16 in, 15 carried + 1 new) are exactly as reported.
