## 3. Rulings

**(A) `float('-nan')` sign bit — ACCEPT as a recorded divergence; the orchestrator ruling that demanded `fff8` should be amended.** The demanded "pinned bit manipulation or a pinned host op" does not exist in the frozen surface: no `data`/`integer` export maps bits to a float or flips a sign bit (verified against both modules' exports), the design forbids new host functions, and the integer module is frozen at v4. Arithmetic cannot do it: an arithmetic NaN takes the CPU's default sign (fff8 on x86, 7ff8 on arm64 — measured in this worktree: codex's `-inf − -inf` gave 7ff8 on the JVM), and negating flips whatever default the host produced, so no composition is stable; a `##NaN` literal is barred by JS content addressing. Decisively, dao.jing writes **every** NaN as 7ff8, so even a correctly signed value cannot survive an image-VM round trip — the sign is unobservable in the C3 guest by construction, and the M4 gate's own Q2 concern (bits observability) is moot for this slice. The implemented outcome (one NaN via `inf − inf`, `:nan` in comparisons, is-NaN fast pin, doc paragraph) is the honest one. Revisit only when a bits→float or sign-flip `data` export is ruled in (post-C3 kernel seat) — not an S4 defect.

**(B) the 27 non-ASCII repr-escape rows — ACCEPT as a recorded divergence.** Independently counted: 25 int-conv + 2 float-text error-message rows quoting a non-ASCII non-printable (`\xa0`, `\u200b`, …). Matching CPython needs `Py_UNICODE_ISPRINTABLE` (category-based) in **both** the renderer and the prelude — a Unicode table the slice's ASCII policy (§4.5, the same policy behind the ASCII-digit divergence) deliberately does not carry; that is an Architect decision, rightly not smuggled into S4. The handling is honest: expectations are derived from `render/string-repr` per the design's own "same escapes, same quote choice" rule, labelled in the `departure` docstring and the doc; the rows still bind guest-repr ≡ renderer on non-ASCII and bind the message prefix and quote choice against CPython; the whitespace-only `''` cases are explicitly preserved. Recommend tracking it beside ruling 13's unclaimed `format`/`%`/`round(x, n)`.
